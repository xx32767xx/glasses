## 可能的报错与修法

> 下面几行「真实 DSL 校验」是在**检出里真实的 `defineTool`** 上实测出来的，不是猜的。
> 这类错误曾经真的会让加载在第一个工具就炸掉（`output.schema` 写成原始 JSON Schema），
> 现在由 `tests/run-all.mjs` 持续守着，所以理论上你不需要再遇到它们。

| 报错 | 原因 | 修法 |
|---|---|---|
| `schema.required is not supported by the value schema DSL` | `output.schema` 用了原始 JSON Schema 的 `required: [...]` 数组 | harness 的 DSL 里 `required` 只能是**每个属性上的** `required: true`；把 `required: ['ok']` 改成 `ok: { type: 'boolean', required: true }` |
| `schema.additionalProperties must be explicitly true or false` | object 节点没声明 `additionalProperties` | 每个 `type: 'object'` 节点都要显式写 `true` 或 `false` |
| `...required must be true when present` | 写了 `required: false` | 省略它，或写 `required: true`；**没有 false 这个选项** |
| `schema.items.required is not supported` | 在 `array` 的 `items` 上写了 `required` | `required` 属于「父对象的属性」，不属于 items |
| `parameters must be an object of value schemas` | `parameters` 整个被省略 | 至少写 `parameters: {}`（空对象是合法的，实测通过） |
| `service "tools" is not declared` | 动态包 scope 里没声明 `inject: ['tools']` | 产物里已经声明了；若仍报，说明该会话的 preset 不提供 tools 服务 |
| 插件 `PENDING` / 一直不起 | 硬依赖没就绪 | 产物声明的是 `inject: ['tools', 'timer']`。`timer` 由 `dsh-base` 挂着，正常都在；若确实没有，把产物里的 `inject` 改成只留 `'tools'`（收件箱会失去自动轮询，但其余工具可用） |
| `拿不到模型 id` | `llm.listModels()` 失败或返回空 | 把产物里 `CONFIG_OVERRIDE` 写成 `{ modelId: 'deepseek-chat' }`，重新生成并 define |
| `ctx 里没有 llm 服务` | 该 scope 拿不到 llm | 用 `cordis_inspect_query { "service": "llm" }` 核实；临时可用 `leion_display` 自己翻译后推送 |

> 改代码的方式：**不要在旧包上改**。改 `plugin/core.mjs` → 跑 `node scripts/generate.mjs` → 让 agent 用 `plugin.kind: 'existing'` + 原 `pluginId` 再 `cordis_define` 一次，得到新 `packageId` 后用 `cordis_run` mode: `update` 切换。这样失败的旧版本还在，可以回滚。

## 另一条路：正式插件包（持久、可交付）

正式插件包已经写好了，在 `plugin/`：导出 `apply(ctx, config)`，**零第三方依赖**（不 import 任何
node_modules），所以不受 profile 模块解析约束。三个关键事实：

1. **profile 的 `cordis.patch.yml` 是被 HMR 监视的**（`apps/cli` 的 `watchUserPatches`），改它会热挂载/热卸载插件行，**不用重启**。你的文件在 `C:\Users\anqi2\.dsh\profiles\web\cordis.patch.yml`（当前是 `[]`）。
2. 用 `--patch` overlay 时，插件的模块路径**必须是绝对路径**；patch 文件只贡献配置，不改变 loader 解析模块路径用的 profile 目录。已经给你准备好了 `plugin/cordis.local.patch.yml`。
3. 正式路径**不需要** `@deepseek-ai/dsh-tools`：`ToolRuntime.register()` 接受原始 `ToolDefinition`（只要求 `output.render` 是函数 + `output.schema` 是 harness 支持的 JSON Schema 子集，见 `packages/core/tools/src/index.ts` 的 `register()`）。schema 由 `plugin/schemas.generated.mjs` 提供，它是由 `plugin/core.mjs` 的同一份 DSL **编译生成**的，所以不会和动态版漂移。

三种落地方式：

| 方式 | 命令 | 是否需重启 | 适合 |
|---|---|---|---|
| `--patch` overlay | `pnpm dsh web --patch E:\GlassesHarness\plugin\cordis.local.patch.yml` | 需要 | 一次性验证 |
| 写进 profile patch 层 | 往 `%DSH_HOME%\profiles\web\cordis.patch.yml` 加一个 `insert` 行，`name` 写 `E:/GlassesHarness/plugin/index.mjs` | **不需要**（HMR 热挂载） | 日常开发 |
| 装成 profile bundle | `dsh plugin --profile web add E:\GlassesHarness\plugin`，然后 `dsh --profile web` | 需要 | 交付成品 |

配置从 `cordis.yml` 里那一行的 `config` 传（正式路径才有的能力，动态包没有）：

```yaml
- insert:
    - id: leion-pro
      name: 'E:/GlassesHarness/plugin/index.mjs'
      config:
        transport: 'file'          # 接真机桥
        sinkPath: 'E:/GlassesHarness/.tmp/subtitle-bus.json'
        cols: 40
        lines: 3
        modelId: 'deepseek-chat'   # 留空则自动选第一个 provider 并发现模型
```
