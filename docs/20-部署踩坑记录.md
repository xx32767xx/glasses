## 1. Node 12：一串 SyntaxError，看不出是谁的问题

```
const activeUser = JSON.parse(activeRaw).user ?? null
                                               ^ SyntaxError: Unexpected token '?'
```

**根因**：Ubuntu 22.04 的 `apt install nodejs` 装的是 **12.22**（24.04 是 18），
而 `??`（空值合并）要 Node 14+，本项目要 20+。

**为什么难查**：这个错在**解析阶段**发生 —— 文件里写任何"友好的版本提示"都没机会执行。

**修法**：

```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs && node -v          # 必须 v20+
```

**防线**：`scripts/preflight.cjs` 故意用 **CommonJS + 老语法**写（不用 `??`/`?.`/`import`），
所以它能跑起来告诉你"你的 Node 太旧"；`package.json` 加了 `engines`，`npm start` 会先跑它。
`tests/run-all.mjs` 有两条断言盯着"preflight 不许被现代化"。

## 2. 大脑要一份构建过的 deepseek-harness 检出

原来的报错是：

```
无法加载真实的 @deepseek-ai/dsh-tools 构建产物 …
Invalid module ".../D:%5CDeepSeekHarness%5Cdeepseek-harness/packages/..." must not include encoded "/" or "\" characters
```

两层原因叠在一起：

1. **这台机器上根本没有检出**。`start-all` 的第三个进程（大脑）必须跑在真实的 DSH 工具运行时上
   —— 这是刻意拒绝降级的设计（仿一个校验器会给假的"契约没问题"的安全感）。
2. **我们的候选路径里写死了开发机的 `D:\...`**，于是"没检出"被渲染成"模块说明符含编码字符"。

**修法**：

```bash
git clone <deepseek-harness 仓库> ~/deepseek-harness
cd ~/deepseek-harness && pnpm install && pnpm build
export DSH_CHECKOUT="$HOME/deepseek-harness"     # systemd 里也要写
```

**防线**：候选路径按平台给（`D:\` 只在 Windows 上才是候选）；一个都没命中时**直接**
抛"没有检出"并给出三条可执行的路；`preflight.cjs` 第 ⑥ 项专门查这一条。

## 3. 数据目录写在 `/var/lib` 下：EACCES

```
EACCES: permission denied, mkdir '/var/lib/leion'
```

**根因**：`/var/lib` 属于 root。而文档示例里只写了 `--data-dir /var/lib/leion/live`，
没写"先建目录并改属主"——**是我给的示例漏了一步**。

**修法**：`sudo mkdir -p /var/lib/leion && sudo chown "$USER": /var/lib/leion`

**防线**：`start-all` 在起任何进程**之前**先试写一次，失败就直接打印上面这条命令并返回 1
（而不是"起两个进程、第三个退出、然后全停"）；`preflight.cjs` ③ 也查。

## 4. 模型下不动：SSL + Xet

```
'[SSL: UNEXPECTED_EOF_WHILE_READING] EOF occurred in violation of protocol'
Retrying in 1s [Retry 1/5] ...  https://huggingface.co/api/models/.../xet-read-token/...
```

**根因**：国内直连 huggingface.co 不稳；而新版 `huggingface_hub`（本机 1.33）默认用 **Xet**
传大文件，**镜像站不转 Xet 接口** —— 所以只设 `HF_ENDPOINT` 仍会报同一个 SSL 错。

**修法**（两个开关缺一不可）：

```bash
export HF_ENDPOINT=https://hf-mirror.com
export HF_HUB_DISABLE_XET=1
python3 scripts/fetch-model.py large-v3 --mirror      # 断了重跑即续传
```

**防线**：`fetch-model.py` 默认就关 Xet、支持镜像与续传，`--list` 打印真实占用
（large-v3 = 2.9 GB）；`check-asr-env.py` 会把这条 SSL 报错翻译成上述两条处置。

## 5. cu12 运行库：ctranslate2 要的是 CUDA 12

```
libcublas.so.12: cannot open shared object file
Could not locate cudnn_ops64_9
```

**根因**：`ctranslate2` 按 CUDA 12 构建。机器上是 CUDA 13 时，`libcublas.so.12` 根本不存在；
P40 那台更典型 —— 装了驱动但**没有** cu12 运行库。

**修法**：`pip install nvidia-cublas-cu12 "nvidia-cudnn-cu12==9.*"`，
再把 `site-packages/nvidia/*/lib` 加进 `LD_LIBRARY_PATH`（**cuBLAS 与 cuDNN 在不同目录，
只给一个会报 cuDNN 缺库**）。

**防线**：`check-asr-env.py` ② 一次给全两个目录；`make-env-file.py` 直接生成 systemd 的
`EnvironmentFile`（PATH + LD_LIBRARY_PATH），不让手抄。

## 6. Tesla P40（Pascal）：默认的 `float16` 用不了

**根因**：P40 是算力 6.1，**有 FP16 存储、没有 FP16 矩阵乘**。`ctranslate2` 按卡查表，
Pascal 上**根本不提供** `float16` / `int8_float16`。而我们的 GPU 缺省值正是 `float16`。

实测这台卡能跑的：`float32, int8, int8_float32`（**没有** `int16`）。
正确档位是 `int8_float32` / `int8`。

**防线**：`whisper_stream.resolve_compute_type()` 启动时查到不支持就自动换档并打一行 ⚠️；
`check-asr-env.py` ③ 直接把"这张卡能跑哪些精度 + 推荐档位"打出来；
`start-all --compute` 白名单加了 `int8_float32`。

## 7. 顺带纠正一个测量错误：那 27% 是假的

第一轮自检（没预热）：`int8_float32` RTF 0.28、`int8` RTF 0.22 → 看着"int8 快 27%"。
加上"每档先预热"再测：

| 档位 | 解码 | RTF |
|---|---|---|
| `int8_float32` | 668 ms | **0.22** |
| `int8` | 680 ms | **0.23** |

差 1.8%，在噪声内。**第一档要替后面所有档付 CUDA 上下文与 cuDNN 选算法的固定开销**
（约 0.2~0.4 s），而生产链路本来就有预热（`whisper_stream` 启动先用 1 秒静音跑一遍），
只有自检没做 —— 是我两边测法不一致。

**防线**：`check-asr-env.py` ④ 每档先预热再计时，并在输出里说明原因。

**教训**：一个排名 / 一个百分比，只要可能受**执行顺序**影响，就必须先排除顺序再下结论。

## 8. "在服务器上能连上自己" ≠ "手机能连上"

在服务器上 `check-relay --base http://10.60.234.77:8788` 全绿 —— 但 `10.x` 是**云主机内网地址**，
同机/同 VPC 内当然通，手机不在这个 VPC 里就完全够不着（公网也不会路由 `10.x`）。

**防线**：文档 §4.1 写清"换一台不在 VPN 里的机器测"，并把三条路（同一局域网 / 公网 IP+TLS /
SSH 隧道）列出来。

## 9. 有公网 IP，从外面连还是超时 → 入站端口没放行

症状组合：服务器上 `--say` 全绿，笔记本上 `timed out`。
**TCP 超时 = 包没送到进程**（"连接被拒"才是服务没起），所以基本只有一个原因。

**修法**：云控制台安全组放行 `TCP 8788`（+ `sudo ufw allow 8788/tcp`）。

**防线**：文档 §4.2 给了三步自证（`ss -ltnp` 看是否 `0.0.0.0` / ufw / 公网 IP 是否在网卡上）、
各厂商菜单位置、以及放行后仍不通的四个后续怀疑（EIP 未绑/NAT 映射、子网 ACL、出站被限、运营商封端口）。

**顺带一个有用的结论**：非标端口（8788）不受 80/443 的备案约束，验证阶段能马上开工；
但**明文上公网 = 密钥与会议音频裸奔**，正式用之前必须 TLS。

## 10. 我给的验收命令用 `curl -s`，失败时一片空白

`curl -s` 静默错误，于是"连不上 / 401 / 大脑没工作"三种完全不同的原因，在屏幕上**长得一样**。

**防线**：`check-relay.py --say "这是一条测试信息"` —— 写入收件箱 → 长轮询 `/frame` 等译文 →
打印"原文 / 译文（增量或定稿）"，失败时列出四条排查（进程 / brain.log / 翻译凭据 / 先用 `--offline`）。

期间还修了一个自己挖的坑：`/frame` 是**长轮询**（服务端挂最多 25 秒），
单次请求超时是"还没有译文"的正常表现，不能当错误。

## 11. 流程上我自己的两次疏漏（记下来，别重演）

1. **只 commit 没 push**：于是让你在服务器上 `git pull` 拉不到东西。
   → 以后凡是让你"在服务器上拉代码"，必须先确认 `git push` 成功并且远端分支一致。
2. **误把 POSIX 命令贴在 Windows 上**（你做的）：`source`/`export` 在 PowerShell 里不是命令，
   于是整段基本没生效（已核查：没有下载、没有残留、没有多余文件）。
   → 给命令时标明"在哪台机器、用什么 shell 跑"，别混在一起给。

## 12. 整文件被写成 GBK 乱码：javac 报一串「未结束的字符串文字」

```
LanClient.java:43: 错误: 未结束的字符串文字
    super(message == null || message.isEmpty() ? "鐧诲綍宸插け鏁堬紝璇烽噸鏂扮櫥褰? : message);   <!-- mojibake-ok -->
                                                 ^
… 9 个错误，全在同一个文件里
```

**真因**：不是编译环境的编码设置，是**文件内容本身坏了**。
4.31 那次提交把 `LanClient.java` 整个重写了一遍，写进去的是
**"原文 UTF-8 字节按 GBK 解码"** 的结果：

| 原文 | 写进去的 |
|---|---|
| `登录已失效，请重新登录` | `鐧诲綍宸插け鏁堬紝璇烽噸鏂扮櫥褰?` <!-- mojibake-ok --> |
| `连接失败：` | `杩炴帴澶辫触锛?` <!-- mojibake-ok --> |

顺带两个签名，一眼能认：① 文件**全变 CRLF**（仓库里 *.java 是 LF）；
② `git diff` 里每处都是成对的 `-正确中文 / +乱码` —— 那不是改写，是同一个句子的两副面孔。

**为什么难查**：报错长得很像"编码设错了"，于是第一反应是去改 `-encoding`、
去查 Gradle daemon 的 `file.encoding`（实测那边本来就是 UTF-8，没问题）。
真正的线索是**乱码字符本身**：`鐧诲綍` 是 UTF-8 字节被 GBK 读的产物，
而且每段中文**最后一个字的字节会把紧跟的引号一起吞掉**，于是字符串没闭合。

**修法（别硬修）**：这种损坏**不可机械还原** —— 每段中文结尾都丢了 1 个字节，
"UTF-8 字节按 GBK 还原" 只能救回 95%，剩下 140 多处的边界要么猜、要么错。
正确做法是**以最近一次干净提交为基重建，再重放那次提交的真实语义改动**：

```bash
git show <干净提交>:android/app/src/main/java/com/leion/lanrelay/LanClient.java > /tmp/base.java
# 4.31 那份的真实改动只有三处：SessionExpiredException、throwIfSessionExpired、
# requestWithCode 里那三行 401 注释 —— 其余全是编码churn
```

**防线**：`tests/android-order-suite.mjs` 里加了「源码完整性」三条判据
（含反向自检）：

1. **不许有乱码字**：`锛 鐨 鏄 鍦 浜 鎴 缁 杩 璇 瑁 璁 闇` 这类只在误读里出现的字；<!-- mojibake-ok -->
2. **必须是合法 UTF-8**：出现 `�` 即判坏（说明文件被按 GBK 存过）；
3. **引号必须成对**：`stripComments` 去掉注释与字面量内容后，同一行里 `"` 的个数必须是偶数
   （Java 字符串不能跨行）—— 这条正是"被吃掉的引号"。

反向自检用的是**真实的 GBK 误读**（`new TextDecoder('gbk').decode(Buffer.from(正确中文,'utf8'))`），
不是手写的假样本：判据自己也得被钉住，否则它可能永远为真而我们以为它在守着。
扫描范围：`android/**/*.java`、两个 `build.gradle.kts`、`docs/*.md`
（文档也是给下一个接手的人读的，坏了同样有毒）。

**教训**：报错里的**乱码字符**是证据，不是噪声。看到 `鐧诲綍` 就该想到
"字节被换过"，而不是去查编译器参数。

## 13. 换服务器 / 整机搬迁：库坏了 + 模型没跟过来（2026-10-29）

用户把镜像完整搬到新服务器后，同时撞了两件事：

```
[识别] httpcore2.RemoteProtocolError: Server disconnected without sending a response.
[识别]   File ".../faster_whisper/transcribe.py", line 681, in __init__
[识别]     model_path = download_model(...)
```

```
管理端登录：database disk image is malformed
```

**① 识别进程崩：模型没搬过来，于是它想联网下载**

`faster-whisper` 拿到的是**仓库名**（`large-v3`）。本地缓存里没有它时，它会去
huggingface.co 下载 —— 而国内机房出网通常不通，于是卡几分钟然后抛
`RemoteProtocolError`。注意它**不会**说"模型不存在"，只说"服务器没响应"，
看起来像网络问题，实际是**搬迁时漏了 `/opt/leion/models`**。

```bash
# 症状确认：看这两行的缓存目录是哪个、里面有没有那个模型
python bridge/whisper_stream.py --self-check --model large-v3 2>&1 | head -3
ls "$HF_HOME/hub" 2>/dev/null || ls ~/.cache/huggingface/hub
```

修法（任选）：

```bash
# 1) 从旧机器把模型目录整个搬过来（推荐）
rsync -av 旧机器:/opt/leion/models/ /opt/leion/models/
export HF_HOME=/opt/leion/models          # 启动脚本里必须有这一句
# 2) 走镜像站
export HF_ENDPOINT=https://hf-mirror.com
# 3) 直接指向本地目录
python bridge/whisper_stream.py --model /opt/leion/models/faster-whisper-large-v3
```

> 现在代码会在**加载之前**先查本地缓存：没有就直接退（退出码 2）并打印上面三种修法，
> 不再甩一屏 traceback。要看完整 traceback：`LEION_DEBUG=1`。

**② 数据库坏：搬迁时 SQLite 最容易被拷坏**

`database disk image is malformed` 有四种典型来源：

| 来源 | 现象 | 处理 |
|---|---|---|
| 拷贝时 relay 还在写 | 拷到半页数据 → 真损坏 | 只能重建/重拷 |
| 只拷 `leion.db`、没拷 `leion.db-wal` | 最近提交丢（不报损坏） | 重拷，或接受丢数据 |
| `-wal` / `-shm` 与主库不是同一次拷的 | SQLite 判两半对不上 → 报损坏 | 挪开 WAL 即可 |
| 用 tar/文本模式/某些同步盘搬运 | 内容被改写 | 重拷（`rsync -a`） |

**正确的搬迁顺序**（照做就不会有这个问题）：

```bash
# 旧机器：先停，再导出（.backup 拿到的一致快照，不是"拷文件"）
systemctl stop leion            # 或 pm2 stop all
sqlite3 /var/lib/leion/live/leion.db ".backup /tmp/live.db"
sqlite3 /var/lib/leion/test/leion.db ".backup /tmp/test.db"

# 搬运
rsync -av /tmp/live.db /tmp/test.db 新机器:/var/lib/leion/
rsync -av /opt/leion/models/ 新机器:/opt/leion/models/

# 新机器：先体检，再起
node scripts/doctor-db.mjs      # 结论必须是"健康"
```

**体检与抢救**：`node scripts/doctor-db.mjs [--fix] [--scan <根目录>]`

- 逐个报 `leion.db` / `-wal` / `-shm` 的大小与时间（谁比谁新一眼看出来）；
- `quick_check` + `integrity_check`；
- 关键一步：**把 WAL 挪开再查一次** —— 用它区分"真坏了"和"只是带了份过期 WAL"；
- `--fix` 先备份再 `VACUUM INTO` 重建；真救不回来就给出 `sqlite3 .recover` 的做法。

现在 `openDb()` 撞到损坏时抛出的错误也会写清：哪个库、常见原因、下一步跑什么
（以前只有一句 `malformed`，管理员登录页上就看到这一句，完全没法排查）。

**4.66 补上的三件事**（真实跑一遍才发现不够用）：

1. **文件头与页尺寸诊断**：`database disk image is malformed` 其实分两种病 ——
   头都不对（根本不是 SQLite 文件，搬迁时被改写过）vs 头对、某几页坏了（数据大多还在）。
   现在会把「页尺寸×页数」打出来，一眼看出是哪种。
2. **逐表抢救**（`salvageToNewDb`）：`VACUUM INTO` 也走不通时，按表 `SELECT *`
   能读一条算一条，写进一个**结构全新**的库；哪张表读不动就报哪张
   （“至少知道丢了什么”）。等价于 sqlite3 的 `.recover`，但不需要服务器装了 CLI。
3. **`--scan <根目录>`**：找所有 `leion.db`。新机器上「数据目录是空的」十有八九是
   `--data-dir` 写的跟你以为的不一样，或根本没跑过。

**4.67：测试环境可以直接重建**（用户定的）。库已经坏到没法抢，而这台只跑测试数据 ——
那就别在废库上浪时间：

```bash
# 1) 旧库改名留档（不删），建一个全新的空库（表结构自动就绪）
node scripts/doctor-db.mjs --data-dir /var/lib/leion/test --reset

# 2) 立刻建一个能登录的管理员（新库是空的，没有账号就进不去）
node scripts/create-account.mjs --data-dir /var/lib/leion/test \
     --user boss --password '你的密码' --role admin

# 3) 起 relay，手机用这个用户名+密码登录（登录页切「用密码登录」）
```

（`create-account.mjs` 也支持 `--role dev --days 7` 建测试账号、`--list` 看当前账号；
密码不回显、也不明文落盘。）

新库里术语库也是空的，需要重新导入：`node scripts/terms-migrate.mjs`。

> 真实案例：一台新机器上 `/var/lib/leion/live` 是空的（relay 带的 `--data-dir` 不在这），
> 而 `/var/lib/leion/test/leion.db` 头正常但页坏了 —— 这两件事看起来都像“数据库坏了”，
> 实际一个是路径错、一个是真拷坏了。
