# 34 · 会议接入与字幕推送（桌面端对接）

> 给**另一个小组的 Windows 桌面端**用：怎么进一个会、怎么收到实时字幕、字段是什么意思、
> 出错时怎么查。所有示例都是从真服务器上抓下来的，不是手写的示意。
>
> 配套的可运行样例：`scripts/watch-room.mjs`（零依赖，Node ≥ 22，Windows 直接跑）。
> 本文档与实现不一致时，**以代码为准**，但请把差异告诉我们（`tests/desktop-api-suite.mjs`
> 会在文档与代码对不上时报红）。

## 1. 连接与鉴权

### 1.1 地址

| 环境 | Base URL | 数据 | 谁在用 |
|---|---|---|---|
| 测试 | `http://<测试服务器>:8789` | `/var/lib/leion/test` | **桌面端就用这个** |
| 生产 | `http://<正式服务器>:8788` | `/var/lib/leion/live` | 只给手机正式用 |

`<测试服务器>` 与 `<RELAY_SECRET>` 由我们单独发给你（密钥不进仓库、不进群）。

### 1.2 两个请求头

```
X-Leion-Secret: <RELAY_SECRET>       # 每个请求都要带，少了一律 401
X-Leion-Token:  <登录拿到的 token>    # /org/* 接口要带，服务端据此知道"我是谁"
Content-Type:   application/json     # 有请求体时
```

⚠️ **不要用 `user=<名字>` 自报身份**：那是 5.21 之前的老做法，账号库存在时会被 401 拒掉
（服务端不再相信客户端自称的名字）。

### 1.3 登录

`POST /auth/login`

```json
{ "username": "test7", "password": "123456", "label": "desktop" }
```

```json
{ "ok": true, "user": "test7", "role": "dev", "token": "1f3c…（64 位十六进制）" }
```

- 测试账号：`test1` … `test45`，密码都是 `123456`（角色 `dev`，带有效期）。
- `label` 只是给"同一账号在多处登录"时看的备注，可省略。
- **同一账号重复登录会吊销旧 token**：桌面端正则调试时别和手机用同一个账号，否则互相顶下线。

### 1.4 先问版本与能力

`GET /version`

```json
{
  "ok": true,
  "appVersion": { "name": "4.274", "code": 303, "required": true },
  "serverFeatures": ["hello", "say", "audio", "frame", "status", "diag", "lint", "terms",
                     "settings", "auth", "org", "floor-ws", "frame-ws", "room-closed-push",
                     "session-push", "asr-http", "translate-http"]
}
```

**请按 `serverFeatures` 判断能力，不要按版本号猜**：`frame-ws` 在就有 WS 字幕推送，
没有就只能长轮询；`room-closed-push` 在就会收到"会议已结束"的推送。

## 2. 会议接入

### 2.1 建房（拿邀请码）

`POST /org/rooms`（需要 token）

```json
{ "name": "桌面端联调", "lang": "zh-CN", "hearLangs": ["zh-CN", "en-US"], "mode": "remote" }
```

```json
{
  "ok": true,
  "room": {
    "id": "room-mwa5gv37-7s8i",
    "code": "757447",
    "name": "桌面端联调",
    "host": "test7",
    "targetLang": "",
    "kind": "meeting",
    "createdAt": "2026-11-10T03:48:11.004Z"
  }
}
```

| 字段 | 说明 |
|---|---|
| `code` | **6 位数字邀请码**，给人念/给人输的就是它 |
| `id` | 内部房间 id；订阅推送、查详情、退会都能用它（也能用 `code`） |
| `host` | 发起者。**发起者退会 = 整场结束**（其他人会被踢出） |
| `lang` | 我说什么语言（识别方向）。省略则按 `speakLang`/默认 |
| `hearLangs` | 我想看哪些语言的译文（数组）。省略 = 只看自己那门 |
| `mode` | `face`（面对面）/ `remote`（远程）。只接受这两个值，别的当没说 |
| `targetLang` | 三语场景下显式指定"译成哪种"；两语场景可省略 |

### 2.2 进会

`POST /org/rooms/join`（需要 token）

```json
{ "code": "757447", "lang": "en-US", "hearLangs": ["en-US", "zh-CN"], "mode": "remote" }
```

```json
{
  "ok": true,
  "room": { "id": "room-mwa5gv37-7s8i", "code": "757447", "name": "桌面端联调",
            "host": "test7", "closed": false, "targetLang": "", "kind": "meeting" },
  "members": [
    { "username": "test7", "lang": "zh-CN", "mode": "remote",
      "hearLangs": ["zh-CN", "en-US"], "joinedAt": "2026-11-10T03:48:11.004Z" },
    { "username": "test8", "lang": "en-US", "mode": "remote",
      "hearLangs": ["en-US", "zh-CN"], "joinedAt": "2026-11-10T03:48:31.221Z" }
  ]
}
```

失败时 `HTTP 400` + `{ "ok": false, "error": "邀请码无效，或这场会已经结束" }`。

**⚠️ 必须先进会再订阅推送**：WS 的连接身份与"这个房间的成员语言"绑在一起，
没进会的人连上 WS 收不到按语言分发出去的译文（服务端不知道他读哪门语言）。

### 2.3 查房间详情

`GET /org/rooms/<房间id 或 邀请码>`

```json
{
  "ok": true,
  "room": { "id": "room-…", "code": "757447", "name": "桌面端联调", "host": "test7",
            "closed": false, "targetLang": "", "kind": "meeting" },
  "members": [ { "username": "test7", "lang": "zh-CN", "mode": "remote",
                 "hearLangs": ["zh-CN"], "joinedAt": "…" } ],
  "libraryIds": [],
  "pipeline": { "state": "running", "…": "…" },
  "strategy": { "…": "这一场冻结的识别策略（开发模式才有用，桌面端可以忽略）" }
}
```

`room.closed === true` 就说明发起者已经散会 —— 桌面端该退出会议界面，
而不是继续等字幕（也不会有字幕了）。

### 2.4 退会

`POST /org/rooms/leave`（需要 token）

```json
{ "roomId": "room-mwa5gv37-7s8i" }
```

```json
{ "ok": true, "closed": false, "roomId": "room-mwa5gv37-7s8i",
  "members": [ { "username": "test8", "lang": "en-US", "mode": "remote",
                 "hearLangs": ["en-US"], "joinedAt": "2026-11-10T03:48:31.221Z" } ] }
```

- `closed: true` = **我是发起者，这一场结束了**，服务端会把屋里所有人断开（他们收到
  `{type:'closed'}` 与关闭帧）。
- 别人退会只是离开，`closed: false`。

### 2.5 发言权（只有你要说话时才需要）

`GET /org/rooms/<id>/floor`

```json
{ "ok": true, "holder": "test7", "locked": false, "since": "2026-11-10T03:49:02.113Z",
  "leaseMs": 15000, "lockedLeaseMs": 60000, "released": null, "releasedLocked": null }
```

`POST /org/rooms/<id>/floor`，`body.action` 五选一：

| action | 作用 | 失败 |
|---|---|---|
| `take` | 抢麦（别人持麦时 409，除非已过期/对方锁定中且你有权限） | 409 `{ok:false,error:…}` |
| `release` | 放麦 | 409 |
| `heartbeat` | 续租（持麦期间每 ≤5 秒一次；15 秒不续 = 自动释放） | 409 |
| `lock` / `unlock` | 锁定/解锁（发起者或持麦者可锁） | 409 |
| `force-release` | 发起者强行收回别人的麦 | 409 |

发言权变了会通过 WS 推 `{type:'floor', …}` 给**全屋**，不必轮询（轮询留兜底）。

## 3. 字幕推送（首选：WebSocket）

### 3.1 连接

```
ws(s)://<base>/ws?room=<房间id 或 邀请码>&secret=<RELAY_SECRET>&token=<TOKEN>
```

- 也可以把 `secret` / `token` 放进请求头（`X-Leion-Secret` / `X-Leion-Token`），
  服务端**头优先、其次查询参数**。浏览器/Node 自带 WebSocket 加不了自定义头 → 用查询参数。
- 握手失败的 HTTP 码就是判据：

| 码 | 原因 | 怎么办 |
|---|---|---|
| 401 | secret 不对，或 token 无效/已吊销 | 重新登录换 token |
| 404 | `room` 参数对应的房间不存在 | 检查邀请码；打完字别忘了先 `join` |
| 503 | 连接数已满（全局上限） | 退掉多余连接再试 |

### 3.2 连上先收到什么

1. 一条 **floor 快照**（不用你再问一次）：

```json
{ "type": "floor", "roomId": "room-mwa5gv37-7s8i", "holder": null, "locked": false,
  "since": null, "leaseMs": 15000, "at": "2026-11-10T03:48:11.538Z",
  "released": null, "releasedLocked": false }
```

2. 之后是推送。**字幕不是裸帧，是包了一层的**（见 3.3）。

### 3.3 消息类型总表

| `type` | 何时来 | 关键字段 |
|---|---|---|
| `frame` | **有字幕了**（这句最常用） | `seq`（全局）、`roomSeq`（本房间）、`lang`（扇出语言）、`frame`（见 §4） |
| `floor` | 发言权变化 / 有人掉线释放 / 锁麦 | `holder`、`locked`、`released`、`releasedLocked` |
| `listening` | 你发了 `{type:'listen'}` 之后 | `on` |
| `pong` | 你发了 `{type:'ping'}` | `at` |
| `closed` | **会议结束了**（发起者退出 / 管理员结束） | `roomId`、`reason`（`host-left` / `closed`） |
| `removed` | 你被发起者/管理员移出 | `roomId`、`reason` |
| `kicked` | 同一账号在别处登录，这条连接被顶掉 | `reason`（`replaced`） |

收到 `closed` / `removed` / `kicked` 之后服务端会**主动发关闭帧**（1000/4001 等），
把连接关掉 —— 桌面端据此退出会议界面，不必重连。

### 3.4 客户端可以发的三种消息

```json
{ "type": "ping" }
```

```json
{ "type": "snapshot" }
```

```json
{ "type": "listen", "on": true }
```

- `ping`：保活。长连接**没有**服务端主动心跳，建议每 25 秒发一次；服务端回 `{"type":"pong"}`。
- `snapshot`：我现在就要一份 floor 快照（房间连接才有效）。
- `listen`：要不要收这个房间的实时原声（音频走 WS 二进制帧）。服务端回 `{"type":"listening","on":true}`。

### 3.5 重连

服务端没有"补发历史帧"：断了就先 `GET /frame?room=…&since=<最后收到的 roomSeq>` 补齐，
再重连 WS。别指望重连时它把断线期间的字幕一次性给你。

## 4. 字幕帧字段（`message.frame`）

```json
{
  "device": "Leion Pro",
  "speaker": "them",
  "speakerName": "Ana",
  "lang": "zh-CN",
  "text": "早上好，会议改到下午三点。",
  "source": "Bom dia, a reunião mudou para as três da tarde.",
  "sourceLang": "pt-BR",
  "partial": false,
  "lines": ["早上好，会议改到下午三点。"],
  "cols": 40,
  "lineBudget": 3
}
```

| 字段 | 类型 | 含义 / 用法 |
|---|---|---|
| `device` | string | 显示设备型号（眼镜）。桌面端可忽略 |
| `speaker` | string | **角色**：`them` = 对方，`me` = 我。**不是人名** |
| `speakerName` | string? | 真名。**由服务端补**（"最近上传这段音频的人"→"当前持麦者"），认不出来时**这个字段直接不存在**（不是 `null`，别拿 `null` 当人名） |
| `lang` | string | 这一帧是**译成哪种语言**的那一份；原文帧里它等于 `sourceLang` |
| `text` | string | 译文。**原文帧为空串** |
| `source` | string | 原文（识别结果） |
| `sourceLang` | string | 原文语言 |
| `partial` | bool | `true` = 流式增量（**原位替换**同一句，不要新建一行）；`false` = 定稿 |
| `lines` | string[] | 按显示宽度（`cols` 列 × `lineBudget` 行）折好行的译文，可直接画 |
| `cols` | number | 折行用的列数（眼镜 40 列） |
| `lineBudget` | number | 折行用的行数（眼镜 3 行） |
| `echo` | bool? | `true` = 原文帧（给说话人自己看的回显） |
| `notice` | string? | 机器码提示：`same-language`（本场语言相同，无需翻译）、`translation-interrupted`（这一句翻译中断）。**按界面语言映射成人话再显示** |
| `translations` | object? | `{"zh-CN": "…", "en-US": "…"}`：一帧带多种译文（5.121） |
| `termsMiss` | string[]? | 本句提到场术语库里某个说法但译文没写规范写法（提示用，可忽略） |

### 4.1 四种典型帧

**① 定稿译文**（最常见）

```json
{ "speaker": "them", "speakerName": "Ana", "lang": "zh-CN",
  "text": "早上好，会议改到下午三点。", "source": "Bom dia, a reunião mudou para as três da tarde.",
  "sourceLang": "pt-BR", "partial": false, "lines": ["早上好，会议改到下午三点。"],
  "cols": 40, "lineBudget": 3 }
```

**② 增量（同一句还在成形）** —— 用 `partial:true` 原位替换上一帧，别追加新行

```json
{ "speaker": "them", "lang": "zh-CN", "text": "下一句还在翻",
  "source": "Próxima frase", "sourceLang": "pt-BR", "partial": true,
  "lines": ["下一句还在翻"], "cols": 40, "lineBudget": 3 }
```

**③ 原文帧（echo）** —— `text` 为空、`echo:true`，是给**说话人自己**的回显

```json
{ "speaker": "me", "speakerName": "test7", "lang": "zh-CN", "text": "",
  "source": "会议改到下午三点了。", "sourceLang": "zh-CN", "echo": true,
  "partial": false, "lines": [""], "cols": 40, "lineBudget": 3 }
```

**④ 提示帧** —— 这一句没有译文，但要说清为什么

```json
{ "speaker": "them", "lang": "zh-CN", "text": "", "source": "Tudo bem.",
  "sourceLang": "pt-BR", "partial": false, "lines": [""], "cols": 40, "lineBudget": 3,
  "notice": "same-language" }
```

**⑤ 一帧多种译文**（三语会议）

```json
{ "speaker": "them", "lang": "zh-CN", "text": "早上好，会议改到下午三点。",
  "source": "Bom dia, a reunião mudou para as três da tarde.", "sourceLang": "pt-BR",
  "partial": false, "lines": ["早上好，会议改到下午三点。"], "cols": 40, "lineBudget": 3,
  "translations": { "zh-CN": "早上好，会议改到下午三点。",
                    "en-US": "Good morning, the meeting moved to 3pm." } }
```

## 5. 字幕推送（兜底：长轮询）

没有 WS 能力、或者 WS 老断的时候用它。请求会**挂住最多 30 秒**，有新帧立刻回。

`GET /frame?room=<房间id>&since=<上次收到的 roomSeq>&langs=zh-CN,en-US`

```json
{
  "ok": true,
  "changed": true,
  "seq": 7,
  "frame": { "speaker": "them", "lang": "zh-CN", "text": "…", "partial": false, "…": "…" },
  "frames": [
    { "lang": "zh-CN", "seq": 7, "frame": { "…": "…" } },
    { "lang": "en-US", "seq": 6, "frame": { "…": "…" } }
  ]
}
```

规则（都是踩过坑之后定的，客户端必须按这个来）：

1. **超时**返回 `{ok:true, changed:false, frame:null, frames:[]}` —— 服务端**不会**把上一帧再发一遍。
   客户端照旧用 `since` 再发一次请求即可。
2. **`reset:true`**：你的 `since` 比服务端序号还大（转发进程重启过）。
   服务端会附带当前帧，你**把 `since` 重置为返回的 `seq`**，否则会永远等不到"更大的序号"。
3. `langs` 给了就按语言各回一份（`frames` 数组），**每门语言只回它自己没给过的那部分**；
   不给就只有单帧（`frame`）。
4. 序号用**房间维度**的 `roomSeq`，不是全局 `seq` —— 多场会并发时全局序号会跳。

## 6. 我会收到哪一帧？（分发规则）

服务端在推之前就筛过一遍，桌面端**不需要**再自己判断"这帧是不是给我的"，但要知道规则，
否则会以为"丢帧了"：

1. **按语言扇出**：一帧的 `lang` 是"译成哪种语言"。只有**进会时登记了想读这门语言**
   （`hearLangs` 含它）的连接才会收到。
2. **说话人自己不看自己那句话的译文**：只收到原文帧（`echo:true`）。那份译文是给别人的。
3. **提示帧（`notice`）发全屋**：它讲的是"这句为什么没译文"，必须让所有人都看到。
4. 三语会议里同一句会产出多份帧（每种目标语言一份）—— 桌面端按 `lang` 分开展示即可。

## 7. 让引擎说一句（联调时不用真说话）

`POST /say`（需要 token）

```json
{ "text": "Bom dia a todos, a reunião começa às três.", "from": "pt-BR" }
```

它把这段文字**喂进识别/翻译链路**（等于"假装有人说了这句"），几秒后就会有一帧字幕推过来。
`from` 省略时按发言者入会登记的语言推断。

⚠️ 这条是**联调用**：它绕过麦克风与识别，但**不绕过翻译**（省钱、也便于验证整条链路）。

## 8. 说话（可选，只有桌面端要出声时才有用）

`POST /audio`：裸 PCM 直接发，`Content-Type: application/octet-stream`

```
POST /audio?room=<房间id>&lang=zh-CN&rate=16000
X-Leion-Secret: …
X-Leion-Token: …
（body：16 kHz / 单声道 / 16-bit 小端 PCM 裸字节，单块上限 8 MB）
```

约束：`rate` 只能是 `16000` / `8000`（`X-Sample-Rate` 头也行）；`lang` 只能是三门之一。
先 `take` 发言权再发；每块 ≤ 几百毫秒，别攒太长的块（识别是流式的）。

## 9. 错误码总表

| HTTP | `error` | 含义 |
|---|---|---|
| 400 | `text 必须是非空字符串` / `rate 只能是 …` | 参数不对 |
| 400 | `邀请码无效，或这场会已经结束` | join 失败 |
| 401 | `unauthorized` | 没带 `X-Leion-Secret` |
| 401 | `需要登录（缺少有效 token）` | `/org/*` 没带或带错 `X-Leion-Token` |
| 401 | `auth-required` | `/terms`、`/auth/whoami` 这些老接口的同一件事（提示语不同） |
| 401 | `auth-failed` | 用户名或密码错（`/auth/login`） |
| 404 | `room not found: …` | 房间不存在（`GET /org/rooms/<id>`） |
| 404 | `没有这个接口：…` | 路径写错了 |
| 400 | `unknown action: …` | 发言权 `action` 写错（只认那五个） |
| 409 | 发言权冲突（`有人正在说话` 一类的原话） | 抢麦失败 / 锁定中 |
| 410 | `这个会议已经结束` | 房间已关闭（发言权接口） |
| 413 | 音频块过大 | 单块超 8 MB |
| 429 / 507 | `too-much-audio` / `audio-storage-full` | 公网模式的音频限流/总量保护 |
| 503 | WS 连接数满 | 退掉多余连接 |

## 11. 最小客户端骨架（伪代码）

```csharp
// 1) 登录
var login = Post("/auth/login", new { username, password, label = "desktop" });
token = login.token;

// 2) 进会（必须有 lang；hearLangs = 我要看哪些语言的译文）
var joined = Post("/org/rooms/join", new { code, lang = "zh-CN", hearLangs = new[] { "zh-CN", "en-US" } });
roomId = joined.room.id;

// 3) 订阅（secret/token 走查询参数，因为 WebSocket 加不了自定义头）
var ws = new ClientWebSocket();
await ws.ConnectAsync(new Uri($"ws://host:8789/ws?room={roomId}&secret={secret}&token={token}"), ct);

// 4) 循环收
while (ws.State == WebSocketState.Open) {
    var msg = JsonSerializer.Deserialize<JsonElement>(await ReceiveText(ws));
    switch (msg.GetProperty("type").GetString()) {
        case "frame":                       // 字幕（frame 字段）
            var f = msg.GetProperty("frame");
            var partial = f.GetProperty("partial").GetBoolean();
            var lines = f.GetProperty("lines");
            Render(f.GetProperty("lang").GetString(), lines, partial);  // partial=true → 原位替换
            break;
        case "floor":   RenderFloor(msg); break;
        case "closed":  LeaveRoom("会议已结束"); break;
        case "removed": LeaveRoom("你被移出会议"); break;
        case "kicked":  ReLogin("账号在别处登录"); break;
    }
}

// 5) 退会（发起者退会 = 整场结束）
Post("/org/rooms/leave", new { roomId });
```

保活：每 25 秒发 `{"type":"ping"}`；断线后先 `GET /frame?since=<最后 roomSeq>` 补齐再重连。

## 12. 常见坑（都真踩过）

1. **先 join 再订阅**。没进会就 WS 连上，收不到按语言分发出去的译文。
2. **别把 `speaker` 当人名**。它是 `them`/`me`；真名在 `speakerName`。
3. **`partial:true` 是"同一句的新版本"**，必须原位替换。每帧都追加一行的话，一句话会变成十几行。
4. **`notice` 是机器码**（`same-language` / `translation-interrupted`），要按界面语言翻成人话再显示。
5. **长轮询超时不代表坏**：`changed:false` 是正常心跳，照着 `since` 继续问；
   但**`reset:true` 必须把 `since` 改回来**，否则永远等不到新帧。
6. **不要用版本号猜能力**，看 `GET /version` 的 `serverFeatures`。
7. **同一账号别在两处登录**：会互相顶掉（`kicked`），表现像"随机掉线"。
