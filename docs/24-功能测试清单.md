# 24 · 功能测试清单（4.77 版）

> 用途：这一轮（4.55 → 4.77）改动很多，这里把**要测的东西**和**已知的边界**一次列清。
> 每条都写了"怎么点、应该看到什么、以及不该看到什么"。
> ⚠️ 标 `[服务端]` 的项必须先 `git pull` + **重启 relay**，否则测的是旧行为。
> APK：**4.77(106)**，`android/app/build/outputs/apk/debug/app-debug.apk`。

## 0. 开测前的准备（两分钟）

```bash
# 服务端
cd ~/glasses && git pull
systemctl stop leion || pm2 stop all          # 停掉旧进程
node scripts/doctor-db.mjs                    # 数据库必须显示"健康"；
                                              # 若显示"结构过旧"，重启一次 relay 会自动补列/建表

```

- 数据库这轮**自动补**了两样东西（都发生在 relay 启动、首次打开库时）：
  - 表 `history_hidden`（按账号删除历史记录）；
  - 列 `requests.hidden_at`（术语库申请可删除）。
- 手机端**必须**装 4.77(106)；旧 APK 看不到新增入口，也听不懂 `listen` 消息。

## 6.5 并发（两场会同时开）怎么测

> 前提：**两个不同账号**（同一账号会因单会话互踢）；两个**不同房间**。

### 6.5.1 一台手机，两个房间顺序测（验“归属不串”）

| # | 操作 | 应该看到 | 不该出现 |
|---|---|---|---|
| 1 | 账号 A 进房间 X，开麦说 5~10 秒后停下 | `ls -l /var/lib/leion/test/audio/` 出现 `room-X.pcm` 并在长 | 只有全局 `audio-in.pcm` 在长 |
| 2 | 记下 X 的字节数 | `curl -s .../audio/rooms` 里只有 X | 列出别的房间 |
| 3 | 退出 → 进房间 Y，开麦说几句 | Y 的 pcm 在长；**X 的字节数不变** | X 还在涨（说明归属错） |

### 6.5.2 两台手机同时说（验“并行”）

| # | 操作 | 应该看到 | 不该出现 |
|---|---|---|---|
| 4 | 手机1进 X 持续说；手机2进 Y 同时持续说 | relay 日志两行：“音频分流：房间 room-X → …”、“room-Y → …” | 只有一行 |
| 5 | 盯 `ls -l` 或 `node scripts/check-audio-split.mjs --host … --secret … --watch` | 两个 pcm **同时**在长 | 只有一个在长 |
| 6 | 把两个 pcm 转 wav 听 | X 里只有手机1 那个人的声音 | X 里能听到手机2 的声音 |

```bash
ffmpeg -f s16le -ar 16000 -ac 1 -i /var/lib/leion/test/audio/room-X.pcm /tmp/x.wav
```

### 6.5.3 字幕要真并行，还需一步配置（不会自动）

relay 默认仍读**单个**总线文件。要两场会各自出字幕：

```bash
# ① relay 用目录模式（每个房间一个总线文件）
node scripts/start-all.mjs ... --bus /var/lib/leion/test/buses

# ② 每场会各起一套翻译管线，写到自己的总线文件
node scripts/start-all.mjs ... --bus /var/lib/leion/test/buses/room-X.json
node scripts/start-all.mjs ... --bus /var/lib/leion/test/buses/room-Y.json
```

| 看什么 | 预期 |
|---|---|
| 手机1 房间 X 的字幕 | 只有 X 自己的句子 |
| 手朶2 房间 Y 的字幕 | 只有 Y 自己的 |
| 停掉 X 的管线 | Y 的字幕照常 |

> ⚠️ 一个识别实例只吃一路音频（1.5 GB/路）；两路真并行还需硬件能力与后续的准入控制。

### 6.5.4 先用脚本造数据（不用手机）

```bash
node scripts/check-audio-split.mjs --host http://127.0.0.1:8789 --secret <密钥> \
     --self-test --rooms room-A,room-B --seconds 3
```

## 8. 已知边界（看着像 bug，其实是设计）

| 现象 | 原因 | 以后是否要做 |
|---|---|---|
| 只有**一场会**能真正实时翻译；两场会同时开时字幕会串 | 字幕总线、音频文件、识别算力都是**单份** | 是：并发第二步/第三步（见 §9） |
| 两场会都有人说话时，历史里可能少一条转写 | 归属推不出来时**宁可不记**（写错会议比少一条糟） | 是：帧里带 roomId 就精确（已预留） |
| 听者开外放时会听到回声 | 回声来自"听者手机扬声器 → 听者麦克风" | 是：AEC |
| 拔插耳机后不会主动切到眼镜 | 设备优先级还没做，现在只跟随系统默认路由 | 是（见 §9） |
| 旧 relay + 新 APK：点「听声音」没声音、历史页读不到 | 服务端还没这些接口 | 重启 relay 即可 |
| 会议纪要那一页没有 | 老师建议砍掉，整块不做（导出也不含摘要/行动项） | 否 |

## 9. 未来可能加入的功能（按建议顺序）

**A. 并发与音频（最该做，因为直接决定"能不能两场会同时开"）**
1. **音频按房间分流**：`POST /audio?room=` 写 `audio-in-<roomId>.pcm`，`--follow` 支持多路跟读；
2. **多实例 + 准入控制**：`--max-live-meetings N`（`large-v3` int8 约 1.5 GB，P40 上约 2–3 路）；
   超出的房间进入「已建会、但未开启同传」，**界面如实告知**而不是偷偷掉帧；
3. **帧由翻译组件写 roomId**（现在是手机经 `/audio?room=` 给线索）：彻底不用推断。

**B. 声音体验**
4. **设备优先级**：耳机/眼镜 → 手机；`AudioManager.getDevices()` + `setPreferredDevice()` +
   拔插监听，界面上标出当前用哪个设备。**前提**：先真机确认眼镜（USB）被识别成什么设备类型；
5. **AEC 回声消除**：`AcousticEchoCanceler` 与录音通道联动，消掉外放回声；
6. **音频编码**（`MediaCodec` AAC/Opus）：省带宽（现在 32 KB/s/人），换更复杂的同步。

**C. 历史与转写**
7. **转写格式细化**（你说下一轮给）：时间戳 / 说话人 / 原文与译文怎么排；
8. **转写筛选**（现在只是占位按钮，点了明说还没做）；
9. **导出格式扩展**（现在只有 .docx，可加 txt / PDF）；
10. **删除可撤销**（现在删了就没了，只能重新参会才会有新记录）。

**D. 账号与语言**
11. **说话语言支持英文**（M6 后半）：服务端 `LANGS` 加 `en`、whisper 候选加英文；
    界面英文（M6 前半）已经做完；
12. **验证码直登**（M7）：原型表单没有密码字段，需要契约决定；
13. **单会话按标签隔离**（一台手机多个标签各自独立登录）；
14. **黑名单**：被移出的成员凭邀请码还能再进来（现在是软移除）。

**E. 我的页面**
15. **真实组织信息**（现在显示角色，因为系统里没有组织数据）；
16. **账号有效期管理入口**（现在只显示，续期要管理员在服务端做）。

**F. 房间页收尾（M5）**
17. 断线/重连提示；字幕主行 auto-size；投屏/扩声真正的设备接入（现在如实写"未接入"）。
