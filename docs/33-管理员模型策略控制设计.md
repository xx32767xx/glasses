# 33 · 管理员控制模型策略（全局策略 + 会议创建时冻结）

> 读者：要在管理端"换识别模型/引擎"、并且要保证**已经在开的会不被中途换掉**的人。
>
> 一句话：**策略表只有管理员能写；会议在创建那一刻把当时的策略抄一份冻结下来，整场会只认那一份。**
> 改表只影响**之后新建的会议**，运行中的会议一个字节都不变。
>
> 相关：[`26-可用模型与切换.md`](26-可用模型与切换.md)（策略表字段与全部候选）、
> [`21-房间与发言权-UI与存储设计.md`](21-房间与发言权-UI与存储设计.md)（房间/成员/侧车）、
> [`19-术语库与账号设计.md`](19-术语库与账号设计.md)（角色与权限）、[`05-数据通路.md`](05-数据通路.md)（队列与侧车）。

## 0. 三条不变量（后面所有的设计都为它们服务）

1. **只有管理员能改策略**：写入口 `/org/asr/models`，权限表里只有 `admin`。
2. **会议创建即冻结**：建房成功的那一刻把"当前有效策略"抄进 `room-strategy/<房间>.json`；
   这场会之后**只认这份快照**，管理员再改表也与它无关。
3. **失败要大声**：策略里写了没下载的模型、没装的依赖、这张卡不支持的精度 ——
   要在**管理端就拒绝或警告**，而不是等会议里每一段都返回空字幕。

## 1. 现在是什么行为（为什么不够）

| 现在的机制 | 后果 |
|---|---|
| 策略表 = `<data-dir>/asr-models.json`，切句与识别两侧**按 mtime 热读** | 管理员（或任何人）改一下，**正在开的会当场换模型**：前半段一个模型、后半段另一个，字幕风格与错率都会变，事后无法归因 |
| 只改 `languages[语种]` 的那一层 | 谁改的、改之前是什么，没有任何记录（`asr-models.json` 只剩最终态） |
| 写入口只有 CLI（`scripts/asr-models-merge.mjs`） | 要么 SSH 上去改文件，要么改仓库里的示例表；**没有权限门**，谁都能改 |
| 识别侧是**一个全局 worker**（`bridge/asr-worker.mjs`），按段里的 `lang` 选模型 | 不同会议**同语种**可以用不同模型这件事，现在架构上表达不出来 |

> 被废弃的那版设计是"每场会（甚至每台手机）自己选模型"：选择权在客户端、策略不统一、
> 也没法回答"这一场到底用了什么"。本设计反过来：**选择权收归管理员，一致性靠冻结保证**。

## 2. 数据模型（三个文件，职责分开）

### 2.1 `asr-models.json`（全局"当前策略"，唯一可写的是管理员）

结构不变（`version: 2`，`default` / `strategies` / `languages` 三层，见 `docs/26 §5`）。
它现在多一个语义：**"下一个新建会议会用的策略"**，而不是"所有会议此刻用的策略"。

### 2.2 `room-strategy/<房间>.json`（会议冻结快照，新建时写一次，之后只读）

```json
{
  "roomId": "m-7f3c…",
  "lockedAt": "2026-11-09T09:12:33.482Z",
  "lockedBy": "boss",
  "source": "asr-models.json",
  "sourceHash": "sha256:9f2a…",       // 快照取自哪一版表（对账用）
  "tableVersion": 2,
  "languages": {
    "en-US": { "strategy": "en-parakeet-gpu", "engine": "parakeet",
               "runtime": "nemo", "model": "nvidia/parakeet-tdt-0.6b-v2",
               "compute_type": "fp16" },
    "zh-CN": { "strategy": "zh-steady", "engine": "whisper",
               "model": "large-v3", "compute_type": "float16" },
    "pt-BR": { "strategy": "pt-funasr", "engine": "funasr",
               "model": "fun-asr-realtime" }
  },
  "segmentation": { "silence_ms": 800, "min_speech_ms": 500, "max_speech_ms": 30000 }
}
```

- 路径走 `lib/paths.mjs` 新增的 `roomStrategyPath(dataDir, roomId)`（和 `room-langs/`、`room-pipeline/` 同一族）。
- 写一次、不覆盖：并发建房时"文件已存在"就当成功（幂等），避免两个人同时建房互相踩。
- 关闭会议后保留（历史归因要用），清理交给 `scripts/leion-clean.mjs`（与 `room-langs/` 同一条规则）。

### 2.3 `asr-audit.jsonl`（append-only 审计）

每行一条：`{ at, by, action, before, after, source, result, note }`。
`action` 只有三种：`models.write`（改表）、`strategy.lock`（建房冻结）、`strategy.relock`（管理员手工重锁）。
**只追加、不提供删除接口**；体积一年也就几十 KB。

## 3. 时点语义：什么时候锁、锁给谁

| 事件 | 行为 |
|---|---|
| `POST /org/rooms`（建房 / 开翻译官会话）**成功** | 读当前表 → 逐语言解析出有效策略 → 写 `room-strategy/<房间>.json` → 写一行 `strategy.lock` 审计。**这是唯一的锁时点** |
| `POST /org/rooms/join`（入会） | 不锁。若该房间**还没有**冻结文件（老数据、或建房时没写成）→ 用全局表，并在日志里写一行 `本场没有冻结策略，按全局表运行` |
| 管理员改表 | 只写 `asr-models.json` + 审计。**不触碰任何 `room-strategy/*`** |
| 会议关闭 / 超时结束 | 冻结文件保留（历史/复盘要用）；`leion-clean` 按天数清理 |
| 手工重锁（可选） | `POST /org/rooms/:id/strategy/relock`，admin 专用；默认**拒绝**正在跑管线的房间（要么先结束），避免又变成"中途换模型" |

> 为什么锁在"建房"而不是"点开始同传"：建房是**发起者已经决定这场会怎么开**的那一刻，
> 也是"邀请码发出去"的那一刻；再晚就可能出现"两个人已经在说，策略还没定"的窗口。

## 4. 消费侧：解析优先级（只改一处，改在库层）

现在是"表 → 语言 → 策略 → 默认 → 命令行"（`whisper_stream.resolve_strategy`）。
插入一层**房间冻结**，优先级最高：

```
room-strategy/<room>.json   ← 会议创建时冻结（新）
   > asr-models.json 的 languages[语种]
   > strategies[策略名]
   > default
   > 命令行 --model/--compute-type
```

实现形态（尽量小）：

- **识别侧**（`bridge/whisper_stream.py`，队列消费者）：段 meta 里已经有 `room`（`_write_segment` 的字段），
  取到 `room` 后先读 `room-strategy/<room>.json`；读到就用它的 `languages[段.lang]`，读不到回落全局表。
  解析结果与 `lockedAt` 一起写进收件箱那一行（`body.strategy` 已有，扩展成 `body.strategyLockedAt`）。
- **切句侧**（`whisper_stream.py --segment-dir`）：**不冻结**（见 §9 待确认第 1 条）。
  切句参数（停顿时长等）属于"怎么收音"，不属于"用哪个模型"，且管理员调它通常是要**立刻**生效。
- **`start-multi` / `asr-worker` 命令行不变**：`--model-map` 仍传全局表；房间快照由识别进程自己按 `room` 读。
  这样不改进程编排，也不影响老数据。

## 5. 接口（沿用 `/org/...` 与 `ROLE_PERMISSIONS`，不新造一套鉴权）

`lib/accounts.mjs` 的权限表加两条：

```js
'model.read':  ['admin', 'dev'],   // dev 只读，便于测试机核对
'model.write': ['admin'],          // 写只有管理员
```

| 方法 | 路径 | 作用 | 权限 |
|---|---|---|---|
| `GET` | `/org/asr/models` | 当前表 + **逐语言解析结果** + 每个模型的可用性（`probeModel`：本地有没有、云端密钥有没有） | `model.read` |
| `POST` | `/org/asr/models/validate` | dry-run：给一份候选表，返回"每语言会落到哪个引擎/模型/精度 + 缺失项"，**不落盘** | `model.write` |
| `PUT` | `/org/asr/models` | 落盘写表（整表或 `{strategies:{…}}` 形式的增量），返回 diff | `model.write` |
| `GET` | `/org/asr/models/history` | 审计尾部（`?limit=50`） | `model.read` |
| `GET` | `/org/rooms/:id/strategy` | 这场会议的冻结策略（发起者/管理员） | `meeting.configure` + 发起者本人 |
| `POST` | `/org/rooms/:id/strategy/relock` | 手工重锁（默认拒绝对正在跑管线的房间） | `model.write` |

**错误码（与现有风格一致：`error` 是机器码、`hint` 是人话）**

| 场景 | HTTP | `error` |
|---|---|---|
| 角色不够 | 403 | `forbidden`（带 `role` / `action`，`ServerText` 已有解析） |
| 表结构不合法（未知字段/策略名形状错/精度不在枚举里） | 409 | `invalid-table`（`hint` 说清是哪个键） |
| 表写进去了，但某个策略的模型没下载 / 依赖没装 | 200 + `warnings[]` | ——（**允许保存**，但必须警告；另设 `POST /org/asr/models/validate` 供"先验再存"） |
| 同时对同一房间 relock 冲突 | 409 | `room-running` |

> **为什么允许"带警告保存"**：管理员可能是有意先把表定下来（模型稍后再下）。
> 但要让他在界面上**看见**"这条策略现在跑不了"，而不是等会议里出空字幕。

## 6. 管理端界面（`scripts/admin-ui.html` 加一个「识别模型」标签页）

- 顶部：**当前表**（三语言各一行：策略名 / 引擎 / 模型 / 精度 / 可用性徽标）。
- 中间：**改一处**（下拉选策略名 + 精度；右侧"验证"按钮走 `validate`，列出缺失项）。
- 底部：**按钮区** ——「保存并生效（只影响新建会议）」+「查看历史」；保存前二次确认，文案写明
  "已在进行的会议不受影响"。
- 只读区：最近 5 条审计（谁、何时、改了什么）。

手机端**不加任何入口**：这是管理员的活，手机只显示"本场策略"（房间详情里已带 `pipeline`，可顺手带 `strategy`）。

## 7. 并发与一致性（三个写者，各自串行）

| 写者 | 串行方式 |
|---|---|
| 管理员改表 | 新增 `withModelsLock(dataDir, task)`（照抄 `lib/accounts.mjs` 的 `withAccountsLock` 思路）：读-改-写在一个临界区里，落盘用 `tmp + rename`，改前留 `<name>.bak-<时间戳>` |
| 建房冻结快照 | 文件名即房间 id，天然互不冲突；已存在直接返回成功（幂等） |
| 审计 | `appendFileSync` 追加（单行写，不加锁） |

另外两条硬约束：

1. **冻结快照必须写成功才算建房成功**（否则"这场会到底用什么"没人知道）——写失败就回 500，让发起者重试，
   不要静默建出一个没有策略的会议。
2. **`asr-models.json` 的校验在写入前做**（形状 + 精度枚举 + 策略名白名单），不做"先写坏再报错"。

## 8. 失败模式与提示（管理端就要能看见）

| 现象 | 管理端提示 |
|---|---|
| 模型没下载 | `未下载：/opt/leion/models 里没有 large-v3-turbo`（`probeModel` 已有这个能力） |
| 引擎依赖没装 | `parakeet 的 nemo 路线需要 nemo_toolkit[asr]；当前环境导入失败` |
| 精度不被这张卡支持 | `int8_float16 在 Pascal 上不可用；这台卡建议 float16`（`check-asr-env.py` 的判定搬到 JS 只做提示） |
| 云端引擎缺密钥 | `funasr 需要 DASHSCOPE_API_KEY；当前未配置` |
| 显存吃紧（多份大模型） | `--max-models 3 时建议语言间不混用不同大模型`（提示，不拦） |

## 9. 需要你拍板的四件事

1. **切句参数要不要一起冻结？** 本设计默认**不冻结**（只冻结"用哪个模型"）。
   若冻结，则"管理员调停顿时长对在跑的会无效"，与"立刻生效"的直觉冲突 —— 我建议不冻结。
2. **锁时点：建房 vs 点「开始同传」？** 本设计取建房（邀请码发出的那一刻）。
3. **重锁（relock）要不要做？** 默认建议做但**拒绝对正在跑的房间**；也可以先只留"查看"。
4. **`dev` 能不能读表？** 本设计给 `model.read` 含 dev（便于测试机核对），写仍只有 admin。

## 10. 落地拆解（每段都有可验收的判据）

| 阶段 | 内容 | 验收 |
|---|---|---|
| **1. 数据与库层**（半天） | `lib/paths.mjs` 加 `roomStrategyPath` / `asrAuditPath`；`lib/asr-engines.mjs` 加 `resolveForRoom(roomId, lang)`（优先快照）+ `writeRoomStrategy()`；`withModelsLock` | 单测：快照优先/回落、幂等、坏快照不影响回落 |
| **2. 接口与冻结**（一天） | `/org/asr/models`（GET/PUT/POST validate）、`/org/rooms/:id/strategy`；建房时写快照 + 审计；权限 `model.read/write` | 端到端：建房→改表→**在跑的会策略不变**、新会拿到新策略；403/409 各一条 |
| **3. 管理页**（一天） | `admin-ui.html` 新标签页（读写 + 验证 + 历史） | 手工点一遍；`dev` 登录只能看不能存 |
| **4. 识别侧接线**（半天） | `whisper_stream.py` 队列消费者按 `room` 读快照；收件箱行带 `strategyLockedAt` | 同一段音频、两场不同快照 → 两个不同策略名落在各自收件箱 |

**测试清单（写进 `tests/`，与现有套件同一套 `it/check`）**

- 库层：优先级、幂等、坏 JSON、快照里缺某个语言时逐语言回落。
- API：非 admin 403（含 dev）、非法表 409、带警告保存 200、审计追加、`withModelsLock` 并发写不丢条目。
- 房间：建房写快照（含 `sourceHash` 与表内一致）、重复建房不覆盖、`relock` 对运行中房间 409。
- 识别侧（Python 单测）：给两段不同 `room` 的 meta → 解析出各自冻结的策略名；没有快照时回落全局表。
- 反向回归：改表后，已存在房间的解析结果**逐字段等于**快照（这条是本次设计最核心的断言）。

## 11. 与"废弃的那版"的差别（三句话）

1. 旧版：**每场会/每台手机自己选** → 策略碎片化、无法回答"这场用了什么"；本版：**管理员定全局，会议创建时冻结**。
2. 旧版：改表**当场影响在跑的会** → 一场会里换模型；本版：**改表只影响新会议**，在跑的会逐字段不变。
3. 旧版：改表没有入口、没有权限、没有记录；本版：**admin-only 接口 + 审计 + 逐语言可用性预检**。
