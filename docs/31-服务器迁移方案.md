# 31 · 服务器迁移方案（换更强的卡 + 在新机器上做眼镜投屏与模型测试）

> 读者：要把整套同传从 `117.50.180.93`（Tesla P40）搬到一台**新卡新机器**上的人。
> 目标有三个，**顺序不能乱**：
>
> 1. 老机器上的线上服务**保持可用**（我们组要用现有 App 测，不能频繁更新/中断）；
> 2. 新机器上先把**眼镜投屏**与**模型升级**试通（这两件事都要真机、都要反复调）；
> 3. 全部验完，再做**数据迁移与切换**，并且**不许弄坏数据库**。
>
> 数据迁移是唯一不可逆的一步，本文第 4、5 节就是为它写的。
> 相关：[`10-服务器部署.md`](10-服务器部署.md)（首次部署）、[`20-部署踩坑记录.md`](20-部署踩坑记录.md)、
> [`28-常驻与磁盘.md`](28-常驻与磁盘.md)（systemd/日志/磁盘）、[`29-接手须知.md`](29-接手须知.md)。

## 0. 一页速览（把这张表打印出来照做）

| 阶段 | 在哪做 | 做什么 | 判据（做完怎么算过） |
|---|---|---|---|
| **A. 冻结现状** | 老机器 | 记下版本/commit、备份 `/etc/leion/*` 与数据目录清单 | `git log -1`、`lib/app-version.generated.mjs` 有值 |
| **B. 新机器就绪** | 新机器 | **整盘镜像时这些"自动带过来"**（只需装驱动/定精度档）；重建路才需要装 venv/DSH/模型 → §3.1 | `nvidia-smi` 认出新卡；`preflight.cjs` 六项全绿；`check-asr-env.py` ②③ 通过 |
| **C. 新机器先跑"空调试"** | 新机器 | 用**空数据目录**起测试口，先把管线跑通（不搬数据） | `GET /version` 200；`check-live-audio --self-test` 过 |
| **D. 眼镜投屏验证** | 新机器 + 手机 | 手机服务器地址指新机器 → 我的 → 眼镜投屏 → 说话 | 镜片出译文；会议页侧边栏写「Rokid 眼镜投屏中」 |
| **E. 模型升级测试** | 新机器 | 新卡精度档位、候选模型 A/B（§7） | 每个候选都有"出字/RTF/错率"三项数字 |
| **F. 数据迁移** | 老机器 → 新机器 | **停服务** → 库 checkpoint/`VACUUM INTO` → rsync → 校验 | `doctor-db` 两个库都 `ok`；行数对得上 |
| **G. 切换** | 手机/客户端 | 把地址改到新机器（或换解析） | 真机开会话全流程正常 |
| **H. 回滚预案** | 老机器 | 老机器**不删不关**、保留 7 天 | 手机改回老地址就恢复 |

> **一句话记住**：**镜像可以在停机后打，数据不能带着写的人搬。**
> 老机器停服之前，任何"整盘 cp / rsync / 打镜像"都可能得到半页数据 —— 这就是上次把库弄坏的原因。

## 1. 要迁什么、不要迁什么（先列清单）

以 `/var/lib/leion` 为数据根（`lib/paths.mjs` 是唯一来源）。

| 路径 | 是什么 | 迁不迁 | 说明 |
|---|---|---|---|
| `live/leion.db` + `-wal` + `-shm` | 账号/房间/字幕/历史（**SQLite，WAL 模式**） | ✅ **必须，且要一致** | 见 §5。三个文件必须**同源同时刻** |
| `live/` 其余（`terms*.json`、`settings.json`、`asr-models.json`、`room-langs/`、`meeting-terms/`、`room-pipeline/`、`library-*`） | 术语库/设置/策略表/房间侧车 | ✅ 迁 | 都是小 JSON，随目录一起 rsync |
| `live/audio/`、`live/queue/`、`live/buses/` | 会议音频、识别队列、字幕总线 | ⚠️ **不必迁** | 都是"当场状态"：队列里可能有失败段（想留证据就单独留 `queue/asr/failed/`） |
| `test/` | 测试环境数据目录 | ✅ 迁（换机器后继续用它做实验） | 同上规则 |
| `var/asr-eval/` | 识别评测集与结果（**不能删**） | ✅ 迁 | 体积大，单独 rsync；`leion-clean` 从不碰它 |
| `var/cache/coraa`、`var/cache/fleurs` | 语料缓存 | 可选 | 想要历史评测可复现就迁；否则新机器重下 |
| `var/logs/` | 日志 | ❌ 不迁 | journald 里也有；需要留档就单独打包 |
| `/opt/leion/models/` | HF 模型缓存（`large-v3` 约 2.9 GB、`parakeet-tdt-0.6b-v2`…） | 可选 | 迁移更稳（不用重下）；也可 `python3 scripts/fetch-model.py large-v3 --mirror` 重下 |
| `/opt/leion/venv/` | Python 环境（含 `nvidia-*-cu12`） | ❌ **不迁** | venv 绑绝对路径与系统 CUDA，**必须在新机器重建**（§2.3） |
| `~/deepseek-harness` | 大脑（DSH 检出，**已构建**） | ❌ 不迁 | 新机器重新 clone + `pnpm install && pnpm build`（§2.4） |
| `/etc/leion/` | `secrets.env`、`asr.env`、`tencent.csv` | ✅ 迁，**权限 600/700** | 见 §3.4；`asr.env` 建议在新机器**重新生成** |
| `/etc/systemd/system/leion.service` | 常驻单元 | ✅ 重写一份 | 见 §2.6（路径、`User=`、`EnvironmentFile=` 全部要对齐新机器） |
| 仓库 `~/glasses` | 代码 | ✅ `git clone` + checkout 同一个 commit | 记下老机器 `git log -1` 的 hash |

**不迁的三样一定要记住**：`venv`、DSH 检出、systemd 单元 —— 它们都写死了旧机器的路径，搬过去只会"看起来在跑、其实指错地方"。

## 2. 新机器就绪（A→B，半天）

> 目标：**在一个空数据目录上把管线跑起来**。这一步不碰任何生产数据，出问题就在这一步出。

### 2.1 硬件/驱动

- 新卡驱动与 CUDA 12 运行库装好：`nvidia-smi` 能列出卡；`python3 scripts/check-asr-env.py` 的 ② 项过。
- ⚠️ **新卡要重新选精度档**（P40 是 Pascal，只能 `int8_float32`；新卡有 FP16 张量核心，应该用 `float16`）。
  这一点直接影响"跑得快不快"，见 §7.1。**不要照抄老机器的 `--compute int8_float32`**。
- 若新卡是 RTX 50 系，需要更新的 CUDA/cuDNN 组合（cu12.8+）；先在 `check-asr-env.py` 里看它怎么说。

### 2.2 系统依赖 + Node（**必须 ≥ 22.5**）

```bash
sudo apt update && sudo apt install -y python3-venv python3-pip curl git ca-certificates rsync sqlite3
# Node 用 NodeSource 22.x（apt 自带的 12/18/20 跑不了 node:sqlite，会 3 秒一重启）
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash - && sudo apt install -y nodejs
node -v            # ≥ v22.5
```

### 2.3 Python 环境（**在新机器重建，不要拷 venv**）

```bash
cd ~/glasses && python3 -m venv .venv && . .venv/bin/activate
pip install -U pip wheel
pip install faster-whisper numpy websockets sherpa-onnx        # 三轮需要的东西
pip install nvidia-cublas-cu12 "nvidia-cudnn-cu12==9.*"        # GPU 必需（cu12 运行库）
python3 scripts/check-asr-env.py                                # ②③ 必须有结果
```

> 老机器 `/opt/leion/venv` 里的包用 `pip freeze > requirements.txt` 导一份**版本清单**带过去，
> 但**只用来装**，不要拷目录。

### 2.4 大脑（DSH）检出

```bash
git clone <deepseek-harness 仓库> ~/deepseek-harness
cd ~/deepseek-harness && corepack enable && corepack prepare pnpm@latest --activate
pnpm install && pnpm build
export DSH_CHECKOUT="$HOME/deepseek-harness"     # 单元文件里也要写
```

### 2.5 代码与数据目录权限

```bash
git clone <glasses 仓库> ~/glasses && cd ~/glasses
git checkout <老机器 git log -1 的 hash>          # A 阶段记下来的那一个
sudo mkdir -p /var/lib/leion && sudo chown "$USER": /var/lib/leion   # 否则 EACCES
```

### 2.6 systemd 单元（照 docs/28 §2.1 抄，但逐项对齐新机器）

三处**必须改**：`ExecStart` 的 node 绝对路径（`which -a node` 确认是 22.5+）、
`--data-dir`/`--port`（先用测试口）、`EnvironmentFile=`（`secrets.env` + `asr.env` 都要）。
`asr.env` 建议用脚本在新机器上**重新生成**（它装的是 cu12 的 `LD_LIBRARY_PATH`）：

```bash
sudo python3 scripts/make-env-file.py /opt/leion/venv \
     --hf-home /opt/leion/models --out /etc/leion/asr.env
```

### 2.7 空调试（先别搬数据）

```bash
node scripts/preflight.cjs                 # 六项全绿（① 必须 ≥ Node 22.5）
node scripts/start-multi.mjs --public --data-dir /var/lib/leion/new --port 8790 \
     --compute float16 --max-models 3 --idle-flush-ms 5000 --quiet-logs
curl -s http://127.0.0.1:8790/version      # 200 且有 appVersion
node scripts/check-live-audio.mjs --self-test
```

到这一步，**新机器已经能翻译了**（空数据目录、无历史）。§4 的眼镜验证与 §7 的模型测试都在这个状态做。

## 3. 三条迁移路线，选一条（**你们做的是 3.1：整盘镜像**）

### 3.1 路线一：用**当前服务器做整盘镜像**（推荐；前提是能停机打镜像）

"依赖自动装好"这句话对这条路线**基本成立** —— 系统盘快照会把下面这些**原样带过去**，
路径也不变，所以**不用重装**：

| 随镜像自动带过去 | 为什么能用 |
|---|---|
| 操作系统、内核、账户 | 整盘 |
| **NVIDIA 驱动 / CUDA 运行库** | 系统层，跟着镜像走（但见下面 ⚠️①） |
| **Node 22.x**（`/usr/local/bin/node`） | 单元里的绝对路径没变 |
| **`/opt/leion/venv`**（含 `nvidia-*-cu12`、faster-whisper、sherpa-onnx…） | venv 的绝对路径没变 → 可以直接用（这也是**为什么整盘镜像比"重装"省事**：§2.3 那一步可以跳过） |
| **`~/deepseek-harness`**（已 `pnpm build`） | 路径没变，`DSH_CHECKOUT` 还指得对 |
| **`/etc/leion/*`**（`secrets.env` / `asr.env` / `tencent.csv`） | 权限也随盘 |
| **`/etc/systemd/system/leion.service`** | 单元原样（`ExecStart` 的 node 路径仍然对） |
| **`/opt/leion/models`**（large-v3 2.9 GB、parakeet…） | 不用重下 |
| **`/var/lib/leion`（含 `leion.db` 三个文件）** | 只要打镜像时**没人在写**，它就是一致的 |

**但有五件事镜像**救不了**，必须逐条处理：

| # | 问题 | 现象 | 怎么办 |
|---|---|---|---|
| ⚠️① | **驱动与"更好的卡"不一定兼容** | 开机 `nvidia-smi` 失败 / 列不出新卡 / `Failed to initialize NVML` | 先看新卡型号需要哪一版驱动；不够就**在新机器上升级驱动**（`apt install nvidia-driver-<ver>` 或官方 `.run`），再 `check-asr-env.py` 复查。**这是整盘镜像最常见的翻车点** |
| ⚠️② | **打镜像时服务还在写库** | 新机器上 `database disk image is malformed` 或"记录少了" | **打镜像前必须 `sudo systemctl stop leion`**（§3.1.1） |
| ⚠️③ | **`/var/lib/leion` 若在独立数据盘上** | 新机器数据目录是空的 | 数据盘**也要一起做快照**；否则按 §4 单独 rsync |
| ⚠️④ | **网卡名/MAC 变了** | 个别系统会改 `eth0→ens5`，若某处绑了 IP 就连不上 | 我们绑 `0.0.0.0`，一般没事；开机后 `ip a` 确认一下，再看安全组 |
| ⚠️⑤ | **镜像里带着密钥** | 谁能拿到镜像，谁就能读 `secrets.env`（腾讯/DashScope/DeepSeek 全在里面） | 镜像当敏感资产管：别放公共对象存储的公开桶；交接后按需**轮换密钥** |

#### 3.1.1 正确的操作顺序（**停机 → 收库 → 打镜像 → 开新实例**）

```bash
# ① 老机器：停服务（唯一不可省的步骤）
sudo systemctl stop leion
sudo systemctl status leion --no-pager | head -5        # 期望 inactive (dead)
pgrep -af 'start-multi|asr-worker|whisper_stream|harness-side' || echo 无残留进程

# ② 把库"收干净"，并留一份干净副本（镜像里那份是给启动用的；副本是兜底）
for D in live test; do
  sudo sqlite3 /var/lib/leion/$D/leion.db "PRAGMA wal_checkpoint(TRUNCATE); PRAGMA integrity_check;"
  sudo sqlite3 /var/lib/leion/$D/leion.db "VACUUM INTO '/var/tmp/leion-$D-$(date +%F).db';"
done

# ③ 控制台：制作自定义镜像（系统盘）——跨地域要"复制镜像"，跨账号要"共享镜像"
# ④ 用镜像开新实例；新机器上用同一个系统盘容量（别比老机器小）
```

> 这一段的代价是"线上停几分钟"。**如果这几分钟绝对不能停**，就走 §3.2。

#### 3.1.2 新实例开机后的**五步验收**（顺序别乱）

```bash
# ① 先把自动重启关掉：镜像里单元是 enable 的，开机就会抢 8788
sudo systemctl disable --now leion
sudo systemctl status leion --no-pager | head -5

# ② 驱动/新卡（整盘镜像最可能出问题的一环）
nvidia-smi                                    # 能列出新卡 + 驱动版本
python3 scripts/check-asr-env.py              # ②③ 有数字；它会告诉你这张卡该用哪档精度

# ③ 依赖确实还在（这正是"依赖自动装好"的验法）
which -a node; node -v                        # ≥ v22.5
source /opt/leion/venv/bin/activate && python -c "import faster_whisper, numpy; print('ok')"
ls /opt/leion/models | head                   # large-v3 / parakeet…

# ④ 数据完整性（**先体检再起服务**）
cd ~/glasses
node scripts/doctor-db.mjs                    # 两个库都 ok；坏就 --fix（先备份再 VACUUM INTO）
sqlite3 /var/lib/leion/live/leion.db "select count(*) from accounts; select count(*) from utterances;"

# ⑤ 先用测试口起，别直接上 8788
node scripts/preflight.cjs
node scripts/start-multi.mjs --public --data-dir /var/lib/leion/test --port 8789 \
     --compute <按新卡定档> --max-models 3 --idle-flush-ms 5000 --quiet-logs
curl -s http://127.0.0.1:8789/version
```

> ⚠️ 还差一件：**精度档位**。老机器（P40 / Pascal）是 `int8_float32`；新卡有 FP16 张量核心，
> 应该用 `float16`（表里 `compute_type` 或启动参数都行）。**照抄老档位会白白慢一档**，见 §7.1。
> 另外 `--compute` 只在"表里没写"时才有意义 —— 先 `node scripts/asr-model-switch.mjs --data-dir /var/lib/leion/test`
> 看表里现在是什么。

### 3.2 路线二：**不停服**打镜像（数据必须在镜像外单独搬）

适用：那几分钟真停不了。做法是**把镜像只当"系统和依赖"的载体，库不用镜像里那一份**：

```bash
# 老机器：不停服务也能打镜像（镜像里那份库可能不一致，我们不用它）
# 然后按 §4 走一遍：停服 → checkpoint/VACUUM INTO → rsync 数据目录 → 对账

# 新机器：**启动服务之前**，用 rsync 过来的那份覆盖掉镜像里自带的库
sudo systemctl disable --now leion
sudo rm -f /var/lib/leion/live/leion.db-wal /var/lib/leion/live/leion.db-shm
sudo rsync -aHAX --numeric-ids --delete /path/to/fresh-copy/leion.db /var/lib/leion/live/
node scripts/doctor-db.mjs
```

> 这条路的代价：**停机窗口没有消失，只是从"打镜像前"挪到了"切数据时"**，还多了一次"删 -wal/-shm"的手工步骤
> （漏删就会踩 §5 的"两半不同源"）。能停机就不要走这条。

### 3.3 路线三：系统重建 + 数据 rsync（跨云/跨账号，或新机器不想继承旧系统时）

按 §2 在新机器上重建系统，然后**只在切换窗口里**做 §4 的数据搬运。
推荐用 `rsync -aHAX --numeric-ids`（保留权限/属主/硬链接/扩展属性），**不要用 `cp -r`**。
这条路的好处是"新系统干净"，代价是 §2 那半天，以及 §2.1 的驱动/精度档要重新定。

### 3.4 无论哪条路线，**老机器都保持开机、不删数据、不卸单元**（回滚用）

## 4. 数据迁移（F 阶段，唯一不可逆的一步）

> 时间窗口估算：停服 ~1 分钟 + 拷贝（按数据量；`var/asr-eval` 往往是最大头）+ 校验 10 分钟。

### 4.1 第一步：**停写**（这是防坏库的全部秘密）

```bash
# 老机器
sudo systemctl stop leion
sudo systemctl status leion --no-pager | head -5      # inactive (dead)
pgrep -af 'start-multi|asr-worker|whisper_stream|harness-side' || echo '没有残留进程'
```

如果还有残留（尤其是 `whisper_stream.py` / `harness-side`），等它们退出再动文件。

### 4.2 第二步：把库**收干净**（checkpoint + 一致性导出）

```bash
cd /var/lib/leion
for D in live test; do
  sudo sqlite3 $D/leion.db "PRAGMA wal_checkpoint(TRUNCATE);"      # 把 -wal 并回主库
  sudo sqlite3 $D/leion.db "PRAGMA integrity_check;"               # 期望只有一行 ok
  # 再导出一份"绝对一致"的库（VACUUM INTO，能读出页面就能重写干净的库）
  sudo sqlite3 $D/leion.db "VACUUM INTO '/var/tmp/leion-$D-$(date +%F).db';"
  ls -l /var/tmp/leion-$D-*.db
done
```

> 为什么两件事都做：checkpoint 让**原来的三个文件**也变成一致状态（拷目录时不会踩到半页）；
> `VACUUM INTO` 那一份则是"重建后的干净库"，是**兜底证据**（哪怕目录拷贝出了问题，它还在）。
> 这个思路与 `scripts/doctor-db.mjs` 的 `--fix` 一致（见 `docs/29` 与 `docs/20 §14`）。

### 4.3 第三步：搬数据目录（停服状态下一次搬完）

```bash
# 在白名单机器上（老机器）
sudo rsync -aHAX --numeric-ids --info=progress2 \
     /var/lib/leion/  newbox:/var/lib/leion/
# 需要评测数据的话再单独搬
sudo rsync -aHAX --numeric-ids --info=progress2 var/asr-eval/ newbox:~/glasses/var/asr-eval/
# 库的干净副本也带过去（兜底）
sudo rsync -aHAX /var/tmp/leion-live-*.db /var/tmp/leion-test-*.db newbox:/var/tmp/
```

**三个"必须"**：

1. `leion.db`、`leion.db-wal`、`leion.db-shm` **要么都拷、要么先用 4.2 收干净**；
   只拷主库 = 最近的提交静默丢失（不报错，只是"记录少了"）；
2. 拷贝**期间不许有进程写这三个文件**（4.1 已经停了）；
3. 用 `-aHAX --numeric-ids`，否则 `var/secrets`、`queue` 的权限/属主会变，出现 `EACCES`。

### 4.4 第四步：密钥与配置

```bash
# 老机器 → 新机器
sudo rsync -aHAX /etc/leion/tencent.csv newbox:/etc/leion/
sudo rsync -aHAX /etc/leion/secrets.env newbox:/etc/leion/
# 新机器上确认权限（600 文件 + 700 目录）
sudo chmod 700 /etc/leion && sudo chmod 600 /etc/leion/secrets.env /etc/leion/tencent.csv
# asr.env（LD_LIBRARY_PATH）在新机器上重新生成，不搬
```

### 4.5 第五步：新机器上**先体检、再起服务**

```bash
# 新机器
cd ~/glasses
node scripts/doctor-db.mjs                      # 两个库都要 ok（有 --fix 先备份再重建）
node scripts/preflight.cjs                      # 六项全绿
python3 scripts/check-asr-env.py                # ②③ 有数字

# 起服务（先测试口，用搬过来的 test 数据目录）
node scripts/start-multi.mjs --public --data-dir /var/lib/leion/test --port 8789 \
     --compute float16 --max-models 3 --idle-flush-ms 5000 --quiet-logs
```

### 4.6 第六步：**对账**（这一步最少 10 分钟，但别省）

```bash
# 老机器与新机器各跑一遍，把数字贴在一起比
for D in live test; do
  echo "== $D"
  sqlite3 /var/lib/leion/$D/leion.db \
    "select 'accounts', count(*) from accounts
     union all select 'rooms', count(*) from rooms
     union all select 'utterances', count(*) from utterances
     union all select 'history_hidden', count(*) from history_hidden;" 2>/dev/null
done
```

判据：**两边数字一致**（停服后老机器不应再有增长）；`doctor-db` 两边都 `ok`；
`GET /version` 与 `lib/app-version.generated.mjs` 与老机器一致。

## 5. 数据库专项：上次为什么会坏，这次怎么保证不坏

### 5.1 三种坏法（`scripts/doctor-db.mjs` 的文件头就写着）

| 坏法 | 现象 | 为什么会发生 |
|---|---|---|
| 拷到了**半页**（服务还在写） | `database disk image is malformed` | relay 正在写库时 `cp`/镜像 |
| **只拷了 `leion.db`**，没拷 `-wal` | 不报错，只是"最近的记录少了" | 以为主库就是全部 |
| `-wal` / `-shm` **与主库不同源** | SQLite 直接判损坏 | 分两次拷、或其中一次失败重试 |

### 5.2 这次的保证（每一条都对应上面一种坏法）

1. **停服**再做任何文件操作（4.1）→ 排掉"半页"；
2. **checkpoint + `VACUUM INTO` 兜底**（4.2）→ 即使目录拷贝出问题，还有一份干净库；
3. **整目录一起 rsync**（4.3）→ 三个文件同源；
4. **`doctor-db` 体检 + 对账**（4.5/4.6）→ 把"静默少记录"这类看不见的问题变成数字比对；
5. **老机器不删**（3.3）→ 最坏情况回滚即可。

### 5.3 如果新机器上 `doctor-db` 报坏

```bash
cd ~/glasses
node scripts/doctor-db.mjs --fix                       # 先备份（.bak-时间戳），再 VACUUM INTO 重建
node scripts/doctor-db.mjs                             # 复查
# 真修不回来：用 4.2 那份 /var/tmp/leion-<D>-<日期>.db 顶上（它就是重建出来的干净库）
```

## 6. 眼镜投屏在新机器上的验证（D 阶段；与迁移解耦）

投屏**不依赖 GPU**：它只要求"手机能连到这台机器的 relay"。所以可以**先于数据迁移**在新机器上验完。

1. 手机 App → 设置 → 服务器地址改成**新机器**（`http://<新IP>:8789`）+ 密钥；
2. 我的 → **眼镜投屏** → 开始投屏 → 状态到「Rokid 眼镜投屏中」；
3. 手机进会议页 → 右侧抽屉应显示「…Rokid 眼镜投屏中」，侧边栏「投屏」写「Rokid 眼镜」；
4. 说一句 → 镜片出译文；电脑日志出现 `投屏：定稿（Rokid） → …`；
5. 去翻译官页再验一次（这条是 5.140 才接上的，见 `docs/09` §13.6c）。

> 眼镜的"连接"在**手机侧**（Rokid AI App + 蓝牙），服务器不知道眼镜存在 ——
> 所以换服务器**不影响**眼镜配对，只影响手机能不能连到 relay。

## 7. 新卡上的模型升级测试（E 阶段）

### 7.1 先定精度档（这是新卡唯一必须重定的参数）

| 卡 | `--compute` / 表里 `compute_type` | 说明 |
|---|---|---|
| Tesla P40（老） | `int8_float32` | Pascal 没有 FP16 张量核心 |
| 新卡（有张量核心） | **`float16`** | 先跑 `python3 scripts/check-asr-env.py` 看它给的建议，再按 §7.2 量 |

### 7.2 候选模型（一次只换一样，留下数字）

```bash
# ① 现状基线（新卡 + float16 + large-v3）
node scripts/asr-model-switch.mjs --data-dir /var/lib/leion/test --lang zh-CN --model large-v3
node scripts/asr-try.mjs --data-dir /var/lib/leion/test --pcm <中文字轨> --rate 16000 --seconds 8

# ② 快 3~4 倍的 turbo（中文）：同一段音频，比耗时与文字
node scripts/asr-model-switch.mjs --data-dir /var/lib/leion/test --lang zh-CN --model large-v3-turbo

# ③ 英语现在可以试 NeMo 路线了（P40 上 `en-parakeet-gpu` 一直没装）
python3 -m pip install -U "nemo_toolkit[asr]"
node scripts/asr-model-switch.mjs --data-dir /var/lib/leion/test --lang en-US --strategy en-parakeet-gpu
node scripts/asr-try.mjs --data-dir /var/lib/leion/test --wav <英语样本> --lang en-US

# ④ 腾讯云（与卡无关）：一条命令就能验
sudo env TENCENT_ASR_SECRET_FILE=/etc/leion/tencent.csv \
  node scripts/asr-try.mjs --wav <样本> --lang en-US --engine tencent --model 16k_en
```

**每个候选都要记三项**：出字（有/无）、耗时与 RTF、以及一份可比的错率（评测包见 `docs/14`，
`node scripts/asr-try.mjs --data-dir … ` 只给单段，正式错率走 `asr-eval` 的评测流程）。

> ⚠️ 判据不要混：**"能不能用"看单段出字；"该用哪个"看同一批数据的错率**。
> 换 STRATEGY 前至少要有一次同数据对照（`docs/26 §2.4` 里腾讯 vs Parakeet 那一段就是反面教材）。

## 8. 切换与回滚

### 8.1 切换（G 阶段，选一个"没人开会"的窗口）

```bash
# 新机器：正式口（8788 / live 数据目录）
sudo systemctl enable --now leion           # 单元里的 --data-dir 指向 /var/lib/leion/live
sudo systemctl status leion --no-pager | head -8
sudo journalctl -u leion -n 40 --no-pager   # 无 ERR_UNKNOWN_BUILTIN_MODULE / libcublas
```

客户端侧二选一：① **改地址**（手机设置里的服务器地址改成新 IP，最快）；② 换解析/弹性 IP（要等 TTL）。

### 8.2 回滚（H 阶段，随时可用）

1. 手机把服务器地址改回**老机器**（或把解析切回）；老机器上 `sudo systemctl start leion`；
2. 老机器数据**保持迁移那一刻的状态**（迁移后它没再跑过业务，所以不会出现"两边都写过"的分叉）；
3. 回滚期间新机器可以继续当测试机（用 `test` 数据目录，端口 8789），不影响老机器。

> 保留期建议 **7 天**：期间老机器不停机、不卸单元、不删 `/var/lib/leion`；
> 7 天后确认无回滚，再做下线与清理。

## 10. 踩过的坑（都是"不报错、只是结果不对"那一类）

| 坑 | 现象 | 依据 |
|---|---|---|
| Node 用 apt 的 20 | 服务 3 秒一重启（`node:sqlite` 不存在） | `docs/28` §2.4 |
| 单元里少 `EnvironmentFile=…/asr.env` | 每段都 `libcublas.so.12 not found` | `docs/28` §2.1 |
| 数据目录属主不对 | `EACCES`，看起来像"库坏了" | `docs/10` §0 第⑤步 |
| 模型没搬也没下 | 第一段识别卡 2.9 GB 下载，看起来像"卡住" | `docs/10` 排障表 |
| 只拷 `leion.db` | 记录静默变少 | `docs/20 §14`、`scripts/doctor-db.mjs` 文件头 |
| 安全组没放行 | 手机连不上，转发进程日志却正常 | `docs/20`（内网可达≠公网可达） |
| 照抄老机器的 `int8_float32` | 新卡白白慢一档 | §7.1 |

## 附：一页命令（按顺序复制）

```bash
# ── 老机器：停写入 + 收干净库 ─────────────────────────────────
sudo systemctl stop leion
pgrep -af 'start-multi|asr-worker|whisper_stream|harness-side' || echo 无残留
for D in live test; do
  sudo sqlite3 /var/lib/leion/$D/leion.db "PRAGMA wal_checkpoint(TRUNCATE); PRAGMA integrity_check;"
  sudo sqlite3 /var/lib/leion/$D/leion.db "VACUUM INTO '/var/tmp/leion-$D-$(date +%F).db';"
done

# ── 老机器：搬到新机器（一次搬完，含 -wal/-shm）────────────────
sudo rsync -aHAX --numeric-ids --info=progress2 /var/lib/leion/ newbox:/var/lib/leion/
sudo rsync -aHAX --numeric-ids --info=progress2 ~/glasses/var/asr-eval/ newbox:~/glasses/var/asr-eval/
sudo rsync -aHAX /var/tmp/leion-*-$(date +%F).db newbox:/var/tmp/
sudo rsync -aHAX /etc/leion/secrets.env /etc/leion/tencent.csv newbox:/etc/leion/

# ── 新机器：体检 → 起服务 → 对账 ──────────────────────────────
cd ~/glasses
node scripts/doctor-db.mjs
node scripts/preflight.cjs
python3 scripts/check-asr-env.py
node scripts/start-multi.mjs --public --data-dir /var/lib/leion/test --port 8789 \
     --compute float16 --max-models 3 --idle-flush-ms 5000 --quiet-logs
# 对账（两台各跑一遍，数字要一致）
sqlite3 /var/lib/leion/live/leion.db "select count(*) from accounts; select count(*) from utterances;"
```
