## 2. 全部可用模型（按引擎分组）

### 2.1 本地 whisper（faster-whisper / CTranslate2，用 GPU）

| 策略名 | 模型 | 适合 | 实测（口径） |
|---|---|---|---|
| `default` | `large-v3` | 中文主力 | 中文口语 16.9% / 葡语口语 17.4%（`asr-norm-v2` 规范化口径，holdout 504/500 条）；RTF 0.19 / 0.24（P40） |
| `en-turbo` | `large-v3-turbo` | 想快 3~4 倍、接受略降 | 本仓库**未单独测**英文 WER |
| `en-distil` | `distil-large-v3` | 纯英文蒸馏版（约 756M） | 未测英文；葡语版 `distil-whisper-large-v3-ptbr` 在 500 条巴葡上 **24.5%**（比 large-v3 差） |
| `en-tiny` | `tiny` | **只用来验证"切换真的生效"**（故意很差） | 别用于业务 |
| `en-fast` / `en-accurate` | （继承 `default`） | 只改切句窗口（快 / 准两档） | 切句参数有实测（docs/14 §6.0），模型未变 |

> ⚠️ P40 是 Pascal（算力 6.1），**没有 FP16 张量核心**：`compute_type` 必须
> `int8_float32`（或 `float32`）。表里写 `float16` 启动即失败 —— 识别侧会自动纠正并**大声说明**换过。

### 2.2 本地 Parakeet（NVIDIA Parakeet TDT 0.6B v2）

| 策略名 | 路线 | 说明 |
|---|---|---|
| `en-parakeet` | `runtime: onnx`（sherpa-onnx，**CPU**） | 英语首选。外部报告：总体 WER 2.13%、**美音 0.93%**、巴西口音英语 2.52%。本机实测 **RTF 0.10**（6.7s 音频 0.69s，8 核 Haswell），**不占显存** |
| `en-parakeet-gpu` | `runtime: nemo`（torch + NeMo） | 同模型的 GPU 路线。⚠️ 需要 `nemo_toolkit[asr]`，本机**还没装**；且 P40 上必须 `fp32` |

> 为什么英语现在用它：美音 WER 0.93% 明显好于 whisper 一档，而且走 CPU 不吃显存 ——
> 中文（whisper large-v3）继续占 GPU，两边不打架。

### 2.3 云端 DashScope（阿里 Fun-ASR，实时 WebSocket）

| 策略名 | 模型 | 实测（500 条 CORAA 巴葡，用户那批评测） |
|---|---|---|
| `pt-funasr` | `fun-asr-realtime` | **19.81%** WER / P50 938ms / P95 3202ms / **成功率 100%**（最快且最稳） |

- 需要两个环境变量：`DASHSCOPE_API_KEY`、`DASHSCOPE_WS_URL`（端点通常是**账号专属域名**，不是公开文档里那个）。
- 模型名必须用**实时（WebSocket）端点认的名字**：`fun-asr-flash-*` 那类是兼容模式的名字，能连但不能用于实时。
- 换模型前先体检：`node scripts/asr-doctor.mjs --data-dir …`（会报密钥形状对不对，不打印密钥）。

### 2.4 云端腾讯云（一句话识别）

| 策略名 | 模型（引擎编码） | 状态 |
|---|---|---|
| `en-tencent` | `16k_en` | ✅ **已通**（2026-11-06 真密钥实测）：三语全部出字并有错率数字，见下表 |

> 5.76 那次卡在 CAM 授权（`AuthFailure.UnauthorizedOperation`）；授权 + 开通服务之后一次就通了，
> 没再改过参数 —— 这反过来证明当时"签名与请求形状都是对的"那个判断。

#### 实测（2026-11-06，本机直连腾讯；真密钥、真音频、逐条对参考文本）

| 语种 | 引擎编码 | 数据（`var/asr-eval/packs`） | 条数 | 错率（v1 严格 / norm-v2） | 每段耗时 | RTF |
|---|---|---|---|---|---|---|
| `zh-CN` | `16k_zh` | `zh-eval`（FLEURS 朗读） | 30 | **3.74% / 3.14%**（字错率） | 0.44–1.14 s | 0.05 |
| `pt-BR` | `16k_pt` | `pt-coraa`（CORAA **真实口语**） | 20 | **15.82% / 15.82%**（词错率） | 0.72–0.98 s | 0.28 |
| `en-US` | `16k_en` | LibriSpeech `validation` 前 73 条（朗读） | 73 | **2.78% / 2.70%**（词错率） | 0.34–0.78 s | 0.07 |

口径要说清（否则这几个数字会被误用）：

- **朗读 ≠ 口语**：中文/英语那两行是朗读语料，巴葡那行是真实口语（有口音标注）。
  同一个模型在这两类数据上的错率天然差一个量级，**不同行之间不要横向比**。
- 条数少（20 / 30 / 73），用途是"能不能用"，不是正式评测数字（正式评测见 `docs/14`）。
- 巴葡 15.82% 可以和 `docs/26 §2.1` 里 whisper large-v3 在**同一份 CORAA 口语**上的
  17.4% 对照着看（口径都是 asr-norm-v2）—— 但条数不同（20 vs 500），只作方向性参考。
- 中文 30 条里有 1 条标点断句位置不同（腾讯在句号处切开），算进严格口径；规范化后消失。

> **英语这一行是"能不能用"的答案，但还不是"该用哪个"的答案**：`16k_en`（2.70–2.78%）
> 与 Parakeet（外部报告总体 2.13%、美音 0.93%，**但那是外部报告、不是我们这台机器上的数**）
> 要**同数据同口径**比过才能换 —— 那一步要在服务器上做（Parakeet 模型在那台机器）。
> 在那之前英语保持 `en-parakeet`。

#### 密钥怎么给（两种都行，都**不进仓库**）

> ⚠️ **变量名必须是我们读的那两个**：`TENCENT_ASR_SECRET_ID` / `TENCENT_ASR_SECRET_KEY`。
> 写成 `SECRETID=` / `SECRETKEY=` 之类（腾讯控制台页面上是那种写法）**不会被读到** ——
> systemd 照样把它设进环境，但代码找的是带前缀的名字，于是又变成"缺密钥"，白折腾一轮。

```bash
# ① 环境变量（写进 /etc/leion/secrets.env —— 那份是**手写**的；600）
TENCENT_ASR_SECRET_ID=AKID...
TENCENT_ASR_SECRET_KEY=...

# ② 文件（更安全：不进 shell history、ps 里也看不到）
TENCENT_ASR_SECRET_FILE=/etc/leion/tencent.csv     # chmod 600；CSV（表头 SecretId,SecretKey）或 JSON 都认
```

> ⚠️ **文件模式要小心服务用户**：`chmod 600` 之后文件归 root，而**服务不一定是 root 跑的**。
> 现场就撞过：`PermissionError: [Errno 13] Permission denied` —— 日志里每段一句、读起来像"腾讯坏了"。
> 要么 `chown <服务用户>` / `chgrp <服务用户> + chmod 640`，要么**直接用 ① 环境变量**
> （`secrets.env` 由 **systemd 以 root 解析**，任何服务用户都拿得到，最省事）。
> 5.132 起权限错会直接把这句指路打在错误信息里。

> ⚠️ **别写进 `/etc/leion/asr.env`**：那份是 `scripts/make-env-file.py` **生成**的
> （放 `LD_LIBRARY_PATH` 那几条），换机器/升级 CUDA 时会重新生成一次，手加的行走丢。
> 手写的秘密一律进 `secrets.env`（单元里两个 `EnvironmentFile=` 都读）。

可选 `TENCENT_ASR_REGION`（缺省 `ap-shanghai`；文档说本接口不需要 Region，传了也无害）、
`TENCENT_ASR_ENDPOINT`（换端点 / 离线演练）。

> `asr-doctor`（5.128 起）**也认 `TENCENT_ASR_SECRET_FILE`**：会打出「来源=…路径」+ 形状结论。
> 但**权限要注意**：`tencent.csv` 是 `600` 归 root，服务是 root 跑的所以能读，
> 而你自己的 shell 读不了 → 复查时用 `sudo`：
> `sudo env TENCENT_ASR_SECRET_FILE=/etc/leion/tencent.csv node scripts/asr-doctor.mjs --data-dir /var/lib/leion/test`
> （5.126 之前它只查环境变量，所以文件模式会误报"缺 secretId / 缺 secretKey" —— 那是**假话**，已修。）

#### 验证命令（一条）

```bash
export TENCENT_ASR_SECRET_FILE=/etc/leion/tencent.csv
node scripts/asr-try.mjs --wav var/asr-eval/packs/pt-coraa/46051_sp_.wav \
     --lang pt-BR --engine tencent --model 16k_pt
```

退出码：**0 = 通了**；**3 = 腾讯回话/回错但没出字**（日志里 `→ …` 就是下一步）；
**2 = 根本没跑到识别**（缺密钥 / 形状不对 / 引擎编码写错）。

> ⚠️ `--engine tencent` 必须**同时给 `--model 16k_en`（或 `16k_pt` / `16k_zh` 等）**。只给引擎时，
> 档案里还带着 whisper 的模型名（`small` / `large-v3`），5.124 起会在发请求**之前**拦下并说清怎么改 ——
> 否则它会被当作引擎编码发出去，而那个报错和"密钥错"分不开。

#### 两条硬上限（代码里已经提前拦）

腾讯一句话识别：**音频 ≤ 60 秒、文件 ≤ 3 MB**。我们切出来的段是 0.6–30 s（约 1 MB），
正常不会撞到；但 `asr-try` 直接喂长文件时会超，所以 `TencentEngine.transcribe` 在**发请求之前**
就判掉并说清"切成更短的段"，而不是白等一次 20 秒超时。

#### 切完**当场**就报「加载失败（…腾讯云引擎缺少密钥…）」怎么查

`en-US` 切成 `en-tencent` 之后，日志里每段都出现：

```
[识别] 加载 tencent:16k_en（引擎 tencent）…
[识别] 这一段要求的引擎/模型 tencent:16k_en 加载失败（策略 en-tencent，…）：RuntimeError: 腾讯云引擎缺少密钥…
```

**这不是腾讯的问题，是服务进程的环境里没有密钥**（你手动 `source` 过 env，所以命令行能通、服务不通）。

从 5.131 起，**启动时就会先探一次**并给出指路（`journalctl -u leion | grep 云端引擎`）。
按这个顺序查，三步内必然定位：

```bash
# ① 服务进程实际拿到的环境（最硬的判据：变量到底在不在 worker 的 env 里）
sudo tr '\0' '\n' < /proc/$(pgrep -f asr-worker | head -1)/environ | grep -E 'TENCENT|DASHSCOPE'
#    空 = 服务没拿到 → 变量写进 /etc/leion/secrets.env，然后 `sudo systemctl restart leion`
#    （只改文件不重启 = 一定不生效：环境变量是进程启动时读的）

# ② 文件本身对不对（第一行必须是 SecretId,SecretKey；BOM/CRLF 都行）
sudo head -2 /etc/leion/tencent.csv | cat -A

# ③ 只验"读得到、形状对"（不联网、不花额度）
sudo env TENCENT_ASR_SECRET_FILE=/etc/leion/tencent.csv /opt/leion/venv/bin/python -c \
  "import sys; sys.path.insert(0,'bridge'); import whisper_stream as w; \
   h=w.TencentEngine(None,None).load({}, 'cpu'); print('OK', h['secret_id'][:4], len(h['secret_key']), h['region'])"

# ④ 修好之后：失败段都留了证，可以挪回去重放
sudo ls /var/lib/leion/test/queue/asr/failed | head
```

> 队列里的段失败时**不会被删**（语音是用户的，删了就是无声丢失），一律挪进 `queue/asr/failed/`。
> 所以"切了策略之后一句字幕都没有"时，第一件该看的就是这个目录 —— 里面有段 = 加载/转写失败，
> 里面没段 = 问题在更上游（切句/转发）。

#### 错误码 → 下一步（日志里 `→ …` 那句话）

| 错误码 | 下一步 |
|---|---|
| `AuthFailure.UnauthorizedOperation` | CAM 授权 `QcloudASRFullAccess`（签名与参数都是对的，见上） |
| `FailedOperation.UserNotRegistered` | 控制台**开通**语音识别（与 CAM 授权是两件事） |
| `FailedOperation.UserHasNoAmount` / `…NoFreeAmount` | 资源包耗尽：购买或开后付费 |
| `FailedOperation.ServiceIsolate` | 欠费/被隔离：结清解冻 |
| `InvalidParameterValue.ErrorInvalidEngservice` | `model` 得是 `16k_*` / `8k_*` |
| `InvalidParameterValue.ErrorVoicedataTooLong` | 段超过 60 秒 |
| `AuthFailure.SignatureFailure` | 密钥形状（尾随换行）或系统时间偏差 > 5 分钟 |

不认识的错误码**不加解释**，原样把腾讯的 JSON 带出来（不把推断当事实写进日志）。

#### 怎么切到它（服务器上五步，按顺序做）

```bash
D=/var/lib/leion/test

# ① 密钥：只做一次。CSV 放 /etc/leion/（600），**在 secrets.env 里**指过去
#    （asr.env 是脚本生成的那份，别手改；见下面「密钥怎么给」）
sudo cp SecretKey.csv /etc/leion/tencent.csv && sudo chmod 600 /etc/leion/tencent.csv
printf 'TENCENT_ASR_SECRET_FILE=/etc/leion/tencent.csv\n' | sudo tee -a /etc/leion/secrets.env
sudo systemctl restart leion          # ⚠️ 改环境变量**必须重启**（进程启动时才读）

# ② 先确认这台机器真能调通（不改任何配置）
#    体检要 sudo：tencent.csv 是 600 归 root，你的 shell 自己读不了（服务是 root 跑的，所以它能读）
sudo env TENCENT_ASR_SECRET_FILE=/etc/leion/tencent.csv \
  node scripts/asr-doctor.mjs --data-dir $D | grep -A2 tencent

#    手上没有现成 wav 时：从**一场会的分轨音频**里切 6 秒出来试（管线的段本来就是 16k 单声道裸 PCM）。
#    ⚠️ 别指望 var/asr-eval/packs 一定在服务器上 —— 那是本机评测数据，服务器常常没有。
sudo env TENCENT_ASR_SECRET_FILE=/etc/leion/tencent.csv \
  node scripts/asr-try.mjs --data-dir $D \
       --pcm "$(ls $D/audio/*/*.pcm 2>/dev/null | head -1)" --rate 16000 --seconds 6 \
       --lang pt-BR --engine tencent --model 16k_pt     # 退出码 0 = 通了

# ③ 把策略写进**服务器那张表**（示例表里有 en-tencent；合并工具默认只加不覆盖）
node scripts/asr-models-merge.mjs --data-dir $D                          # 预览
node scripts/asr-models-merge.mjs --data-dir $D --only en-tencent --write

# ④ 切（**热生效**：不用重启，下一段音频就走腾讯）
node scripts/asr-model-switch.mjs --data-dir $D --lang en-US --strategy en-tencent

# ⑤ 确认（三条，缺一条都不算切好）
node scripts/asr-model-switch.mjs --data-dir $D        # 看 en-US：策略 en-tencent，引擎 tencent/16k_en
journalctl -u leion -n 60 --no-pager | grep -E 'tencent|16k_en'
#   期望每段一行：[识别] 房间 … 策略 en-tencent（模型 16k_en…）→ x.xs 出词 N
# 然后手机上说一句英语，看字幕。
```

回滚同样一条命令（也热生效）：`--lang en-US --strategy en-parakeet`；
删掉直接钉的模型：`--lang en-US --model ""`。

**切换前请对一下代价**（这些是"换成云端"本身的代价，不是 bug）：

| 项 | 说明 |
|---|---|
| 延迟 | 英语 5.9s 段 0.82s（RTF 0.14，含一次公网往返）；比本地 CPU 的 Parakeet 多一次网络 |
| 计费/配额 | 每段一次云端调用（30 次/秒上限）；**每句话都花钱** |
| 隐私 | 语音要出网到腾讯云；本地 whisper/parakeet 不出网 |
| 断网/欠费 | 该语种**直接没字幕**（云端引擎没有本地静音闸），片段会留证在 `queue/asr/failed/` |
| 上限 | 单段 ≤ 60s（切句默认 30s 以内，撞不到） |

**还没做的一件事**：英语 `16k_en` 与 Parakeet 的**同数据同口径**对比（本机没有英语测试包；
Parakeet 模型在服务器上）。要换之前，至少用**同一段英语音频**各跑一次
`asr-try --engine parakeet` / `--engine tencent --model 16k_en`，把两边的文字对照一下 ——
5.126 的 2.70% 是"朗读语料上能不能用"，不是"比 Parakeet 好"。

## 3. 怎么切（四种场景，按"影响范围从小到大"）

> 判定顺序（后面的覆盖前面的）：
> **命令行 → 表 `default` → `strategies[名字]` → `languages[语种]`**
> （⚠️ 5.108 起「房间侧车」那一层已整层删除：手机端的模型控制 5.69 就删了，侧车只可能带着
> 过期值却拥有最高优先级。现在**表是唯一的决定点**，`--room` 也随之取消。）
> 所以只改表不一定生效 —— 侧车压着它。切完用第 4 节的命令**验一遍**。

### 3.1 只改某一门语言的模型（最常见的"换个模型试试"）

```bash
# 换成表里已有的整套策略（引擎 + 模型 + 切句一起换）—— parakeet / tencent / funasr 只能这样切
node scripts/asr-model-switch.mjs --data-dir /var/lib/leion/test --lang pt-BR --strategy pt-funasr

# 只换 whisper 的尺寸名（引擎还是 whisper，切句不动）
node scripts/asr-model-switch.mjs --data-dir /var/lib/leion/test --lang zh-CN --model large-v3

# 还原成"跟策略表走"
node scripts/asr-model-switch.mjs --data-dir /var/lib/leion/test --lang pt-BR --model ""
```

- **不用重启**：识别侧按 mtime 热读表，下一段音频就生效。

### 3.3 调切句间隔与电平门槛（5.109：跟模型同一套机制）

这两件事原来一个写在表里（切句）、一个只能写命令行（电平），现在**都在表里**，
所以行为完全一致：**改完下一段生效、不用重启、可以按语种覆盖、`--clear-tuning` 一键还原。**

```bash
D=/var/lib/leion/test

# 切句间隔（说完多久算一句结束）：越小字幕越快、越容易切碎
node scripts/asr-model-switch.mjs --data-dir $D --lang pt-BR --silence-ms 650

# 一段话至少多少语音才交出去（太小会产碎片；觉得"被吃掉音节"时先看它）
node scripts/asr-model-switch.mjs --data-dir $D --lang pt-BR --min-speech-ms 300

# 两个电平门槛
node scripts/asr-model-switch.mjs --data-dir $D --lang pt-BR --skip-level 0.006   # 识别侧：解码前丢弃
node scripts/asr-model-switch.mjs --data-dir $D --lang pt-BR --rms-level 0.015    # 切句侧：算不算在说话

# 全撤掉（回到 default 层 / 命令行缺省）
node scripts/asr-model-switch.mjs --data-dir $D --lang pt-BR --clear-tuning

# 看现在到底是多少（切句六项 + 两个门槛，一次摊开）
node scripts/asr-model-switch.mjs --data-dir $D
```

三个门槛**不是一回事**，别混（都是"均方根电平 RMS"，0~1 的浮点，0.01 ≈ 满刻度的 1% ≈ −40 dBFS）：

| 字段 | 在哪一侧 | 缺省 | 判什么 | 调大 / 调小的后果 |
|---|---|---|---|---|
| `silence_skip_level` | **识别侧**（整段、解码前） | 0.02 | 这段音频值不值得送去识别 | 调大 → 更多段被直接丢（表现：一句字幕都没有）；调小 → 说话轻的人也能出字，但噪声可能变成幻听 |
| `rms_threshold` | 切句侧（固定门槛） | 0.01 | 100ms 这一块算不算"在说话" | ⚠️ **只在 `--no-adaptive` 时全程有效**；缺省自适应模式下只决定开头 2 秒 |
| `rms_floor` | 切句侧（自适应下限） | 0.004 | 同上，但这是自适应真正用的下限 | 实际门槛 = `max(rms_floor, 噪声底×4)`（还有安全阀：不超过"较响那一档"的 50%）。**要调切句灵敏度，动这个** |

> 一句话记法：**`--skip-level` 管"要不要送去识别"，`--rms-level` / `--rms-floor` 管"算不算在说话"。**
> 前者错了是"有字幕空白"，后者错了是"切不出句子 / 切得稀碎"。

- 两个都**只对 whisper 这条本地路生效**：云端引擎（Fun-ASR / 腾讯）没有本地静音闸，
  设了不会有效果（`asr-try` 会把值打印出来，但那个引擎不会用它）。
- 越界**直接报错**，不夹到边界：`0.2` 这种"多打一个 0"会把正常说话全丢掉，
  而 `silence_ms=5` 会把每块音频都切成一句。
- 手改表也一样（字段同名），两种方式等价。
- 切句参数改了会**重造切句器**；如果那一刻正在说话，会等这一句收尾后再换
  （不让同一句被两套阈值判两次）。

#### 症状 → 调哪个（照这张表，不要猜）

先分清**症状出在哪一层**（一句话就够，看日志怎么写的）：

| 日志里出现 | 说明问题在 |
|---|---|
| 完全没有任何段产出、也没有"丢弃"字样 | **切句侧**（门槛太高 / 不切句） |
| `[切句] ⚠️ 丢掉一段碎片：13.5s–13.7s（语音只有 200ms < min-speech 500ms）` | **切句侧**（`min_speech_ms`） |
| `[识别] … [丢弃 3.7s … 电平偏低（原始 0.0121，门槛 0.02）…]` | **识别侧**（`silence_skip_level`，**只有 whisper 有**） |
| `[识别] … [丢弃 3.7s … Fun-ASR 没出字]` | 引擎没认出东西（不是电平问题） |

| 症状 | 中文（whisper，本地） | 英文（Parakeet，本地 CPU） | 葡语（Fun-ASR，云端） |
|---|---|---|---|
| **① 说话被判成静音** | 切句侧先调小 **`rms_floor`**（0.004 → 0.002）；仍有 `电平偏低` 丢弃再调小 **`silence_skip_level`**（0.02 → 0.006~0.010） | **只能动切句侧 `rms_floor`**（Parakeet 没有本地静音闸） | **只能动切句侧 `rms_floor`**（云端没有本地静音闸） |
| **② 切句太碎**（一堆半句） | 调大 **`min_speech_ms`**（500 → 800~1000）丢掉短碎片；再调大 **`silence_ms`**（800 → 1000） | 同左 | 同左（云端尤其值得调：**碎段 = 多花钱多延迟**） |
| **③ 不切句**（一直不结束、字幕迟迟不来） | 先调大 **`rms_floor`**（0.004 → 0.008~0.012）；再调小 **`silence_ms`**（800 → 600）；兜底调小 **`max_speech_ms`**（30000 → 15000） | 同左 | 同左 |
| **④ 在说话中间切**（句中切断 / 句尾缺一截） | 若日志显示"到上限强切"→ 调大 **`max_speech_ms`** 并调大 **`cut_pause_ms`**（200 → 300~400）；若句尾音节被吞 → 调小 **`rms_floor`**（弱音节被判静音） | 同左 | 同左 |

> 为什么 ②③ 全是切句侧：**切句是纯 CPU 的能量判定，三语走的是同一段代码**（策略表里那份
> `segmentation`），引擎只影响"切出来之后怎么认"。所以这三个语种的差别只在于
> **①（静音丢弃）有没有识别侧那一道闸**：只有中文（whisper）有。
>
> ⚠️ 调 `min_speech_ms` 是**双刃剑**：调大能消碎片，但"太短的说话"会被整段丢掉
> （日志会明说"丢掉一段碎片"）。先看那句日志里丢的是 200ms 的碎片还是 800ms 的真话。

#### 先判断"碎"是**哪一种**碎（看日志，别猜）

| 日志里的指纹 | 它是怎么碎的 | 该动 |
|---|---|---|
| `尾部静音裁掉 1100ms`（约等于 `silence_ms`） | 确实靠静音收的句 | `silence_ms` / `short_utterance_ms` |
| `尾部静音裁掉 0ms` + `⚠️ 不是静音收的句` | **被 idle 截断**：手机这批音频之间停太久 | `--idle-flush-ms`（缺省 3000；这批日志的节奏建议 5000） |
| `能量门槛：… 已触发安全阀` / `门槛顶到安全阀` | 门槛 ≈ 说话电平（连续说话把"人声"估成了噪声底） | `noise_multiplier` 调小，或 `--no-adaptive --rms-threshold 0.03` |
| `丢掉一段碎片：语音只有 200ms < min-speech 500ms` | 短促的响声被丢（不是"碎"） | 想留住就调小 `min_speech_ms` |
#### 已验证的配方（2026-11-05 实机）：`--idle-flush-ms` 才是那次的主因

把 `silence_ms` 800→1100、`short_utterance_ms`→1200 之后仍碎；加上 `--idle-flush-ms 5000` 之后
**句子完整了**（实机日志：13.8s / 25.6s 的整段都切得出来，译文成了完整长句）。

| 步骤 | 命令 | 结果 |
|---|---|---|
| ① 抬 idle 阈值（主因） | `--idle-flush-ms 5000` | 碎句消失；`尾部静音裁掉 0ms` 的那种段不再出现 |
| ② 等更久再收句 | `--default --silence-ms 1100 --short-utterance-ms 1200` | 句子更长、更完整（代价：字幕晚 ~1 秒） |
| ③ 门槛顶安全阀时（噪声大/连续说话的房间） | `--no-adaptive --rms-threshold 0.03` | 门槛不再被人声撑高 |

> 三个都是**一台机器一次**的事，写在启动命令/表里即可，不需要改代码。

#### 反过来：句子**太长**（字幕迟迟不来）怎么调

整段很长时（实机见过 25.6s / 28.8s 的段 ⇒ 字幕要 30 秒以上才出现），该动的是
**`max_speech_ms`**（缺省 30000 → 12000~15000）：
到上限时它**不会硬切**，而是先在缓冲里找**内部停顿**再断（`cut_pause_ms`，缺省 200ms），
所以长段会被切在自然的停顿处。次要手段是把 `silence_ms` 调回 900~1000。
#### 现在就有一个具体的：**句子太碎**（half-sentence 一堆）

这是"切句太短"的典型，几乎是 `silence_ms` / `short_utterance_ms` 太小。**按顺序试**：

```bash

node scripts/asr-model-switch.mjs --data-dir $D --default --silence-ms 1100

# ② 还碎 → 提高"短句保护"的界限（还不到 1200ms 的片段，要等 1100ms 静音才收句）
node scripts/asr-model-switch.mjs --data-dir $D --default --short-utterance-ms 1200

# ③ 碎的全是几百毫秒的渣 → 直接把小于 700ms 的丢掉（日志会明说"丢掉一段碎片"）
node scripts/asr-model-switch.mjs --data-dir $D --default --min-speech-ms 700
```

- `--default` = 改**所有人的默认**（切句是同一段 CPU 代码，三门语言一起变）；
  想只调一门就把 `--default` 换成 `--lang pt-BR`。
- 代价必须一起看：`silence_ms` 800 → 1100 大约让字幕**晚 1 秒多**（`docs/06` §3.2 有实测对照：
  500/800/1200 分别是平局晚 2.7 / 3.8 / 6.2 秒）。
- **不要**靠调小 `min_speech_ms` 来"多出字幕"：小碎片只会产胡话（`docs/06` §6 的忠告）。
- 改完**下一段生效**；日志里会看到 `[切句] … 换策略 → …（切句 silence_ms=1100 …）`。
每个值都能按语种单独设，命令见上一节；改完**下一段生效**：

## 6. 常见坑（按踩过的次数排）

| 现象 | 真因 | 怎么办 |
|---|---|---|
| 改了表，行为没变 | 5.108 起已不可能（表是唯一决定点） | 确认代码是 5.108+；旧版本是侧车压着，升级后可 `rm -rf <data-dir>/asr-profiles` |
| 改了示例表，服务器没跟着变 | 合并工具默认**只加不覆盖** | 加 `--replace` |
| 换了 `default` 或 CLI 参数不生效 | 启动时加载的那份模型不会自己换 | 重启管线（`ctrl-c` 后重开） |
| 引擎名拼错 | 会**直接报错**并列已知引擎（不会静默退回 whisper） | 看报错里的清单 |
| parakeet/nemo 路线起不来 | 没装 `nemo_toolkit[asr]`/`torch` | 用 `en-parakeet`（ONNX/CPU）即可 |
| 云端连上但报参数错 | 端点不是公开域名，而是**账号专属** | 设 `DASHSCOPE_WS_URL` |
| `InvalidHeaderValue` | 密钥里混了换行（长 key 复制折行） | 重设单行密钥；`asr-doctor` 会提前告诉你 |
| 显存爆 / 突然变慢 | `--max-models` 太大或切了多个 GPU 模型 | `--max-models 2~3`；英语走 CPU 的 parakeet 更省 |
| 英语/葡语互译没选项 | 手机端的语言选项规则（5.106 已修） | 升级 APK |
