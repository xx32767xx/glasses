# 收音质量量化：把"眼镜收音效果好不好"变成一个数

> 工具：`asr-eval/mic_eval.py`（信号层 + 任务层指标，自带 `--selftest`）
> 前置事实：眼镜麦克风是 USB 音频输入设备、44.1 kHz / 单声道 / 16-bit（`docs/09` §12）

## 1. 先说清"评价收音效果"评的是什么

收音不是**一个**数字，而是三层：

| 层 | 问题 | 指标 | 需不需要参考文本 |
|---|---|---|---|
| **信号层** | 这段音频本身干不干净 | 信噪比、噪声底、削波率、有效带宽、工频哼声、块接缝咔哒 | 不需要 |
| **任务层** | 这条链路对识别有多友好 | 字错率（CER）、表内名字命中数 | 需要 |
| **链路层** | 采集→上传→落盘有没有丢/抖 | 块到达间隔抖动、丢块数、上传延迟 | 不需要 |

**只报信号层不够**（干净但不识别），**只报任务层也不够**（CER 差了不知道是麦克风还是模型）。
所以报告里必须三层都给，而且必须给**差值**：眼镜 vs 手机，同一内容、同一位置。

## 2. 录音矩阵（控制变量）

每次录音固定只变**一个**因素：

| 因素 | 取值 | 说明 |
|---|---|---|
| 音源 | **眼镜** / **手机** | 开发者·眼镜预览页的音源开关；两边必须各录一遍 |
| 距离 | 0.3 m / 1 m / 3 m | 眼镜戴在脸上（约 0.2 m），手机可能放桌上（1–3 m）——这是两者最大的差别来源 |
| 环境 | 安静 / 空调或风扇 / 有人说话的背景声 | 噪声是识别最怕的东西，必须分开测 |
| 重复 | 每种条件 ≥ 3 遍 | 单遍噪声太大 |

**每段录音的内容（固定，别换）**：

1. **3 秒静音**（不说话）—— 用来测噪声底；没有它 SNR 会虚高
2. **名字句**（C 组）：`亮亮眼镜这条产品线在圣保罗的团队，也在用骁龙 8 Gen 3 的方案。`
3. **普通陈述句**：`联合国还希望最终成立一项基金，帮助有关国家应对全球变暖的影响。`
4. **数字句**：`今年第三季度的出货量是一万两千台，比去年同期增长了百分之十八。`

## 3. 实验成立性检查（不做这步，实验可能是假的）

`docs/09` §12 已经踩过：**你以为在测眼镜，其实 SDK 悄悄退回了手机麦克风** —— 两者拿到的都是 PCM，代码上看不出来。所以每次录音前：

1. 打开诊断面板，确认显示 **`✓ 实际用的是眼镜（USB 音频设备）`**；
   显示 `✗ 实际用的是手机内置麦克风` 或 `? 设备未指定` 时，**这次录音作废**。
2. 确认只开了一路录音（同时开两路 → 音频混在一起，从留档里看不出来）。
3. 记录当时的采样率（`var/live/audio-in.rate`）：眼镜固定 44100，手机通常是 16000。
   **采样率不同会影响频响比较**（16k 的麦克风天生没有 4 kHz 以上能量），所以频响只在同采样率之间对比。

**顺序交替**：同一条件下按 `眼镜 → 手机 → 眼镜 → 手机 → 眼镜 → 手机` 录，抵消环境随时间漂移。

## 4. 一次录音怎么保存

转发进程把音频写到 `var/live/audio-in.pcm`（只追加）。**每录完一条，立刻复制成带条件的文件名**，
否则下一条会覆盖掉：

```powershell
# 录完"眼镜 / 安静 / 1m / 第 0 遍"之后
Copy-Item var/live/audio-in.pcm var/asr-eval/mic/glasses-quiet-1m-0.pcm -Force
Copy-Item var/live/audio-in.rate var/asr-eval/mic/glasses-quiet-1m-0.rate -Force
```

命名约定：`{音源}-{环境}-{距离}-{第几遍}.pcm`，音源取 `glasses` / `phone`，环境取 `quiet` / `ac` / `babble`。

## 6. 报告表格模板（给老师看的版本）

| 条件 | 音源 | 信噪比 dB | 噪声底 RMS | >4k 能量占比 | 削波 % | 咔哒率 | CER | 名字命中 |
|---|---|---|---|---|---|---|---|---|
| 安静 1m | 眼镜 | | | | | | | /7 |
| 安静 1m | 手机 | | | | | | | /7 |
| 空调 1m | 眼镜 | | | | | | | /7 |
| 空调 1m | 手机 | | | | | | | /7 |
| 安静 3m | 眼镜 | | | | | | | /7 |
| 安静 3m | 手机 | | | | | | | /7 |

**结论只写差值**（例如"眼镜比手机信噪比高 X dB、CER 低 Y 个百分点"），
不写绝对值承诺 —— 绝对值依赖房间、说话人、距离，换场景就变。

## 7. 指标的诚实边界（写报告时必须带上）

- **噪声底靠"录音里确实有静音"**：没有静音段，10 百分位会取到轻声说话，SNR 虚高。
- **频响是相对形状**，不是绝对声压级；麦克风灵敏度要校准信号才能当绝对值用。
- **SNR 用分位数近似**（语音档 90 百分位 / 噪声底 10 百分位），不是逐帧对齐的真实信噪比；
  它能反映"这条链路的动态范围"，不能当声学实验室的 SNRD。
- **CER 只反映"对识别有多友好"**，模型也是变量之一。换模型这条数会变，所以对比必须同模型。
- **顺序录音不是同时录音**：环境可能漂移。要用最强证据，需要另一台设备同时录一路作参考。
- 目前**没有任何真机录音**：`docs/06` §5 里写明"真机麦克风没有硬件，这套门槛肯定要重调"。
  跑完这一轮，才有第一组真机数字。

## 8. 最低成本起步版（30 分钟能出结论）

不必一次跑满矩阵。先做这一格，就能回答"眼镜比手机好还是差"：

1. 安静房间、距离 1 m、**同一段名字句**；
2. `眼镜 → 手机 → 眼镜 → 手机 → 眼镜 → 手机` 交替录 3 遍；
3. 每遍前确认诊断面板是 `✓ 实际用的是眼镜`（手机那几遍切开关后再确认一次）；
4. 跑 §5 的命令，把 6 份录音两两配对，看差值的**方向是否稳定**（3 遍都同向才算成立）。

> 若 3 遍都不稳定，说明噪声大于差异 —— 那就把重复加到 6 遍，或先解决"环境不够安静"再测。
