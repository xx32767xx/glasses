# 识别评测：测试包、评分规则、固定语言基准

> **给谁看**：做识别优化的人；以及要判断"这个数字可不可信"的人。
> **这份文档对应老师那份测试建议的 §二 / §三 / §四**（冻结测试包 → 统一评分规则 → 固定语言基准）。
> §五（连续录音的实时损失）、§七（双语自动选择）还没做，见文末。

---

## 0. 一句话

**在源语言已知、音频边界已给定时，识别到底什么水平 —— 现在有一个可复现、可审计、
带版本号的口径来回答了。** 而"实时切句损失多少""语种选择错多少"要等下一阶段。

---

## 1. 为什么先做"冻结测试包 + 评分规则"

老师的 §三 是整件事的地基，我完全同意，理由是：

> **没有冻结的切分与评分规则，后面每个数字都说不清是"模型变好了"还是"换了一批样本 / 换了口径"。**

这条不是理论。我们**已经踩过一次同类**：`docs/04` 里那批数字（FLEURS 朗读 3.9%、CORAA 口语 13.3%）
当初是拿"前 30 条 / 前 20 条"跑的，而且那 30 条后来还被反复看过 ——
按老师的说法，它们只能算**历史回归集**，不能再当"未见测试集"。

## 2. 测试包（`python bridge/asr_pack.py`）

```powershell
python bridge/asr_pack.py --list      # 看能切什么、本地各有多少
python bridge/asr_pack.py --build all # 切包
python bridge/asr_pack.py --verify    # 查切分卫生（可反复查，不是看一眼就算）
python bridge/asr_pack.py --keys      # 生成关键内容候选，供人工确认
```

| 包 | 条数 | 总时长 | 说话人 | 语料 |
|---|---|---|---|---|
| `zh-read-dev` | 100 | 1169 s | — | FLEURS cmn_hans_cn（朗读） |
| `zh-read-holdout` | 227 | 2494 s | — | 同上 |
| `pt-read-dev` | 100 | 1187 s | — | FLEURS pt_br（朗读） |
| `pt-read-holdout` | 217 | 2662 s | — | 同上 |
| `pt-speech-dev` | 300 | 1015 s | 300 | CORAA（真实口语） |
| `pt-speech-holdout` | 500 | 1394 s | 500 | 同上 |

切出来的东西在 `var/audio/<包名>/`（在 `.gitignore` 里），**一条 `--build all` 可重建**。

### 三条切分纪律（每条都有原因）

| 纪律 | 为什么 |
|---|---|
| **确定性**：按 `original_id` 排序 + 固定种子打散 | 不依赖 parquet 行序。换台机器、换次运行必须切出同一份 —— 否则"对比"没有意义 |
| **与历史回归集不相交**：按 id / 文件名 / **参考文本** 三重排除 | 老 manifest **没记 original_id**，只按 id 比对会漏，那 30 条会重新混进"新"保留集 |
| **按说话人整组切** | 老师的原话："不能把同一段录音随机切开分到两组"。CORAA 的文件名编号是受访者，同一个人不跨包 |

### ⚠️ 两个必须知道的限制

1. **本地只有 CORAA 的 test 分片**（2113 条音频；dev 的元数据有、音频没有）。
   所以巴葡口语的 dev 是从 **test** 里切出来的，**不是官方 dev**。
   dev 与保留集之间按说话人编号做了不相交，但仍在同一批采集条件下 ——
   结论强度不如"官方 dev 调参 + 官方 test 验收"。这一点写在每个包的 `pack.json` 里。
2. **FLEURS 的 `id` 不是每条唯一**（409 行只有 150 个唯一 id）—— 它是**句子**编号，
   同一句由 2~3 个说话人各录一遍。所以：
   - `original_id` 必须带行号才唯一；
   - 排除历史回归集时按文本比对会**连带排掉同句的其它录音**（30 条排掉 82 行），
     这是正常的，也是保留集凑不满 300 条的原因之一。

> **顺带一个有用的发现**：**中文与巴葡按 id 对齐**（实测 147 个共同 id，
> `zh 1510` 与 `pt 1510` 是同一句话的两种语言录音）。
> 这正好是老师 §七 要的"构造切换测试"的材料 —— 交替回放同一句的中/葡版本，
> 可以验证语言路由与状态切换，且**不依赖任何自录数据**。

## 3. 每条样本存什么（老师的 §三）

`manifest.jsonl` 一行一条，字段：

| 分类 | 字段 |
|---|---|
| 样本身份 | `file` `dataset` `dataset_version` `split` `original_id` |
| 音频 | `seconds` `rate` `channels` |
| 会话信息 | `session` `speaker`（FLEURS 无说话人标注 → 如实为 `null`，不假装有） |
| 正确答案 | `reference`（原始转写）`reference_char_spaced`（逐字转写，FLEURS 有） |
| 分组标签 | `tags.register`（朗读/口语）`tags.accent` `tags.speech_style` `tags.noise_votes` `tags.overlap_votes` … |
| 关键内容 | `key_terms`（**人工确认过**才填；脚本只提候选，见 `--keys`） |

## 4. 评分规则（`bridge/asr_score.py`，版本 `asr-score-v1`）

老师要求"冻结规范 + 绑定版本号"。规则写在一处、带版本、可被逐条测试。

### 4.1 单位与主指标

| 语言 | 单位 | 主指标 |
|---|---|---|
| 中文 | **字** | CER |
| 巴葡 | **词** | WER |

**整体错误率 = 全部编辑错误数 ÷ 全部参考单位数**，中文与葡语分别报。
**不用"每句百分比的平均"** —— 短句权重过大（一个字错就是 100%）。

### 4.2 归一化（v1 **刻意与旧实现逐字一致**）

| 项 | 处理 |
|---|---|
| 大小写 / 弯引号 | 统一小写；`’` → `'` |
| 中文按字 | `re.sub(r"[^\w]", "", text)` —— 标点**与空白**一起去掉 |
| 葡语按词 | `re.sub(r"[^\w\s']", " ", text)` 再合并空白（标点是换成空格，不是删） |
| **重音符号** | **保留**（`é` ≠ `e`，那是有意义的） |
| **繁简** | **不转换**。繁体按错字计入（base/tiny 会把简体输出成繁体，那是真实缺陷，不该被洗掉）；同时单列"疑似繁体字数" |
| **数字** | **不做等价归一**（见 4.4） |
| 语气词 / 重复 / 改口 | **计入**（按原始转写）—— 主指标是**严格转写**口径 |

> ⚠️ **为什么 v1 是"照抄旧实现"而不是顺手改好**：旧实现产出的那批数字
> （FLEURS 3.9%、CORAA 12.2% / 13.3%）是现在所有结论的基线。
> 我第一版写了 NFKC 归一 + 保留空白 —— 那会**悄悄改掉历史数字**，
> 于是"改进了没有"再也说不清。想改归一化就开 v2、把所有历史集重跑一遍。
> **这正是"评分规则冻结 + 绑版本号"的实际含义。**
> 现在有一条测试把 v1 与旧实现逐字对比，防止将来"顺手改好"。

### 4.3 替换 / 删除 / 插入（老师的 §八）

每条样本都存 `substitutions` / `deletions` / `insertions` 与总编辑距离，汇总也分开报。
**删除（漏字/漏词）单独盯着**：同传里漏掉的内容比译错更严重 —— 听的人不知道自己漏了。

### 4.4 关键内容专项（老师要求"不能只依赖整体 CER/WER"）

- `key_terms` **必须人工确认**，脚本只提候选（`--keys` 提出数字与拉丁字母词两类客观可判的；
  **中文人名机构名故意不提** —— 没有可靠启发式，硬提会把清单淹掉）。
- 判据：关键项归一化后在归一化后的识别输出里出现即算命中。
  **听错的数字不会被洗成正确**（`802` 听成 `800` → 未命中，有测试钉着）。
- 清单为空时报告里**明确写"这一项不可用"**，不假装有分。

### 4.5 失败样本不许静默排除（老师的 §四）

每条的加载与推理都单独兜住，失败记进 `failures` 并在报告开头显式列出
（含分母是多少）。**静默排除会让"只测了 460/500 条"看起来像"全测完了"**，
而失败的那些往往是坏文件/异常音频，恰恰最该被看见。

### 4.6 运行可追溯（老师的 §六）

每次运行的 JSON 里带 `provenance`：git 提交号、评分规则版本、模型、设备、精度、
beam、语种与候选集、提示词、是否峰值归一化、数据目录、**manifest 的 sha256 前 16 位**、样本数。

## 5. 固定语言基准（老师的 §四）

```powershell
node scripts/test-asr.mjs --set pt-speech-dev --model large-v3 --language pt --count 0
```

> ⚠️ `test-asr.mjs` 的 `--count` **缺省是 30**（不传就只跑前 30 条）。
> 跑全量必须显式 `--count 0`（0 = 不截断）。第一版我漏了这个，于是"全量基准"其实只跑了 30 条。

**按数据集原有片段送 ASR，不经过生产 VAD** —— 这样先回答一个问题：
> 在源语言已知、音频边界已提供时，识别模型能达到什么水平？

### 5.1 ZH-BASE / PT-BASE 实测（large-v3 / CUDA / float16，固定语种，全量）

| 测试包 | 条数 | 整体错误率 | 替换 | 删除 | 插入 | 好的句子 | RTF |
|---|---|---|---|---|---|---|---|
| `zh-read-dev` | 100 | **12.3%** | 3.7% | **8.2%** | 0.4% | 76/100 | 0.114 |
| `zh-read-holdout` | 227 | **5.4%** | 2.5% | 2.5% | 0.4% | 182/227 | 0.124 |
| `pt-read-dev` | 100 | **2.8%** | 2.1% | 0.3% | 0.4% | 90/100 | 0.100 |
| `pt-read-holdout` | 217 | **3.8%** | 3.1% | 0.4% | 0.3% | 198/217 | 0.090 |
| `pt-speech-dev` | 300 | **16.8%** | 7.1% | 8.1% | 1.7% | 142/300 | 0.192 |
| `pt-speech-holdout` | 500 | **17.6%** | 7.2% | 7.9% | 2.5% | 223/500 | 0.243 |

语种判定：**全部 100% 正确**（固定语种，共 1444 条）。

### 5.2 三件从这批数字里读出来的事

**① 巴葡：口语比朗读差 5~6 倍。** `pt-read` 2.8~3.8% → `pt-speech` 16.8~17.6%。
而且 dev 与 holdout **互相印证**（16.8% vs 17.6%），说明这不是抽样噪声。
**这是目前最大的一个数** —— 它说明"朗读语料上的数字"完全不能代表产品表现。

**② 中文的错法主要是"漏字"，葡语主要是"换字"。**

| | 删除占比 |
|---|---|
| 中文 | **2.5%~8.2%**（占了总错误的一半以上） |
| 巴葡朗读 | 0.3%~0.4% |
| 巴葡口语 | 7.9%~8.1% |

中文 CER 里"删除"压倒性 —— 也就是**识别整段整段地少给字**。这类错在同传里最危险：
听的人不知道自己漏了。**报告必须把删除单独列出来**（老师 §八 要 S/D/I 就是这个原因）。

**③ ⚠️ 中文 dev(12.3%) 与 holdout(5.4%) 差 2.3 倍 —— 查下来主要是"计分假象"。**

按句错误率分布：dev 的 P50 只有 **2.0%**、P90 却是 **33.3%** —— 不是整体偏移，
是**少数灾难样本**拖的（最差 5 条贡献了 dev 全部错误的 **42%**；holdout 里同样的 5 条只占 18%）。

看那些灾难样本，原因是**参考文本的写法约定**：

```
参考  108 碟珍馐奉纳（Chhappan Bhog）… 指供奉神灵的56 种…
识别  一百零八碟真修凤纳 在印度教中 只供奉神灵的五十六种…
参考  克鲁格国家公园 (KNP) 位于南非东北部…
识别  克鲁格国家公园位于南非东北部…
```

参考里混着**阿拉伯数字**与**外文括号注记**，而朗读音频里这些注记往往**没有被念出来**，
Whisper 自然不会输出 —— 在 v1 的严格口径下这些全算**删除**。

**归因（同一批样本，只在评分前做不同处理）**：

| 处理 | zh-read-dev | zh-read-holdout | pt-read-dev |
|---|---|---|---|
| v1（现行） | 12.3% | 5.4% | 2.8% |
| 只做数字写法归一 | 11.8% | 5.3% | 2.8% |
| 只去掉括号注记 | **9.0%** | 5.0% | **3.4%**（反而变差） |
| 两者都做 | 8.6% | 4.9% | 3.4% |

**结论有两层，第二层更重要：**
1. 中文 dev 的 12.3% 里有 **约 3.3 个百分点（27%）来自"参考的注记约定"**，不是识别错。
2. **但不能用一个通用规则去掉它** —— 同一条规则在葡语上让指标**变差**（2.8% → 3.4%），
   说明"括号里的内容念没念"**因语料而异**。所以这正是老师 §三 要的两件事：
   **① 原始转写与评分用转写分开存；② 评分规范要冻结、并且能人工核对。**

> ⚠️ 所以 **v1 保持不动**：改口径必须开 v2 并把所有历史集重跑一遍。
> 而"评分用转写"该怎么定，需要**对着音频确认**那些注记到底念没念 ——
> 这件事我在这里只能提出证据，不能替它拍板。

### 5.3 三个分开报的耗时（老师的 §八 要求分开）

| 指标 | 含义 | 本轮实测 |
|---|---|---|
| 单条识别耗时 P50 / P95 | 从 ASR 调用开始计时 | 朗读 P50 1.08~1.33s；口语 P50 0.62~0.63s |
| 识别总耗时 / RTF | 整批合计 | 朗读 RTF 0.09~0.12；口语 **0.19~0.24** |
| 模型加载与预热 | 单独报，不混进上面 | 每次运行约 11~15s（未计入上面） |

> **口语的 RTF 反而更高（0.24 vs 0.09）**：口语片段更短（中位 2.5~3.0s vs 朗读 10~12s），
> 而每段的固定开销摊不掉。**这对同传是坏消息** —— 我们的生产链路正好是短片段。
>
> **"稳定提交延迟"（从发言结束到最终文字提交）属于实时链路，本阶段不测** ——
> 要靠 §五 的连续回放模式才能量。
