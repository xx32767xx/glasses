# 识别评测规程：怎么切测试集、怎么跑、按什么标准评分

> **给谁看**：做识别优化的人；以及要判断"这个数字可不可信"的人。
> **对应老师那份测试建议的 §二 / §三 / §四**（冻结测试包 → 统一评分规则 → 固定语言基准）。
> §五（连续录音的实时损失）、§七（双语自动选择）还没做，见 §8。

---

## 1. 为什么先冻结测试集与评分标准

老师把"先冻结一套起步测试包 + 统一数据和评分规则"放在最前面当地基，我完全同意，理由是一条已经吃过的教训：

> **没有冻结的切分与评分规则，后面每个数字都说不清是"模型变好了"还是"换了一批样本 / 换了口径"。**

`docs/04` 里那批数字（FLEURS 朗读 3.9%、CORAA 口语 13.3%）当初是拿"前 30 条 / 前 20 条"跑的，
而且那 30 条后来被反复看过 —— 按老师的说法，它们只能算**历史回归集**，不能再当"未见测试集"。

## 2. 怎么切测试集

### 2.1 四个命令

```powershell
python bridge/asr_pack.py --list       # 看能切哪些包、本地各有多少条（不写盘）
python bridge/asr_pack.py --build all  # 切出全部包
python bridge/asr_pack.py --verify     # 查切分卫生（可反复跑）
python bridge/asr_pack.py --keys       # 生成关键内容候选，供人工确认
```

切出来的包：

| 包 | 条数 | 总时长 | 说话人 | 语料 |
|---|---|---|---|---|
| `zh-read-dev` | 100 | 1169 s | — | FLEURS cmn_hans_cn（朗读） |
| `zh-read-holdout` | 227 | 2494 s | — | 同上 |
| `pt-read-dev` | 100 | 1187 s | — | FLEURS pt_br（朗读） |
| `pt-read-holdout` | 217 | 2662 s | — | 同上 |
| `pt-speech-dev` | 300 | 1015 s | 300 | CORAA（真实口语） |
| `pt-speech-holdout` | 500 | 1394 s | 500 | 同上 |

### 2.2 命名规范（`<语种>-<语体>-<用途>`）

三段都是**封闭取值**，不是随手起的：

| 段 | 取值 | 含义 |
|---|---|---|
| 语种 | `zh` / `pt` | 中文 / 巴葡 |
| 语体 | `read` / `speech` | 朗读 / 真实口语（自发说话） |
| 用途 | `dev` / `holdout` | 开发集（可反复调参）/ 保留集（**只在最后用一次**） |

**为什么语体必须进名字**：它决定这批数字能不能代表产品 —— 实测 `read` 与 `speech`
差 **5~6 倍**（2.8% vs 16.8%，见 §6.1）。混在一起报就失去意义。

### 2.3 落盘位置

```
var/audio/<包名>/                     ← 一个包一个目录（var/ 在 .gitignore，不进仓库）
├─ manifest.jsonl                     每条样本一行，字段见 §3
├─ pack.json                          这一包**怎么切出来的**：数据集·版本·种子·条数·
│                                     总时长·说话人数·切分规则·已知限制（审计用）
├─ key-candidates.jsonl               关键内容候选（`--keys` 生成，待人工确认）
└─ <包名>-0000.wav …                  音频（16 kHz 单声道，与 Whisper 要的格式一致）
```

### 2.4 三条切分纪律（每条都有原因）

| 纪律 | 为什么 |
|---|---|
| **确定性**：按 `original_id` 排序 + 固定种子打散 | 种子由 `base:source:split` 派生，**不依赖 parquet 行序**。换台机器、换次运行必须切出同一份，否则"对比"没有意义 —— 也正因为如此，`var/` 删了可以一条命令重建 |
| **与历史回归集不相交**：按 `original_id` / 文件名 / **参考文本** 三重排除 | 老评测集的 manifest **没记 `original_id`**，只按 id 比对会漏 —— 那 30 条会重新混进"新"保留集，而老师明确要求它们留作历史回归集 |
| **按说话人整组切** | 老师的原话："不能把**同一段录音**随机切开分到两组"。CORAA 文件名里的编号是受访者编号，同一个人必须整组落在同一侧 |

`--verify` 会把这三条都查一遍并打印结论，**不是"我看一眼就算"**。它同时报一个**软提示**：

> **"参考文本重复"不是失败。** 老师警告的是"同一段**录音**被切开分到两组"（样本泄漏）；
> 而文本相同、录音不同（同一句话由不同说话人各录一遍）是**两个独立样本**，对识别评测不构成泄漏。
> 但它确实削弱了"文本从未见过"这个说法，所以如实报出来，由读的人决定要不要介意。

### 2.5 两个必须知道的限制

1. **本地只有 CORAA 的 test 分片**（2113 条音频；dev 的元数据有、音频没有）。
   所以巴葡口语的 dev 是从 **test** 里切出来的，**不是官方 dev**。
   dev 与保留集之间按说话人编号做了不相交，但仍在同一批采集条件下 ——
   结论强度不如"官方 dev 调参 + 官方 test 验收"。这一点写在每个包的 `pack.json` 里。
2. **FLEURS 的 `id` 不是每条唯一**（409 行只有 150 个唯一 id）—— 它是**句子**编号，
   同一句由 2~3 个说话人各录一遍。所以：
   - `original_id` 必须带行号才唯一；
   - 排除历史回归集时按文本比对会**连带排掉同句的其它录音**（30 条排掉 82 行），
     这是正常的，也是保留集凑不满 300 条的原因之一。

> **顺带一个有用的发现**：**中文与巴葡按 id 对齐**（实测 147 个共同 id，
> `zh 1510` 与 `pt 1510` 是同一句话的两种语言录音）。
> 这正好是老师 §七 要的"构造切换测试"的材料 —— 交替回放同一句的中/葡版本，
> 可以验证语言路由与状态切换，且**不依赖任何自录数据**。

### 2.6 还缺哪一格

| 组合 | 状态 | 语料 |
|---|---|---|
| 中文朗读 | ✅ 已切 | FLEURS `cmn_hans_cn` |
| **中文口语** | ❌ **没有数据** | MagicData-RAMC（需下载） |
| 葡语朗读 | ✅ 已切 | FLEURS `pt_br` |
| 葡语口语 | ✅ 已切 | CORAA |

**四格里实到三格。** RAMC 到位后，在 `asr_pack.py` 的 `PACKS` 里加一条、跑 `--build` 即可。

## 3. 每条样本存什么（老师的 §三）

`manifest.jsonl` 一行一条，字段：

| 分类 | 字段 |
|---|---|
| 样本身份 | `file` `dataset` `dataset_version` `split` `original_id` |
| 音频 | `seconds` `rate` `channels` |
| 会话信息 | `session` `speaker`（FLEURS 无说话人标注 → 如实为 `null`，不假装有） |
| 正确答案 | `reference`（原始转写）`reference_char_spaced`（逐字转写，FLEURS 有） |
| 分组标签 | `tags.register`（朗读/口语）`tags.accent` `tags.speech_style` `tags.noise_votes` `tags.overlap_votes` … |
| 关键内容 | `key_terms`（**人工确认过**才填；脚本只提候选，见 `--keys`） |

## 4. 评分标准（`bridge/asr_score.py`，版本 `asr-score-v1`）

老师要求"把评分规范冻结并绑定版本号"。下面**只是评分标准本身** ——
运行时的纪律（失败样本、可追溯）在 §5。

### 4.1 单位与主指标

| 语言 | 单位 | 主指标 |
|---|---|---|
| 中文 | **字** | CER |
| 巴葡 | **词** | WER |

**整体错误率 = 全部编辑错误数 ÷ 全部参考单位数**，中文与葡语**分别报**。

**不用"每句百分比的平均"** —— 短句权重过大（两个字的一句话，错一个字就是 50%）。
"每句平均"仍然会打印出来，但标明**仅供参考**。

### 4.2 归一化规则（比较前做什么、不做什么）

| 项 | 处理 | 为什么 |
|---|---|---|
| 大小写 | 统一小写 | |
| 弯引号 | `’` → `'` | |
| **中文按字** | `re.sub(r"[^\w]", "", text)` —— 标点**与空白一起去掉** | 中文里空白不是语义；FLEURS 的逐字转写字段是空格分隔的，不去掉会算错字数 |
| **葡语按词** | `re.sub(r"[^\w\s']", " ", text)` 再合并空白 | 标点是**换成空格**而不是删，否则 `hello,world` 会被粘成一个词 |
| **重音符号** | **保留**（`é` ≠ `e`） | 葡语里重音是有意义的 |
| **繁简** | **不转换**，繁体按错字计入 | base/tiny 会把简体输出成繁体，那是**真实缺陷**，不该被"转换后不算错"洗掉；同时单列"疑似繁体字数"（见 4.5） |
| **数字** | **不做等价归一** | 见 4.6 的说明（这是**待定的 v2 议题**：实测发现参考的阿拉伯数字与识别输出的中文读法会被算成删除，虚增指标 —— 详见 §6.3） |
| 语气词 / 重复 / 改口 | **计入**（按原始转写） | 主指标是**严格转写**口径 |

> ⚠️ **v1 是"照抄既有实现"，不是顺手改好** —— 旧实现产出的那批数字是所有结论的基线。
> 我第一版写了 NFKC 归一 + 中文保留空白，那会**悄悄改掉历史数字**，于是"改进了没有"再也说不清。
> 想改归一化就开 **v2**、把所有历史集重跑一遍。现在有一条测试把 v1 与旧实现**逐字对比**，
> 防止将来有人"顺手改好"。

### 4.3 替换 / 删除 / 插入（老师的 §八）

每条样本都存 `substitutions` / `deletions` / `insertions` 与总编辑距离，汇总也分开报。
定义**相对参考文本**：

| 指标 | 定义 | 通俗说法 |
|---|---|---|
| **替换** | 参考里有一个单位，识别里换成了别的 | 写错了 |
| **删除** | 参考里有，识别里没有 | **漏字 / 漏词** |
| **插入** | 识别里多出来的（参考里没有） | 多字 / 重复 |

三者之和 = 总编辑距离；所以 S、D、I 的百分比相加 = 整体错误率。

**为什么要拆开**：三类严重程度差得很远。**删除最危险** —— 听的人不知道自己漏了，
还以为听到了全部。实测中文的删除占总错误一半以上（整段整段少给字），
而葡语朗读的删除只占约 10%（主要是写错）。

### 4.4 关键内容专项（老师要求"不能只依赖整体 CER/WER"）

- `key_terms` **必须人工确认**，脚本只提候选：`--keys` 只提**客观可判**的两类
  （数字、拉丁字母词）；**中文人名机构名故意不提** —— 没有可靠启发式，硬提会把清单淹掉。
- 判据：关键项归一化后，在归一化后的识别输出里出现即算命中。
  **听错的数字不会被洗成正确**（`802` 听成 `800` → 未命中，有测试钉着）。
- 清单为空时报告里**明确写"这一项不可用"**，不假装有分。

### 4.5 单列项：疑似繁体字数

只统计"简体句里不该出现的繁体专用字"（87 字的表，**照抄既有实现** —— 换表等于换口径）。
指标名带"疑似"是因为这张表不完备，只覆盖口语里最常出现的一批。

### 4.6 明确**不做**的

| 不做 | 为什么 |
|---|---|
| **数字等价归一** | 老师指出"数字等价表达可以规范化，但**不能把听错的金额、否定词或名称洗成正确**"。而实测发现参考里的阿拉伯数字与识别输出的中文读法写法不同会**虚增**指标（见 §6.3），所以这是个**待定的 v2 议题**，不能在 v1 里悄悄改 |
| 繁简转换 | 同上：转换会把真实缺陷洗掉 |
| 语义判断 | 它只回答"识别出来的字/词与参考差在哪"，不判"意思对不对" |

## 5. 怎么跑测试

### 5.1 固定语言基准（老师的 §四）

```powershell
# 中文朗读（固定语种 zh）
node scripts/test-asr.mjs --set zh-read-holdout --model large-v3 --language zh --count 0

# 巴葡口语（固定语种 pt）
node scripts/test-asr.mjs --set pt-speech-dev --model large-v3 --language pt --count 0
```

> ⚠️ **`--count` 缺省是 30**（不传就只跑前 30 条）。跑全量必须显式 **`--count 0`**（0 = 不截断）。
> 第一版我漏了这个，于是"全量基准"其实只跑了 30 条 —— 数字看着正常，但根本不是全量。

也可以直接调评测脚本（参数更多，`--vad-filter`、`--initial-prompt` 等）：

```powershell
python bridge/asr_eval.py --set var/audio/pt-speech-dev `
  --model large-v3 --device cuda --compute-type float16 `
  --language pt --count 0 --show 3 `
  --out-json var/logs/asr-eval/我的结果.json
```

### 5.2 这一批属于哪种模式（**别误读**）

老师 §五 把连续录音分成三种模式。**现在这批不是"当前实时"**：

| 模式 | 做法 | 跑了吗 |
|---|---|---|
| **A 离线参考** | 用**人工标注的完整发言边界**，允许看到完整发言 | ✅ **本批是这一半** |
| **B 当前实时** | 按 1 倍速喂进**当前生产 VAD + 切句 + 识别**链路 | ❌ 没跑 |
| **C 候选策略** | 同上，只改一个处理因素 | ❌ 没跑 |

**本批的具体做法**：音频边界取自**语料官方的切分**（FLEURS 一句一条、CORAA 一段一条），
**不经过我们的生产 VAD**；每条**独立识别**、离线批量、**不是 1 倍速输入**；
没有生产链路里的切句错位、丢块、幻听闸误丢、增量提交。

> 这正是老师 §四 规定的那一步 ——「先按数据集原有片段送入 ASR，**不通过生产 VAD 重新切分**。
> 这样先回答：在源语言已知、音频边界已提供时，识别模型能达到什么水平？」

**所以这批数字是实时链路的「上界」，真实表现只会更差，不会更好。**
差多少要靠 §五 的 A/B/C 对照来量（还没做）。

### 5.3 运行纪律（三条，都不是可选项）

**① 失败样本不许静默排除。** 每条的加载与推理都单独兜住，失败记进 `failures`
并在报告开头显式列出（含分母是多少）。**静默排除会让"只测了 460/500 条"看起来像"全测完了"**，
而失败的那些往往是坏文件/异常音频，恰恰最该被看见。

**② 三类耗时分开报**（老师的 §八 要求分开，混在一起会误判）：

| 指标 | 含义 |
|---|---|
| **单条识别耗时 P50 / P95** | 从 ASR 调用开始计时。**P95 比平均重要** —— 同传怕的是尾巴 |
| **识别总耗时 / RTF** | 整批合计（RTF = 识别总耗时 ÷ 音频总时长，越小越好） |
| **模型加载与预热** | 单独报，不混进上面（CUDA 上每次约 11~15s） |

**③ 每次运行绑定可追溯信息。** 结果 JSON 里带 `provenance`：git 提交号、评分规则版本、
模型、设备、精度、beam、语种与候选集、提示词、是否峰值归一化、是否内置 VAD、
数据目录、**manifest 的 sha256 前 16 位**、样本数。
理由：报告一旦离开现场，"这个 12.2% 是哪一版代码、哪个模型、哪批数据算的"就没人说得清。

### 5.4 结果落在哪

```
var/logs/asr-eval/<包名>__<模型>_<设备>_<精度>.json
   例：pt-speech-holdout__large-v3_cuda_float16.json
```

文件名由 `scripts/test-asr.mjs` 的 `resultPath()` 拼出（包名 + 双下划线 + 模型/设备/精度）。
逐条都存了参考原文、识别原文、S/D/I、耗时、分组标签，以及那次运行的 `provenance`。

## 6. 实测结果

### 6.1 ZH-BASE / PT-BASE（large-v3 / CUDA / float16，固定语种，全量）

| 测试包 | 条数 | 整体错误率 | 替换 | 删除 | 插入 | 好的句子 | RTF |
|---|---|---|---|---|---|---|---|
| `zh-read-dev` | 100 | **12.3%** | 3.7% | **8.2%** | 0.4% | 76/100 | 0.114 |
| `zh-read-holdout` | 227 | **5.4%** | 2.5% | 2.5% | 0.4% | 182/227 | 0.124 |
| `pt-read-dev` | 100 | **2.8%** | 2.1% | 0.3% | 0.4% | 90/100 | 0.100 |
| `pt-read-holdout` | 217 | **3.8%** | 3.1% | 0.4% | 0.3% | 198/217 | 0.090 |
| `pt-speech-dev` | 300 | **16.8%** | 7.1% | 8.1% | 1.7% | 142/300 | 0.192 |
| `pt-speech-holdout` | 500 | **17.6%** | 7.2% | 7.9% | 2.5% | 223/500 | 0.243 |

语种判定：**全部 100% 正确**（固定语种，共 1444 条）。

**"好的句子"的判据是"该句自身错误率 ≤ 10%"** —— 这个 10% 是**我们定的**，老师没规定。
短句特别容易踩到它（两个字的一句话错一个字就是 50%），所以它只作参考，不当验收线。
**"好的句子"回答的是"有多少句基本能用"**，因为整体错误率是平均数、会被长句支配。

### 6.2 三件从这批数字里读出来的事

**① 巴葡：口语比朗读差 5~6 倍。** `pt-read` 2.8~3.8% → `pt-speech` 16.8~17.6%。
而且 dev 与 holdout **互相印证**（16.8% vs 17.6%），说明这不是抽样噪声。
**这是目前最大的一个数** —— 它说明"朗读语料上的数字"完全不能代表产品表现。

**② 中文的错法主要是"漏字"，葡语主要是"换字"。**

| | 删除占比 |
|---|---|
| 中文 | **2.5%~8.2%**（占总错误一半以上） |
| 巴葡朗读 | 0.3%~0.4% |
| 巴葡口语 | 7.9%~8.1% |

中文 CER 里"删除"压倒性 —— 识别**整段整段地少给字**。这类错在同传里最危险：
听的人不知道自己漏了。**报告必须把删除单独列出来**（老师 §八 要 S/D/I 就是这个原因）。

**③ 口语的 RTF 反而更高（0.19~0.24 vs 0.09~0.12）。**
口语片段更短（中位 2.5~3.0s vs 朗读 10~12s），而每段的固定开销摊不掉。
**这对同传是坏消息 —— 我们的生产链路正好是短片段。**

### 6.3 ⚠️ 一个必须知道的"计分假象"（中文）

中文 dev(12.3%) 与 holdout(5.4%) 差 2.3 倍，一度很像 bug。查下来是**参考文本的写法约定**：

按句错误率分布：dev 的 P50 只有 **2.0%**、P90 却是 **33.3%** —— 不是整体偏移，
是**少数灾难样本**拖的（最差 5 条贡献了 dev 全部错误的 **42%**；holdout 里同样 5 条只占 18%）。

看那些灾难样本：

```
参考  108 碟珍馐奉纳（Chhappan Bhog）… 指供奉神灵的56 种…
识别  一百零八碟真修凤纳 在印度教中 只供奉神灵的五十六种…
参考  克鲁格国家公园 (KNP) 位于南非东北部…
识别  克鲁格国家公园位于南非东北部…
```

参考里混着**阿拉伯数字**与**外文括号注记**，而朗读音频里这些注记往往**没有被念出来**，
Whisper 自然不会输出 —— 在 v1 的严格口径下这些全算**删除**。

**归因（同一批样本，只在评分前做不同处理）**：

| 处理 | zh-read-dev | zh-read-holdout | pt-read-dev |
|---|---|---|---|
| v1（现行口径） | 12.3% | 5.4% | 2.8% |
| 只做数字写法归一 | 11.8% | 5.3% | 2.8% |
| 只去掉括号注记 | **9.0%** | 5.0% | **3.4%**（反而变差） |
| 两者都做 | 8.6% | 4.9% | 3.4% |

**结论两层，第二层更重要：**
1. 中文 dev 的 12.3% 里，**约 3.3 个百分点（27%）来自"参考的注记约定"，不是识别错**。
2. **但不能用一个通用规则去掉它** —— 同一条规则在葡语上让指标**变差**（2.8% → 3.4%），
   说明"括号里的内容念没念"**因语料而异**。这正是老师 §三 要的两件事：
   **① 原始转写与评分用转写分开存；② 评分规范要冻结、并且能人工核对。**

> 所以 **v1 保持不动**：改口径必须开 v2 并把所有历史集重跑一遍。
> "评分用转写"该怎么定，需要**对着音频确认那些注记到底念没念** ——
> 这件事只能提出证据，不能替它拍板。

### 6.4 评测口径与产线口径的两处差别（已查、已量、已做成开关）

老师要求"保留现有解码参数"。查代码发现**评测原来有两处与产线不一致**：

| 参数 | 评测原缺省 | 产线 | 影响 |
|---|---|---|---|
| `vad_filter` | `True`（faster-whisper 内置 Silero VAD 再切一遍） | **`False`**（产线自己已按能量切好） | 评测多切了一次 |
| `initial_prompt` | **不发** | **默认发语种提示词**（zh:「请用简体中文输出」/ pt:「巴西葡语」） | 产线多一个先验 |

**实测差别（同一批 30 条样本，逐一核对过是同一条）**：

| 测试包 | 评测原口径 | 产线口径 | 差值 |
|---|---|---|---|
| `pt-speech-dev` | 18.1% | 18.5% | **+0.4pp** |
| `pt-speech-holdout` | 16.1% | 16.6% | **+0.4pp** |
| `zh-read-holdout` | 5.4% | **4.9%** | **−0.5pp** |

**结论：两处差别都小于 0.5 个百分点，不改变任何结论** —— §6.1 那张表仍然可用。
（顺带：那个"请用简体中文输出"的提示词在这 30 条上**没有减少繁体字**，都是 2 字 ——
说明它除了会被回显成假字幕之外，对繁体并没有可测的收益，见 `docs/04` §9 的更正。）

两个开关都在 `asr_eval.py` 上（`--vad-filter/--no-vad-filter`、`--initial-prompt`），
并且**写进 `provenance`** —— 以后跑"产线口径"只需加参数，不必改代码。

## 7. 怎么读这些数字（三个容易搞混的点）

| 容易搞混 | 正解 |
|---|---|
| 把 RTF 与"单条耗时"当一回事 | RTF 是**整批**的吞吐比；单条耗时是**每句**的快慢。同传看 P95，不看平均 |
| 把"好的句子"当验收线 | 它是"有多少句基本能用"的**分布指标**，阈值 10% 是我们定的；验收线要用**整体错误率** |
| 把 dev 数字当结论 | dev 是**用来调参**的，会被反复看；**只有保留集的数字能当结论**。而且现在 dev/holdout 差 2.3 倍（§6.3），说明这个规模的切分本身噪声不小 |
