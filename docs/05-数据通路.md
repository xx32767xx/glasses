# 05 · 数据通路与目录布局

> 这一页回答两个问题：
> **① 数据到底存在哪、哪个能删哪个不能删？② 一笔语音从手机进来到字幕回到手机上，中间经过什么？**
>
> 改造前这些路径散落在 4 个文件里、还有 5 处写死了 `E:/GlassesHarness`。
> 现在**所有落盘路径只有一处定义**：`lib/paths.mjs`。别在别处再写字面量。

## 一、目录布局

```
GlassesHarness/
├─ plugin/          交付的插件本体（业务逻辑唯一来源 + 正式包入口 + 两个生成物）
├─ dynamic/         生成的动态插件包（粘贴到创造模式用）
├─ policy/          巴葡口径的唯一来源（br-pt.json）
├─ skills/          同传操作规范（SKILL.md，手写 + 一段自动生成）
├─ bridge/          ASR 桥（JS）+ 可选的 Python 识别引擎
├─ relay/           局域网转发（手机 ↔ 电脑）
├─ lib/             生成、组合、路径等共用实现
├─ scripts/         开发期脚本（生成 / 演示 / 常驻进程 / 打包 APK）
├─ tests/           验证（JS 契约 + Python 分段器 + 真实 Cordis 组合）
├─ android/         安卓 App「虚拟眼镜」
├─ docs/            文档（本页是 05）
└─ var/             **运行时数据，全部不进版本库**
   ├─ live/         收件箱 + 字幕总线 + 转发密钥   ← 不能删
   ├─ demo/         一键演示的数据                  ← 可删
   ├─ test/         测试用数据                      ← 可删
   ├─ cache/        模型缓存 + 公开语料             ← 随便删，会自动重下
   ├─ audio/        测试音频                        ← 可删，但重录要花时间
   └─ logs/         跑出来的日志                    ← 随便删
```

### 为什么按"能不能随便删"分层，而不是全塞一个 `.tmp`

三种数据混在一起的代价很具体：

| 数据 | 例子 | 删掉的后果 |
|---|---|---|
| 进程间通信状态 | `live/asr-inbox.jsonl`、`live/subtitle-bus.json` | 链路当场断，要重启两个进程 |
| 可重建缓存 | `cache/hf/`（Whisper 模型，约 5 GB） | 下次自动重下（几分钟到十几分钟） |
| 一次性产物 | `audio/`、`logs/` | 没了就没了，不影响运行 |

以前它们都在 `.tmp/` 下平铺。后果是：**想清缓存就会顺手把正在跑的收件箱一起删掉**；
而 5 GB 模型缓存躺在仓库里，`git clean -xdf` 一不小心就连带清掉。
现在删 `var/cache` 是安全的，删 `var/live` 是明确危险的 —— 这件事变成了目录名就能看出来的信息。

## 二、一笔语音的完整通路

```
        ┌─────────────────────────── 手机（安卓 App「虚拟眼镜」）───────────────────────────┐
        │  麦克风 → [ASR] → 文本                                                            │
        │  注：这台设备的系统语音识别服务不可用（已诊断），所以改成录音上传给电脑识别          │
        └────────────────────────────────────┬──────────────────────────────────────────────┘
                                             │ POST /say   （局域网 + 共享密钥）
                                             ▼
                            relay/lan-relay.mjs（手机 ↔ 电脑的转发进程）
                                             │ 按行追加
                                             ▼
                         var/live/asr-inbox.jsonl      ← 【收件箱】一行一句话
                                             │ leion-pro 用真实 timer 轮询
                                             ▼
                    语向判定 → 调模型翻译 → 排版成 40 列 × 3 行
                                             │ 覆盖写
                                             ▼
                         var/live/subtitle-bus.json    ← 【字幕总线】只保留当前帧
                                             │ GET /frame?since=N（长轮询）
                                             ▼
        ┌────────────────────────────────────────────────────────────────────────────────┐
        │  手机面板显示字幕                                                                 │
        └────────────────────────────────────────────────────────────────────────────────┘
```

用**文件**做接缝（而不是进程内调用）是刻意的：转发进程与插件互不认识，
将来插件装进 `dsh web`、或者识别挪到别的机器上，两边都不用改。

### 语音识别的另一条支路（本地 Whisper）

```
var/audio/zh/xxx.wav
   └─► bridge/whisper_stream.py   按音量切句（自适应门槛）+ 防幻听 + 预热
         └─► bridge/asr-bridge.mjs  每行一句话
               └─► var/live/asr-inbox.jsonl   （之后同上）
```

`asr-bridge.mjs` 的四种引擎都往同一个收件箱写：`stdin` / `command` / `replay` / `whisper`。
所以换识别引擎**不影响**后面任何一环。

## 三、两个文件的格式（唯一权威定义）

### 收件箱 `var/live/asr-inbox.jsonl`

**一行一句话，UTF-8，以 `\n` 结束。** 半行不算（插件只处理到最后一个换行符为止）。

纯文本行就是原文：

```
你好，这是一条测试信息
```

也可以写成 JSON，用来指定语向与说话人（省掉插件的自动判定）：

```json
{"text":"Bom dia, tudo bem?","from":"pt-BR","to":"zh-CN","speaker":"them"}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `text` | ✅ | 原文。JSON 行必须有这个字符串字段 |
| `from` | ⬜ | 源语种，如 `pt-BR` / `zh-CN`。省略则插件自动判定 |
| `to` | ⬜ | 目标语种。省略则由语向规则推 |
| `speaker` | ⬜ | `them`（对方）/ `me`（佩戴者自己）。只允许这两个值 |

坏行**不会**中断整条同传：只计数、记进 `lastError`，然后跳过继续。
所以外部 ASR 写坏了不会让眼镜黑屏。

### 字幕总线 `var/live/subtitle-bus.json`

**每次覆盖写整个文件**（不是追加）。只保留"眼镜屏幕上此刻该显示什么"：

```json
{
  "device": "Leion Pro",
  "speaker": "me",
  "lang": "pt-BR",
  "text": "Esta é uma mensagem de teste.",
  "lines": ["Esta é uma mensagem de teste."],
  "cols": 40,
  "lineBudget": 3,
  "at": "2026-10-03T16:57:20.529Z"
}
```

| 字段 | 说明 |
|---|---|
| `text` | 完整译文（未折行） |
| `lines` | **已经折好行**的最终显示内容，长度 ≤ `lineBudget` |
| `cols` / `lineBudget` | 显示预算。**转发进程以帧里的值为准**，不再自己存一份 |
| `speaker` | `them` = 对方说的话（主通道）；`me` = 佩戴者自己说的话（出站通道） |
| `lang` | 这一帧的语言 |

`cols`/`lineBudget` 放在帧里而不是让继电器自己配，是为了避免"眼镜多大"这件事
在两个进程里各存一份然后漂移 —— 插件是唯一来源。

## 四、路径怎么取（写代码时看这里）

```js
import { LIVE_DIR, CACHE_DIR, defaultInbox, defaultBus } from '../lib/paths.mjs'
```

| 导出 | 值 | 用途 |
|---|---|---|
| `ROOT` | 仓库根 | **别再自己算** |
| `VAR_DIR` / `LIVE_DIR` / `DEMO_DIR` / `TEST_DIR` | 见上表 | 数据目录 |
| `CACHE_DIR` / `AUDIO_DIR` / `LOGS_DIR` | | 缓存、音频、日志 |
| `INBOX_NAME` / `BUS_NAME` / `SECRET_NAME` | 文件名 | 别在别处写字面量 |
| `defaultInbox(dir)` / `defaultBus(dir)` / `defaultSecret(dir)` | 拼路径 | 缺省值统一从这来 |
| `WHISPER_CACHE_DIR` / `CORPUS_DIR` / `PT_EVAL_DIR` / `TEST_INBOX` | | 具体用途的固定位置 |

Python 那边不 import 这个文件（跨语言没必要），约定是：**命令行显式传路径**，
缺省值写在文档里。见 `docs/04` 的复现命令。

## 五、改造前后的对照（这次修掉了什么）

| 问题 | 改造前 | 改造后 |
|---|---|---|
| 硬编码绝对路径 | `E:/GlassesHarness/...` 写死在 5 个文件的 8 处；`tests/live/cordis.yml` 里还写死了 DSH 检出位置 `D:/DeepSeekHarness/...` | 一处都没有。全部从 `lib/paths.mjs` 与检出探测结果推导 |
| 同一路径多处定义 | `.tmp/live` 在 2 个文件里各写一遍；两个文件名在 4 个文件里各写一遍 | 只在 `lib/paths.mjs` 定义一次 |
| 收件箱路径两处同步 | `tests/live/probe.mjs` 写死一个，`cordis.yml` 再写一个，靠注释提醒"保持一致" | 组合由 `tests/live/composition.mjs` 现场生成，只写一次，通过 config 传给探针 |
| 数据混层 | `.tmp/` 里平铺着 IPC 状态、5 GB 缓存、日志 | 按"能不能删"分层到 `var/` 六个子目录 |
| 仓库换位置 | 5 处直接崩，且报错指不到真正原因 | 随便换 |

⚠️ **一个做不到的地方（照实写）**：原计划把生成产物统一搬进 `generated/`，**没做**。
原因是两处约束：
- `plugin/schemas.generated.mjs`、`plugin/policy.generated.mjs` 被 `plugin/package.json`
  的 `files` 列为**交付包的一部分** —— 搬出去，这个包就不再自包含了。
- `skills/.../SKILL.md` 是**手写为主 + 一段自动生成**（用成对标记圈出生成区），
  且技能目录要按 `skills/` 约定被发现 —— 搬走会破坏技能发现。

所以生成物留在各自来源旁边，靠文件名后缀 `.generated.mjs` + 文件头"自动生成 请勿手改" +
`tests/run-all.mjs` 的新鲜度门禁三重保证。想手改生成物会被门禁当场拦下。

## 六、日常怎么用

```powershell
node scripts/harness-side.mjs      # 常驻：读 var/live 收件箱 → 写 var/live 字幕总线
node relay/lan-relay.mjs           # 转发：打印手机该填的地址和密钥
node scripts/demo.mjs              # 一键演示（数据落 var/demo，不需要手机和麦克风）

# 清缓存（安全，会自动重下）
Remove-Item -Recurse -Force var\cache

# 想看链路状态：直接读这两个文件
Get-Content var\live\asr-inbox.jsonl -Tail 5
Get-Content var\live\subtitle-bus.json -Raw
```
