# 05 · 数据通路与目录布局

> 这一页回答三个问题：
> **① 数据到底存在哪、哪个能删哪个不能删？② 一笔语音从手机进来到字幕回到手机上，中间经过什么？
> ③ 这些文件里，哪些是「harness 的插件」，哪些只是围着它转的外部程序？**
>
> 改造前这些路径散落在 4 个文件里、还有 5 处写死了 `E:/GlassesHarness`。
> 现在**所有落盘路径只有一处定义**：`lib/paths.mjs`。别在别处再写字面量。

## 读这一页前先记住一件事

老师要的那个「在 harness 里自定义的眼镜插件」，**只有这两处**：

- `plugin/` —— 正式插件（持久，装进 profile）
- `dynamic/` —— 同一个插件的动态形态（粘贴到创造模式会话）

**其余所有目录（`bridge/` `relay/` `android/` `scripts/` `tests/`）都跑在 harness 之外**，
是独立的进程或设备。它们不是插件，插件也不认识它们 —— 两边只通过
**两个文件**（收件箱 / 字幕总线）打交道。

> 容易被绕晕的地方：`scripts/harness-side.mjs` 和 `tests/live/` **会启动一个真实的 harness 进程
> 并把插件装进去**，所以它们看起来"在 harness 里"。但它们本身不是插件，而是"把插件跑起来的壳"。
> 下面用 🧩 / ⚙️ / 🔌 三种标记区分。

| 标记 | 含义 | 在哪个进程里 |
|---|---|---|
| 🧩 | **插件（交付物）** | harness 进程内 |
| ⚙️ | harness 进程内、但**不是**交付的插件（配套服务 / 技能文档 / 测试替身） | harness 进程内 |
| 🛠️ | **构建期输入**：只在 `node scripts/generate.mjs` 时被读，运行时与插件无关 | 不在任何进程里 |
| 🔌 | harness 之外（独立进程或设备） | 各自独立 |

## 一、目录布局

🧩 = 插件（交付物）　⚙️ = harness 内非交付插件　🛠️ = 构建期输入　🔌 = harness 之外

```
GlassesHarness/
│
│  ── 🧩 插件本体（老师要的那个东西，只有这两处）────────────────────────────
├─ plugin/          🧩 正式插件包：core.mjs（业务逻辑唯一来源）+ index.mjs（入口）
│                      + 两个生成物 + 两个挂载用 patch + package.json
├─ dynamic/         🧩 同一个插件的「动态包」（粘贴进创造模式会话，会话结束即消失）
│
│  ── 🛠️ 插件在构建期吃进去的原料（运行时都不读）──────────────────────────
├─ policy/          🛠️ 巴葡口径的唯一来源（br-pt.json）
│                      → 由 generate.mjs 编译进 plugin/policy.generated.mjs
│                      ⚠️ 插件运行时**不读**这个目录，读的是编译好的产物
├─ lib/artifacts.mjs🛠️ 生成逻辑：把 policy/ 编译成产物、并更新 SKILL.md 的生成区
│
│  ── ⚙️ harness 进程内的配套（不是交付插件，但插件依赖它们）──────────────
├─ skills/          ⚙️ 同传操作规范 SKILL.md：给 **agent/模型** 看的，不是插件代码，
│                      插件运行时不读它（两者可能漂移，见 docs/01）
├─ lib/fs-node.mjs  ⚙️ 小型 Cordis 插件，提供 `fs` 服务 —— 插件的收件箱/字幕总线靠它读写
├─ lib/keepalive.mjs⚙️ 小型 Cordis 插件，让常驻进程不退
│
│  ── 🔌 harness 之外（独立进程，只通过两个文件与插件对接）─────────────────
├─ bridge/          🔌 ASR 桥（JS）+ Python 识别引擎：把语音变成收件箱里的一行一句话
├─ relay/           🔌 局域网转发：手机 ↔ 电脑，读写收件箱与字幕总线
├─ android/         🔌 手机 App「虚拟眼镜」：录音、显示字幕面板
│
│  ── 开发与验证的脚手架（自己不处理业务数据）────────────────────────────
├─ scripts/         🔌 harness-side（把插件跑起来的壳）/ demo / 生成 / 打包 APK
├─ tests/           🔌 验证：JS 契约 + Python 分段器；tests/live 会启动真实 harness 装插件
├─ lib/（其余文件）  共用实现，**插件一行都不 import 它**：
│                      paths.mjs → 🔌 外部程序运行时取路径用（唯一来源）
│                      composition.mjs / loader-links.mjs / real-tools.mjs → 装配真实 harness 组合用
├─ docs/            文档（本页是 05）
│
│  ── 运行时数据 ──────────────────────────────────────────────────────────
└─ var/             **全部不进版本库**
   ├─ live/         收件箱 + 字幕总线 + 转发密钥   ← 不能删（是 🧩 与 🔌 之间的接缝）
   ├─ demo/         一键演示的数据                  ← 可删
   ├─ test/         测试用数据                      ← 可删
   ├─ cache/        模型缓存 + 公开语料             ← 随便删，会自动重下
   ├─ audio/        测试音频                        ← 可删，但重录要花时间
   └─ logs/         跑出来的日志                    ← 随便删
```

### 哪些文件是 harness 的插件

一个组合（composition）里往往挂着**好几个** Cordis 插件。**只有 `leion-pro` 是交付物**，
其余都是配套服务或测试替身 —— 它们的共同点是都写成 `export name / inject / apply` 的形状，
所以光看代码长得一样，容易混。

| 文件 | 插件名 | 角色 |
|---|---|---|
| `plugin/index.mjs` | `leion-pro` | 🧩 **交付物**：注册 7 个眼镜工具 + ASR 收件箱（`inject: ['tools','timer']`） |
| `dynamic/leion-pro.host.js` | （动态） | 🧩 **同一个插件的动态形态**：业务逻辑与上面完全一致，只是注册方式不同 |
| `lib/fs-node.mjs` | `leion-node-fs` | ⚙️ 提供 `fs` 服务。插件的收件箱与字幕总线就是通过它读写文件的 |
| `lib/keepalive.mjs` | `leion-keepalive` | ⚙️ 让常驻进程保持存活，不参与业务 |
| `tests/live/fake-llm.mjs` | `leion-live-fake-llm` | ⚙️ 测试替身：假 `llm`，让验证不联网、不需要 key |
| `tests/live/probe.mjs` | `leion-live-probe` | ⚙️ 测试观察者：断言 7 个工具注册成功并驱动调用 |
| `scripts/demo-driver.mjs` | `leion-demo-driver` | ⚙️ 演示驱动：把剧本重放进收件箱、把眼镜屏幕画出来 |
| `@deepseek-ai/cordis-plugin-timer`、`…-logger-console` | 厂商插件 | ⚙️ harness 自带：定时器与日志。插件的 `inject` 里有 `timer`，所以组合里必须有 |
| `packages/core/tools`、`packages/core/system-prompt` | 厂商插件 | ⚙️ harness 自带：就是 `ctx.tools` 与系统提示词的提供者 |

**判断口诀**：`plugin/` 与 `dynamic/` 里的是交付物；其他任何 `export name / inject / apply`
的文件都是"为了让交付物跑起来/被验证"而存在的。

### 插件用到了 harness 的哪些能力

插件自己**不碰**麦克风、不碰网络、不碰硬件，它只用 harness 已注入的服务：

| 服务 | 用法 | 在哪一行 |
|---|---|---|
| `ctx.tools` | 注册 7 个工具 | `plugin/index.mjs` 的 `ctx.tools.register()` |
| `ctx.timer` | 轮询收件箱（这是"自动同传"的开关） | `plugin/index.mjs` 的 `inject` |
| `ctx.llm` | 调模型做翻译（默认后端 `harness-llm`） | `plugin/core.mjs` |
| `ctx.fs` | 读写收件箱与字幕总线 | `plugin/core.mjs` |

所以"插件的边界"很清楚：**它只是个纯计算的中间层** —— 文本进、文本出，
进出的通道就是下面那两个文件。

### 为什么按"能不能随便删"分层，而不是全塞一个 `.tmp`

三种数据混在一起的代价很具体：

| 数据 | 例子 | 删掉的后果 |
|---|---|---|
| 进程间通信状态 | `live/asr-inbox.jsonl`、`live/subtitle-bus.json` | 链路当场断，要重启两个进程 |
| 可重建缓存 | `cache/hf/`（Whisper 模型，约 5 GB） | 下次自动重下（几分钟到十几分钟） |
| 一次性产物 | `audio/`、`logs/` | 没了就没了，不影响运行 |

以前它们都在 `.tmp/` 下平铺。后果是：**想清缓存就会顺手把正在跑的收件箱一起删掉**；
而 5 GB 模型缓存躺在仓库里，`git clean -xdf` 一不小心就连带清掉。
现在删 `var/cache` 是安全的，删 `var/live` 是明确危险的 —— 这件事变成了目录名就能看出来的信息。

## 二、一笔语音的完整通路

**看这张图只盯一件事：`VAR` 那条横线就是 harness 进程的边界。**
线以上全是 🔌 harness 之外，线以下才是 🧩 插件在干活。

手机有**两种**把语音送进来的方式，最后都汇到同一个收件箱：

```
   方式①录音上传（推荐，本机唯一真能用的）
   ────────────────────────────────────────
   手机麦克风 → AudioRecord 录成裸 PCM → 每秒一块 POST /audio?rate=&fresh=
        │
        ▼
   relay 追加写 → var/live/audio-in.pcm  +  audio-in.rate（真实采样率）
        │
        ▼  电脑上的识别进程尾随这个文件（whisper_stream.py --follow）
   按音量切句 → Whisper 识别 → 一句话一行（stdout）
        │
        └──────────────┐
                       │
   方式②系统语音识别    │
   ────────────────────┤
   手机麦克风 → 安卓自带识别 → POST /say {"text":...}
                       │
   🔌 harness 之外 ────┼──────────────────────────────────────────────────────
                       ▼
   ══════════════════════════════════════════════════════════════════════════
                    var/live/asr-inbox.jsonl   ← 【收件箱】🧩 与 🔌 的接缝之一
   ══════════════════════════════════════════════════════════════════════════
                       │ leion-pro 用真实 timer 轮询（⚙️ ctx.timer）
   🧩 harness 进程内 ──▼─────────────────────────────────────────────────────
                    plugin/index.mjs   🧩 交付的插件本体
                         │
                         ├─ 读收件箱（⚙️ ctx.fs）
                         ├─ 判语向 → 调模型翻译（⚙️ ctx.llm，默认 harness-llm）
                         └─ 排版成 40 列 × 3 行
                         │ 覆盖写
   ══════════════════════╪═══════════════════════════════════════════════════
                    var/live/subtitle-bus.json ← 【字幕总线】接缝之二
   ══════════════════════╪═══════════════════════════════════════════════════
                         │ GET /frame?since=N（长轮询）
   🔌 harness 之外 ──────▼───────────────────────────────────────────────────
        relay 取到帧 → 手机面板显示字幕
```

**为什么两边用文件而不是直接调用**：转发进程与插件互不认识。
将来插件装进你自己的 `dsh web`、或者把识别挪到另一台机器、或者干脆换掉手机端，
**另一边一行都不用改** —— 这也是为什么 `relay/` 与 `bridge/` 里没有一行 import 插件的代码。

**为什么录音要"落盘再尾随"，而不是收到一块就识别一块**：
按音量切句需要**跨块**的连续性 —— 一句话可能横跨两次上传。追加到一个文件里，
下游看到的就是一条连续的音频流，跟"直接用麦克风录"在形态上完全一致；
如果每块单独识别，句首句尾会被切断，结果是莫名其妙地缺字。

### 语音识别的另一条支路（本地 Whisper 转写文件，全部在 harness 之外）

```
var/audio/zh/xxx.wav 或 var/live/audio-in.pcm                    🔌
   └─► bridge/whisper_stream.py   按音量切句（自适应门槛）+ 防幻听 + 预热   🔌
         └─► bridge/asr-bridge.mjs  每行一句话                            🔌
               └─► var/live/asr-inbox.jsonl   ← 到了这条线就与上面那张图汇合
```

`asr-bridge.mjs` 的四种引擎都往同一个收件箱写：`stdin` / `command` / `replay` / `whisper`。
所以换识别引擎**不影响**插件那一侧的任何一环。

## 三、接口与文件的格式（唯一权威定义）

这里定的是 🧩 插件与 🔌 外部程序之间**全部的接口**。改格式等于改协议，两边要一起改。

### 转发进程的 5 个端点（`relay/lan-relay.mjs`）

| 端点 | 谁调 | 作用 |
|---|---|---|
| `GET /hello` | 手机 | 握手：验证密钥 + 取回显示预算 |
| `POST /say` | 手机（系统识别那条路） | `{"text":...}` → 追加进收件箱 |
| `POST /audio` | 手机（录音上传那条路） | 裸 PCM → 追加进 `audio-in.pcm` |
| `GET /frame?since=N` | 手机 | 长轮询取字幕帧 |
| `GET /status` | 手机 / 你 | 诊断计数 |

全部要带密钥（`X-Leion-Secret` 头或 `?secret=`）。

### 收件箱 `var/live/asr-inbox.jsonl`

**谁写**：🔌 任意外部程序（`relay`、`asr-bridge`、你自己写的脚本）。
**谁读**：🧩 `leion-pro`（用 `ctx.fs` + `ctx.timer` 轮询）。

**一行一句话，UTF-8，以 `\n` 结束。** 半行不算（插件只处理到最后一个换行符为止）。

纯文本行就是原文：

```
你好，这是一条测试信息
```

也可以写成 JSON，用来指定语向与说话人（省掉插件的自动判定）：

```json
{"text":"Bom dia, tudo bem?","from":"pt-BR","to":"zh-CN","speaker":"them"}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `text` | ✅ | 原文。JSON 行必须有这个字符串字段 |
| `from` | ⬜ | 源语种，如 `pt-BR` / `zh-CN`。省略则插件自动判定 |
| `to` | ⬜ | 目标语种。省略则由语向规则推 |
| `speaker` | ⬜ | `them`（对方）/ `me`（佩戴者自己）。只允许这两个值 |

坏行**不会**中断整条同传：只计数、记进 `lastError`，然后跳过继续。
所以外部 ASR 写坏了不会让眼镜黑屏。

### 字幕总线 `var/live/subtitle-bus.json`

**谁写**：🧩 `leion-pro`（`transport: 'file'` 时，用 `ctx.fs` 覆盖写）。
**谁读**：🔌 `relay`（长轮询后推给手机）。测试与演示还会读它来"画眼镜屏幕"。

**每次覆盖写整个文件**（不是追加）。只保留"眼镜屏幕上此刻该显示什么"：

```json
{
  "device": "Leion Pro",
  "speaker": "me",
  "lang": "pt-BR",
  "text": "Esta é uma mensagem de teste.",
  "lines": ["Esta é uma mensagem de teste."],
  "cols": 40,
  "lineBudget": 3,
  "at": "2026-10-03T16:57:20.529Z"
}
```

| 字段 | 说明 |
|---|---|
| `text` | 完整译文（未折行） |
| `lines` | **已经折好行**的最终显示内容，长度 ≤ `lineBudget` |
| `cols` / `lineBudget` | 显示预算。**转发进程以帧里的值为准**，不再自己存一份 |
| `speaker` | `them` = 对方说的话（主通道）；`me` = 佩戴者自己说的话（出站通道） |
| `lang` | 这一帧的语言 |

`cols`/`lineBudget` 放在帧里而不是让继电器自己配，是为了避免"眼镜多大"这件事
在两个进程里各存一份然后漂移 —— 插件是唯一来源。

### 上传音频 `var/live/audio-in.pcm` + `audio-in.rate` + `audio-in.lang`

**谁写**：🔌 `relay`（手机 POST `/audio` 时追加写）。
**谁读**：🔌 电脑上的识别进程（`whisper_stream.py --follow`）。
**🧩 插件完全不碰这些文件** —— 它只认收件箱里的文字。

| 文件 | 内容 |
|---|---|
| `audio-in.pcm` | 裸 PCM：**16-bit 小端、单声道、无文件头**。追加写，不是覆盖 |
| `audio-in.rate` | 就一个数字：真实采样率（`16000` / `44100` / `48000`）+ 换行 |
| `audio-in.lang` | 手机当前在听哪种语言（`pt-BR` / `zh-CN`）+ 换行 |

四个必须遵守的约定，都有下游代码在为它们兜底：

1. **字节数必须是偶数**。PCM 一帧 2 字节，奇数长度说明发端截断在半帧上；
   收下会把之后所有采样错位（听感是刺啦声，识别必然崩）。所以 relay 直接返回 400。
2. **采样率必须如实上报，不许猜**。安卓不保证每台设备都能以 16 kHz 录音
   （Whisper 要 16 kHz），手机降级后会声明 44.1 kHz，识别进程按 `audio-in.rate` 重采样。
   猜错的后果是全篇乱码，所以宁可拒收也不静默改成 16 kHz。
3. **语种跟着音频一起发**（`?lang=`），识别进程按 `audio-in.lang` 切语种。
   这样手机上切「听葡语/听中文」**在录音过程中也立刻生效**，不用停止再开始。
4. **`?fresh=1` 表示新一次录音的开始**，relay 会先把文件清空。
   识别进程发现文件变短了就把读指针退回 0 —— 不处理的话会永远卡在旧偏移，
   表现成"录音上传没反应"。

为什么单独放旁文件而不是塞进音频文件头：音频是**追加流**，
读的人可能在文件写到一半时就开始读（这正是低延迟的来源），
此时任何"文件头"都还没写完。旁文件是独立的一次性小写入，不存在这个问题。

## 四、路径怎么取（写代码时看这里）

```js
import { LIVE_DIR, CACHE_DIR, defaultInbox, defaultBus } from '../lib/paths.mjs'
```

| 导出 | 值 | 用途 |
|---|---|---|
| `ROOT` | 仓库根 | **别再自己算** |
| `VAR_DIR` / `LIVE_DIR` / `DEMO_DIR` / `TEST_DIR` | 见上表 | 数据目录 |
| `CACHE_DIR` / `AUDIO_DIR` / `LOGS_DIR` | | 缓存、音频、日志 |
| `INBOX_NAME` / `BUS_NAME` / `SECRET_NAME` | 文件名 | 别在别处写字面量 |
| `defaultInbox(dir)` / `defaultBus(dir)` / `defaultSecret(dir)` | 拼路径 | 缺省值统一从这来 |
| `WHISPER_CACHE_DIR` / `CORPUS_DIR` / `PT_EVAL_DIR` / `TEST_INBOX` | | 具体用途的固定位置 |

Python 那边不 import 这个文件（跨语言没必要），约定是：**命令行显式传路径**，
缺省值写在文档里。见 `docs/04` 的复现命令。

> ⚠️ **注意插件本体不 import 这个文件。** `plugin/` 与 `dynamic/` 是交付物，
> 要保持零第三方依赖、且能被装到别人机器上的任意位置 —— 所以收件箱与字幕总线的路径
> 是**从 `cordis.yml` 的 `config` 传进去的**（`inboxPath` / `sinkPath`），
> 不是从仓库里推导的。这一点跟 🔌 外部程序正好相反：
>
> | | 🧩 插件 | 🔌 外部程序 |
> |---|---|---|
> | 路径从哪来 | `config`（由挂载方给） | `lib/paths.mjs` 推导，或命令行参数 |
> | 为什么 | 要能装到任意位置、脱离本仓库运行 | 就在本仓库里跑，能自己算 |
>
> `lib/paths.mjs` 里没有、也不该有 `plugin/` 的导入，这是刻意保持的边界。

## 五、改造前后的对照（这次修掉了什么）

| 问题 | 改造前 | 改造后 |
|---|---|---|
| 硬编码绝对路径 | `E:/GlassesHarness/...` 写死在 5 个文件的 8 处；`tests/live/cordis.yml` 里还写死了 DSH 检出位置 `D:/DeepSeekHarness/...` | 一处都没有。全部从 `lib/paths.mjs` 与检出探测结果推导 |
| 同一路径多处定义 | `.tmp/live` 在 2 个文件里各写一遍；两个文件名在 4 个文件里各写一遍 | 只在 `lib/paths.mjs` 定义一次 |
| 收件箱路径两处同步 | `tests/live/probe.mjs` 写死一个，`cordis.yml` 再写一个，靠注释提醒"保持一致" | 组合由 `tests/live/composition.mjs` 现场生成，只写一次，通过 config 传给探针 |
| 数据混层 | `.tmp/` 里平铺着 IPC 状态、5 GB 缓存、日志 | 按"能不能删"分层到 `var/` 六个子目录 |
| 仓库换位置 | 5 处直接崩，且报错指不到真正原因 | 随便换 |

⚠️ **一个做不到的地方（照实写）**：原计划把生成产物统一搬进 `generated/`，**没做**。
原因是两处约束：
- `plugin/schemas.generated.mjs`、`plugin/policy.generated.mjs` 被 `plugin/package.json`
  的 `files` 列为**交付包的一部分** —— 搬出去，这个包就不再自包含了。
- `skills/.../SKILL.md` 是**手写为主 + 一段自动生成**（用成对标记圈出生成区），
  且技能目录要按 `skills/` 约定被发现 —— 搬走会破坏技能发现。

所以生成物留在各自来源旁边，靠文件名后缀 `.generated.mjs` + 文件头"自动生成 请勿手改" +
`tests/run-all.mjs` 的新鲜度门禁三重保证。想手改生成物会被门禁当场拦下。

## 六、日常怎么用

命令后面标了**它在哪一侧**：🧩/⚙️ 会启动 harness 并把插件装进去，🔌 是纯外部程序。

```powershell
node scripts/harness-side.mjs      # ⚙️ 壳：起真实 harness + 装插件，读 var/live 收件箱 → 写字幕总线
                                   #    默认先清空收件箱（否则会把上次留下的行再翻译一遍，看着像"刚收到"）
                                   #    想保留旧内容加 --keep-inbox
node relay/lan-relay.mjs           # 🔌 转发：打印手机该填的地址和密钥，并打印收到的音频/文字/字幕
node scripts/debug-window.mjs      # 🔌 调试窗口：四个环节并排显示 + 直接判断断在哪一环（只读，不影响链路）
node scripts/demo.mjs              # ⚙️ 一键演示（数据落 var/demo，不需要手机和麦克风）

# 清缓存（安全，会自动重下）
Remove-Item -Recurse -Force var\cache
```

**想知道"手机说的话走到哪一步了"，用调试窗口**，不要靠猜：

```powershell
node scripts/debug-window.mjs --url http://127.0.0.1:8788 --secret <转发进程打印的密钥>
```

它读的正是本页定义的四个环节（音频文件 / 收件箱 / 字幕总线 / 转发进程计数），
所以它的结论和这一页的布局一一对应：

| 证据 | 结论 |
|---|---|
| `audio-in.pcm` 不涨 | 音频没上来（手机没点按钮，或转发进程是**改代码之前**启动的） |
| 音频在涨、收件箱不动 | 识别进程没跑，或它盯的不是这个文件 |
| 收件箱在涨、字幕不动 | 插件没在消费（harness-side 没跑或跑的是旧进程） |
| 字幕在更新、手机不显示 | 手机取字幕那一环 |

⚠️ **改完电脑侧代码要重启对应进程**：Node 启动时就把代码读进内存，改文件不影响已在跑的进程。
这一条踩过两次，症状都完全不像"代码没生效"（一次是 `HTTP 404` 说没有 `/audio`，
一次是手机永远收不到字幕却也不报错）。

**想确认"插件到底有没有被 harness 加载"**，看这两处：

```powershell
# 1) 插件加载时会打一行（来自 plugin/core.mjs 的 loadedMessage）
#    [leion-pro] 插件已加载 · Leion Pro · transport=file · 显示预算 40×3
# 2) 或者直接问它自己：7 个工具在不在
node scripts/show-prompt.mjs       # ⚙️ 打印插件给模型看的系统提示词，能出内容就说明逻辑是好的
```

⚠️ `plugin/` 与 `dynamic/` 是**唯一**要交给别人的东西；
`var/live/` 里那两个文件是它与外界的全部接口。其余目录都可以不要 ——
换句话说：**把 `plugin/`（或 `dynamic/`）+ 两个文件的路径配置交出去，插件就能在别人的
harness 里跑**，而 `bridge/` `relay/` `android/` 只是本机这套演示环境。
