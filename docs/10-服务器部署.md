# 服务器部署（把电脑端搬到公网服务器）

> **状态：方案已定，代码侧的准备工作已做完，但还没有在真实服务器上跑过一次。**
> 下面凡是"没验证过"的地方都明确标了。别把它当"已验证的操作手册"。

---

## 1. 为什么这一步能一次解决两个问题

### 问题一：手机连不上电脑（校园网跨网段）

实测结论：**手机在 10.136 网段、电脑在 10.135 网段，校园网不允许设备互访。**
电脑这一侧 `net-doctor` 的四项（地址 / 端口 / 监听 / 防火墙）**全过**，
所以卡点百分之百在"两机之间"这一层，不是配置问题。

而校园网只挡**设备之间**，不挡**出公网**。所以一旦服务在公网服务器上：

```
手机 ──(普通出网流量)──> 服务器公网 IP:端口      ← 这一条任何网络都允许
```

跨网段、AP 隔离、DHCP 换网段——**全部消失**。不是绕过，是问题不存在了。

### 问题二：这是最终架构

原计划就是把 harness 搬到租的国内 GPU 服务器上。所以这一步不是权宜之计，
而是本来就要走的路；反过来，**先上服务器就不必再折腾热点 / VPN 了**。

### 目标架构

```
┌──────────┐  USB   ┌───────────────┐   HTTPS    ┌─────────────────────────┐
│ 亮亮眼镜 │<──────>│  安卓手机 App │<──────────>│  公网服务器（国内）      │
│（只做显示）│        │ 麦克风 + 投屏 │   音频上行  │  转发进程 :8788          │
└──────────┘        └───────────────┘   字幕下行  │  → asr-inbox.jsonl       │
                                                  │  → 识别（faster-whisper）│
                                                  │  → 插件（翻译 + 排版）   │
                                                  │  → subtitle-bus.json     │
                                                  └─────────────────────────┘
```

**关键点：眼镜仍然接在手机上。** 服务器不接触硬件，只做"音频 → 字幕"。
所以上服务器**不影响眼镜这条线**（`docs/09` 里那些坑一个都不用重踩）。

## 2. 服务器要什么

| 项 | 要求 | 说明 |
|---|---|---|
| **公网 IP** | 必须 | 这是整件事的前提。没有公网 IP 就得先看第 8 节 |
| 系统 | Linux（Ubuntu 22.04 / Debian 12 验证最多） | 我们的脚本是 Node，跨平台 |
| Node.js | **20 或更高** | 用到 `fetch`、`node:test` 等 |
| Python | 3.10+ | 识别用 faster-whisper |
| GPU | **强烈建议** | 见下面的延迟预算；纯 CPU 也能跑，但要降模型 |
| 内存 | ≥ 8 GB（GPU 版 large-v3 要 ~4 GB 显存/内存） | 模型常驻内存 |
| 磁盘 | ≥ 40 GB | 模型 + 音频落盘（音频只追加不清空） |
| 出网 | 要能访问翻译 API | 国内服务器访问 DeepSeek 没问题 |

### 延迟与带宽预算（算给你看的）

```
上行（手机 → 服务器）：16kHz × 16bit 单声道 = 32 KB/s ≈ 256 kbps
下行（服务器 → 手机）：字幕，可忽略
```

256 kbps 对 4G / 校园网都很轻。真正的延迟大头是**识别**，不是网络：

| 环节 | 量级 | 依据 |
|---|---|---|
| 网络 RTT（国内服务器） | 10–50 ms | 同城/同省 |
| 切句（等静音） | 500 ms | `--silence-ms 500`，`docs/06` |
| 识别（GPU large-v3） | ~600 ms/句 | `docs/04` 实测 |
| 翻译 | 取决于后端 | 大模型校对另算，见 `docs/07` |
| 合计 | **≈ 1.2–1.5 s** | 与局域网相比只多几十毫秒 |

也就是说：**网络这一环在总延迟里占比很小**，上服务器不会明显变慢。

## 3. 部署步骤

> 下面的路径用 `/opt/glasses-harness` 和 `/opt/deepseek-harness` 举例，按你自己的放。

### 3.1 拉代码

```bash
# 本仓库
sudo mkdir -p /opt/glasses-harness && sudo chown $USER /opt/glasses-harness
git clone <本仓库> /opt/glasses-harness
cd /opt/glasses-harness

# ⚠️ harness 检出（**必需**，不是可选）
#    插件跑在 DSH harness 里，lib/real-tools.mjs 会去加载它的构建产物。
git clone <deepseek-harness 仓库> /opt/deepseek-harness
cd /opt/deepseek-harness && pnpm install && pnpm build
```

> **这一条最容易漏。** `lib/real-tools.mjs` 里原来**写死了 Windows 路径**
> （`D:\DeepSeekHarness\deepseek-harness`），这次一起改成了按候选路径查找，
> 并把"找过哪些"写进报错信息。所以服务器上要么把检出放在
> `~/deepseek-harness`、`/opt/deepseek-harness` 这类候选位置，
> 要么显式设环境变量：
>
> ```bash
> export DSH_CHECKOUT=/opt/deepseek-harness
> ```

### 3.2 装 Python 依赖

```bash
cd /opt/glasses-harness
python3 -m venv .venv && . .venv/bin/activate
pip install faster-whisper
```

模型下载：国内直连 HuggingFace 通常不通，用镜像。

```bash
export HF_ENDPOINT=https://hf-mirror.com
export HF_HOME=/opt/glasses-harness/var/cache/hf
```

> `HF_HOME` 必须设：只设 `HF_ENDPOINT` 时 `faster_whisper` 可能仍然找不到已缓存的模型
> （这个坑在本机踩过，见 `docs/04`）。

第一次跑会自动下模型（large-v3 约 3 GB）。建议**先手动预热一次**，别在演示时等下载：

```bash
python3 bridge/whisper_stream.py --help   # 或者先跑一次 --whisper-model tiny
```

### 3.3 配密钥

翻译用的 API key 不要写进仓库。三种来源（按优先级）：

1. 环境变量 `DEEPSEEK_API_KEY`
2. `$DSH_HOME/.credentials.yaml`
3. 仓库根的 `.env`（**已在 `.gitignore` 里**）

systemd 部署推荐用 `EnvironmentFile`：

```bash
sudo install -m 600 /dev/null /etc/glasses-harness.env
sudo tee /etc/glasses-harness.env >/dev/null <<'EOF'
DEEPSEEK_API_KEY=sk-xxxxxxxxxxxxxxxx
DSH_CHECKOUT=/opt/deepseek-harness
HF_ENDPOINT=https://hf-mirror.com
HF_HOME=/opt/glasses-harness/var/cache/hf
PYTHONUTF8=1
EOF
```

### 3.4 用 `--public` 起（**别省这个参数**）

```bash
cd /opt/glasses-harness
node scripts/start-all.mjs --public --data-dir var/live --port 8788
```

`--public` 会做四件事（缺一件都别上线）：

| 做了什么 | 为什么 |
|---|---|
| 密钥要求 ≥ 24 字符，不足则重新生成 | 局域网那个缺省是 12 个 hex（48 位），放公网太短 |
| 转发进程绑 `0.0.0.0` | 否则外面连不进来 |
| **每 IP 限流**（600 次/分、音频 8 MB/分） | 公网上扫到端口就能发请求 |
| **音频总量上限**（1 GB） | 音频是**只追加、从不清空**的；不限的话灌满磁盘会把识别和系统一起拖死 |

> 转发进程对音频只追加不清空，是为了**不丢音频**（见 `relay/lan-relay.mjs` 里那段注释）——
> 这是个刻意的设计，所以"磁盘写满"必须用上限来防，而不是靠清理。

启动时会打印一份**公网清单**（TLS、安全组、systemd），照着做。

### 3.5 systemd 常驻

```ini
# /etc/systemd/system/glasses-harness.service
[Unit]
Description=Glasses simultaneous interpretation (relay + asr + brain)
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=glasses
WorkingDirectory=/opt/glasses-harness
EnvironmentFile=/etc/glasses-harness.env
ExecStart=/usr/bin/node scripts/start-all.mjs --public --data-dir /opt/glasses-harness/var/live --port 8788
Restart=always
RestartSec=3
# 日志进 journald，用 journalctl -u glasses-harness -f 看
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now glasses-harness
journalctl -u glasses-harness -f
```

> ⚠️ **别用 `nohup` 挂着**：服务器重启后不会自己起来，而"演示前发现服务没起"
> 是最没意义的失败。

## 4. TLS：**必须做**，推荐 Caddy

现在转发进程是**明文 HTTP**，手机把密钥和音频直接发在公网上。
绑到 `0.0.0.0` 之后，链路上任何人都能看到。

Caddy 自动申请并续期证书，配置只有三行：

```caddyfile
# /etc/caddy/Caddyfile
your.domain.com {
    reverse_proxy 127.0.0.1:8788
}
```

然后让转发进程**只监听回环**（外面由 Caddy 转发）：

```bash
node scripts/start-all.mjs --public --port 8788     # 注意：这时不需要 0.0.0.0
```

> ⚠️ **两个必须注意的点：**
>
> 1. **让 Caddy 覆盖 `X-Real-IP`。** 我们的限流是按 `X-Real-IP` 认客户端的，
>    而 Caddy/nginx 默认会设它。如果反代没设，所有请求会被算成同一个 IP
>    （都是反代的地址），**限流会把正常用户一起挡掉**。
>    （代码刻意**不采信** `X-Forwarded-For` 的第一个值 —— 那个客户端能随便伪造，
>    用它做限流等于没限流。）
> 2. 手机地址改成 `https://your.domain.com`（App 支持 `https://`，
>    密钥走 `X-Leion-Secret` 请求头，不在 URL 里）。

### 国内服务器的备案问题

- 用**域名 + 80/443** 在境内服务器上提供服务，通常需要 **ICP 备案**；
  没备案时云厂商可能直接封 80/443。
- **变通办法**：用高端口（例如 8443）跑 TLS，证书用 DNS-01 方式签发
  （不需要 80 端口）。Caddy 配 `tls { dns <provider> ... }` 即可。
- 如果暂时不想弄域名：用**纯 IP + HTTP** 也能跑通（密钥仍然有效，只是不加密）。
  **这对课程演示可以接受，但要清楚这是明文**，别在里面传敏感内容。

## 5. 安全组 / 防火墙

只放开你真正要用的端口：

```bash
# 服务器本机（如果开了 ufw）
sudo ufw allow 443/tcp          # 走 Caddy 时
# 或者直连时
sudo ufw allow 8788/tcp
```

云厂商控制台的**安全组也要开**（这一步比本机防火墙更容易忘 ——
现象是"本机 curl 通、外面连不上"）。

## 6. 手机侧怎么配

App 的「连接电脑」页：

| 字段 | 填什么 |
|---|---|
| 服务地址 | `https://your.domain.com` 或 `http://<公网IP>:8788` |
| 配对码 | 服务器启动时打印的那串（公网模式下是 48 个 hex） |

填完点 **「连接自检」**（不用先连接）。它会直接告诉你通到哪一层：

```
· TCP 1.2.3.4:8788 → ✅ 通（23 ms）
· HTTP /status → 200
     ✅ **链路和密钥都对** —— 手机会话应该能连上
     电脑那边：connections=1 · sockets=1 · frames=3 · inboxLines=2
```

四种结果对应四个不同的问题（见 `SelfCheck.java` 头部注释）：
TCP 超时 = 包没到；连接被拒 = 服务没起；401 = 配对码错；200 = 全通。

## 7. 上线前的验证清单

按顺序做，每一步都要有"可观察的证据"，不要靠感觉：

- [ ] `curl -s http://127.0.0.1:8788/status?secret=<密钥>` 在**服务器上**返回 JSON
- [ ] 从**手机浏览器**打开同一个地址 → 返回 JSON（证明公网可达）
- [ ] App 的「连接自检」→ TCP 通、HTTP 200
- [ ] 手机点「开始同传」，说话 → 服务器日志出现音频电平行（`peak/rms`）
- [ ] `var/live/asr-inbox.jsonl` 出现识别出来的句子
- [ ] `var/live/subtitle-bus.json` 出现译文帧
- [ ] 手机上看到字幕
- [ ] **眼镜上看到同一条字幕**（这一步才证明整条链路打通）
- [ ] 故意填错配对码 → 自检报 401（证明密钥校验真的在工作）
- [ ] `journalctl -u glasses-harness` 里没有反复重启

## 8. 如果服务器**没有**公网 IP

有些租的机器只在 NAT 后面，或者只给 SSH 端口。那就先把流量弄出来：

| 办法 | 适用 | 代价 |
|---|---|---|
| **frp / nps**（本机 frpc + 有公网 IP 的frps） | 最常用的组合 | 需要另一台有公网 IP 的机器 |
| **SSH 反向隧道** `ssh -R 8788:127.0.0.1:8788 user@vps` | 临时验证最省事 | 连接会断，要配 autossh |
| **Cloudflare Tunnel** | 不能开端口时 | 需要域名；国内访问 Cloudflare 不稳定 |
| **自建 WireGuard / headscale** | 想让手机、电脑、服务器三者互访 | 配置量大，但完全自主、不受污染影响 |

> ⚠️ **关于 Tailscale（公共控制面）**：在这台校园网上实测**走不通**。
> 本机 DNS 把 `login.tailscale.com` / `controlplane.tailscale.com` 解析到
> `192.200.0.101–116` 一小段连续地址（典型污染特征）；
> 而且它的守护进程是 LocalSystem 服务，**不使用浏览器的代理**，所以
> "浏览器能打开登录页" ≠ "tailscaled 能登录"。
> 真要用 mesh，请在**自己的国内服务器**上跑 headscale，而不是用公共控制面。

## 9. 已经做好的准备 / 还没做的

### 已经做好（这一轮）

| 项 | 位置 |
|---|---|
| `--public` 加固（强密钥 / 限流 / 音频上限） | `relay/lan-relay.mjs` |
| `--public` 从 start-all 透传（不漏参数） | `scripts/start-all.mjs` |
| 检出路径不再写死 Windows 路径 | `lib/real-tools.mjs` |
| 拒绝超大请求体后**不再污染连接** | `relay/lan-relay.mjs`（`sendAndClose`） |
| 被拒请求记录来源 IP（区分"密钥填错"和"有人在扫"） | `relay/lan-relay.mjs` |
| App 支持 `https://`、密钥走请求头、连接自检 | `android/`（`SelfCheck.java`） |

### 还没做（别以为已经好了）

- ❌ **没有在真实服务器上跑过一次** —— 上面所有命令都是按代码推导的
- ❌ 转发进程**没有内置 TLS**，要靠 Caddy 反代（也可以给它加 `--tls-cert`，尚未实现）
- ❌ 识别进程在服务器上的**首次模型下载**没验证过（镜像 + `HF_HOME` 按本机经验写的）
- ❌ **端到端延迟没测**（手机 ↔ 服务器这一段）
- ❌ 音频文件只追加不清空，长期跑需要**定期轮转**（当前只有 `--public` 的 1 GB 硬上限）
- ❌ 没有健康检查端点给负载均衡/监控用
