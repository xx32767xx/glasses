# 服务器部署（2026-10-25 实测版）

> 读者：要把这套同传系统放到一台带 GPU 的 Ubuntu 上、让手机通过公网连进来的人。
> 本文按"照着做就能起来"的顺序写，每节末尾都有**怎么验证**。
>
> 本版与旧版最大的不同：**命令都在真实服务器上跑过一遍**（Ubuntu + Tesla P40 + 公网 IP），
> 踩过的坑与"为什么会那样"另见 [`20-部署踩坑记录.md`](20-部署踩坑记录.md)。

## 0. 一页速览

```bash
# ① 系统依赖 + Node 20（apt 装的是 12/18，必须换 NodeSource）
sudo apt update && sudo apt install -y python3-venv python3-pip curl git ca-certificates
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash - && sudo apt install -y nodejs
node -v                                    # 必须 v20+

# ② Python 环境（cu12 运行库是关键，缺了只能跑 CPU）
git clone <仓库> ~/glasses && cd ~/glasses
python3 -m venv .venv && . .venv/bin/activate
pip install -U pip wheel
pip install faster-whisper numpy
pip install nvidia-cublas-cu12 "nvidia-cudnn-cu12==9.*"

# ③ 大脑要一份构建过的 deepseek-harness 检出
git clone <deepseek-harness 仓库> ~/deepseek-harness
cd ~/deepseek-harness && corepack enable && corepack prepare pnpm@latest --activate && pnpm install && pnpm build
export DSH_CHECKOUT="$HOME/deepseek-harness"

# ④ 模型（2.9 GB，断了重跑即续传）
cd ~/glasses
python3 scripts/fetch-model.py large-v3 --mirror

# ⑤ 数据目录（要归当前用户，否则 EACCES）
sudo mkdir -p /var/lib/leion && sudo chown "$USER": /var/lib/leion

# ⑥ 体检（六项，缺什么它直接说怎么修）
export HF_HOME=/opt/leion/models        # 或任意你有权限的位置
node scripts/preflight.cjs
python3 scripts/check-asr-env.py --models large-v3   # ③ 会告诉你这张卡该用哪档精度

# ⑦ 起服务
node scripts/start-all.mjs --public --data-dir /var/lib/leion/live --port 8788 \
     --whisper-model large-v3 --compute int8_float32

# ⑧ 验收（另开终端）
python3 scripts/check-relay.py --data-dir /var/lib/leion/live --say "这是一条测试信息"

# ⑨ 公网放行（安全组 + 防火墙），然后从外网验证
python3 scripts/check-relay.py --base http://<公网IP>:8788 --secret <密钥>
```

需要配的东西只有四样：`--data-dir`、`--port`、共享密钥（`--public` 自动生成强密钥）、
`HF_HOME`（模型缓存）。

## 1. 服务器要什么

| 项 | 要求 | 为什么 |
|---|---|---|
| **GPU** | N 卡，≥ 6 GB 显存 | large-v3 中文 3.9% 字错率；纯 CPU 只能退到 small（18.9%），每句 1.9 秒 |
| CPU / 内存 | 4 核 / ≥ 8 GB | 模型常驻，另有 Node 三个进程 |
| 磁盘 | ≥ 40 GB | 模型 2.9 GB + 音频只追加（16k 单声道 ≈ 115 MB/小时）+ DSH 检出 |
| 系统 | Ubuntu 22.04 / 24.04 | 脚本全是 Node，跨平台；本文命令按 Debian 系写 |
| **Node** | **≥ 20**（`apt` 装到的是 12.22/18，必须 NodeSource） | 用到 `??`、`fetch`、`node:test` |
| Python | 3.10+（3.10.12 实测可用） | faster-whisper |
| **DSH 检出** | 一份**已构建**的 `deepseek-harness` | 大脑必须跑在真实 DSH 工具运行时上 |
| 翻译凭据 | `DEEPSEEK_API_KEY` 或 `$DSH_HOME/.credentials.yaml` | 真实模型翻译（`--offline` 不需要） |
| 出网 | 能访问 DeepSeek API 与模型源 | 首次下模型；每句一次翻译调用 |

**端口**：对公只开 `8788`（验证阶段）或只开 `443`（有了 TLS 之后）。GPU 不需要对外。

### 1.1 老显卡（Tesla P40 / Pascal）该用哪档精度

Pascal（算力 6.1）**有 FP16 存储、没有 FP16 矩阵乘**，`ctranslate2` 在它上面**不提供**
`float16` / `int8_float16`。实测这台卡能跑：`float32, int8, int8_float32`；

| 档位 | 解码（3 秒音频） | RTF |
| --- | --- | --- |
| `int8_float32` | 668 ms | **0.22** |
| `int8` | 680 ms | **0.23** |
| `float32` | 更慢 | 不建议 |

**结论**：用 `--compute int8_float32`（与 int8 等价，精度更保险；也是自动兜底的档位）。
给错档位不会崩：`whisper_stream` 会查到这张卡支持什么、自动换档并打一行 ⚠️。
3 秒合成音的 RTF 不能和 `docs/04 §4`（真实语音切成 20 句）并列，要正式数字按那里复测。

## 2. 一次性准备

### 2.1 Node 20

```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs
node -v            # 必须 v20+
```

> ⚠️ 别用 `apt install nodejs`：22.04 装到 12.22，一跑 `.mjs` 就报
> `SyntaxError: Unexpected token '?'`（`??` 要 Node 14+）。
> 装完还是旧的就先 `sudo apt purge -y nodejs` 再装一遍。

### 2.2 本仓库 + Python 依赖

```bash
git clone <你的仓库地址> ~/glasses && cd ~/glasses
python3 -m venv .venv && . .venv/bin/activate
pip install -U pip wheel
pip install faster-whisper numpy                # 识别只用这两个
pip install nvidia-cublas-cu12 "nvidia-cudnn-cu12==9.*"    # GPU 必需（cu12 运行库）
```

- `ctranslate2` 要的是 **CUDA 12** 的运行库，不是 CUDA Toolkit。pip 的 `nvidia-*-cu12`
  把 `.so` 装进 `site-packages/nvidia/*/lib`，跟系统装没装 CUDA 无关。
- Node 没有任何运行时依赖（`package.json` 的 dependencies 是空的），不用 `npm install`。

### 2.3 大脑：deepseek-harness 检出

```bash
corepack enable && corepack prepare pnpm@latest --activate
git clone <deepseek-harness 仓库> ~/deepseek-harness
cd ~/deepseek-harness && pnpm install && pnpm build
ls packages/core/tools/lib/index.js          # 必须存在

export DSH_CHECKOUT="$HOME/deepseek-harness" # 临时；常驻见 §6
export DEEPSEEK_API_KEY=<你的 key>            # 或放 $DSH_HOME/.credentials.yaml
```

**只想先验证网络连通性？** 可以不启动大脑，单独起转发：

```bash
node relay/lan-relay.mjs --data-dir /var/lib/leion/live --port 8788 --public
```

### 2.4 模型（2.9 GB，只做一次）

```bash
export HF_HOME=/opt/leion/models          # 定好再下，之后别改
python3 scripts/fetch-model.py large-v3 --mirror
python3 scripts/fetch-model.py --list     # 期望：Systran/faster-whisper-large-v3  2.9 GB
```

> ⚠️ 国内直连官方源基本下不动，报错是 `[SSL: UNEXPECTED_EOF_WHILE_READING]` +
> `xet-read-token`。两个开关缺一不可：`HF_ENDPOINT=https://hf-mirror.com`
> 与 `HF_HUB_DISABLE_XET=1`（新版 huggingface_hub 默认走 Xet，镜像站不转 Xet 接口）。
> `fetch-model.py` 默认已经关掉 Xet。

### 2.5 数据目录

```bash
sudo mkdir -p /var/lib/leion && sudo chown "$USER": /var/lib/leion
```

> `/var/lib` 属于 root。不建目录直接 `--data-dir /var/lib/leion/live` 会
> `EACCES: permission denied, mkdir '/var/lib/leion'`（现在 `start-all` 会在起进程前就提示）。

里面的东西（**这就是全部状态，迁移时整目录搬走**）：

```
leion/live/
  accounts.json        账号（scrypt 哈希 + sha256 token，换机器不用重设密码）
  libraries/           术语库（管理员建的）
  meeting-terms/       当前这一场的会议术语（插件读的就是它）
  meetings/<会议id>/    历史归档（每场一份）
  relay-secret.txt     共享密钥（手机要填这个）
  asr-inbox.jsonl      收件箱（一行一句话）
  subtitle-bus.json    字幕总线（当前该显示的那一帧）
  audio-in.pcm         手机上传的音频（只追加，重启会清）
```

## 3. 启动与自检

### 3.1 手动起一次（推荐，能立刻看到报错）

```bash
cd ~/glasses && . .venv/bin/activate
export HF_HOME=/opt/leion/models
export LD_LIBRARY_PATH="$(python3 scripts/make-env-file.py .venv | grep '^LD_LIBRARY_PATH=' | cut -d= -f2-)"
export DSH_CHECKOUT="$HOME/deepseek-harness"

node scripts/start-all.mjs --public --data-dir /var/lib/leion/live --port 8788 \
     --whisper-model large-v3 --compute int8_float32
```

`--public` 做三件事（**绑公网必须加**）：强密钥（≥24 字符）+ 按 IP 限流 + 音频请求体上限，
并把密钥打进横幅 —— **抄下来，手机要用**。

横幅里要确认：

```
识别模型    large-v3 / cuda / int8_float32
数据目录    /var/lib/leion/live
术语来源    旧全局表 / 会议术语 N 条（会议 m-…）
共享密钥    <24 位以上>
```

### 3.2 一条命令验收（含大脑）

```bash
# 另开一个终端
python3 scripts/preflight.cjs                                   # 六项：Node/python3/数据目录/端口/模型/DSH
python3 scripts/check-relay.py --data-dir /var/lib/leion/live   # ②TCP ③hello ④status ⑤admin
python3 scripts/check-relay.py --data-dir /var/lib/leion/live --say "这是一条测试信息"
#   期望：⑦ 大脑链路 ✓ 译文到了：Esta é uma mensagem de teste
```

`--say` 失败时它会说查哪四处：进程 / `var/logs/brain.log` / 翻译凭据 / 先用 `--offline` 排除大脑。

想看实时字幕（服务端侧）：

```bash
node scripts/debug-window.mjs --data-dir /var/lib/leion/live \
     --url http://127.0.0.1:8788 --secret "$(cat /var/lib/leion/live/relay-secret.txt)"
```

## 4. 让手机连进来

### 4.1 先分清"能连自己"和"手机能连"

在**服务器上**测 `127.0.0.1` 或内网 IP 通过，**不代表**手机能连 —— `10.x` 是云主机内网地址。

三条路，按投入从小到大：

| 场景 | 做法 | 注意 |
| --- | --- | --- |
| 手机与服务器**同一局域网** | 手机直接填服务器内网 IP | 最干净，演示首选 |
| 服务器有**公网 IP** | 安全组放行 + 手机填公网地址 | 公网**必须**做 §4.3 的 TLS |
| 什么都没有（临时验证） | SSH 隧道 `ssh -L 0.0.0.0:8788:127.0.0.1:8788 ubuntu@<公网IP>`，手机连**笔记本**的局域网 IP | 只用于验证 |

### 4.2 公网 IP 有了、外面还是超时 → 入站没放行

**TCP 超时 = 包没送到进程**（"连接被拒"才是服务没起）。三步自证：

```bash
sudo ss -ltnp | grep 8788        # 必须看到 0.0.0.0:8788（只有 127.0.0.1 就不行）
sudo ufw status                  # inactive 跳过；active 就 sudo ufw allow 8788/tcp
ip -4 addr | grep -F '<公网IP>' || echo "公网 IP 不在本机网卡上（EIP/NAT 模式）"
```

云控制台放行（找到「安全组 / 防火墙 / 入站规则」即可，名字各厂商不同）：

- 阿里云：ECS → 安全组 → 配置规则 → 入方向 → `TCP / 8788 / 0.0.0.0/0`
- 腾讯云：云服务器 → 安全组 → 入站规则 → `TCP:8788`

**从外面验证**（Windows / Linux 均可）：

```powershell
Test-NetConnection -ComputerName <公网IP> -Port 8788      # Windows
```
```bash
python3 scripts/check-relay.py --base http://<公网IP>:8788 --secret <密钥>
```

> 用 8788 这种非标端口还有个好处：**80/443 走域名要备案，8788 不用**，验证阶段能马上开工。
> 但明文 http 上公网 = 密钥与会议音频裸奔，正式使用前必须做 §4.3。

**放行了还不通**，依次查：EIP 是否绑在这台实例（NAT 模式要网关侧映射）、子网 ACL、
你所在网络限制出站（换手机热点即可区分）、运营商封非标端口。

### 4.3 TLS（公网**必须做**，推荐 Caddy）

```bash
sudo apt install -y caddy
```

`/etc/caddy/Caddyfile`：

```
translate.example.com {
    reverse_proxy 127.0.0.1:8788
}
```

```bash
sudo systemctl reload caddy
```

然后把监听收回本机（二选一）：保持 `--host 0.0.0.0` 但安全组只放 443 与 SSH；
或加 `--host 127.0.0.1` 只让 Caddy 访问（更干净）。

**验证**：`curl https://translate.example.com/status?secret=<密钥>` 返回 JSON。

> 国内服务器上 80/443 的域名访问需要备案；没有域名可以先用 IP + 自签证书（手机要信任，麻烦）。

### 4.4 手机端配置

1. 设置里填地址（`https://你的域名` 或 `http://<IP>:8788`）+ 密钥（`relay-secret.txt`）
2. 账户：用管理员建的账号**登录**（用户名+密码），或走「注册」（邮箱 → 验证码 → 用户名密码）
3. 术语库页：勾选库 → 保存 → 顶部显示"本场会议术语 N 条"
4. 点「开始同传」说一句 → 服务器日志出现 `[术语] 新一场与会：会议 m-…`，字幕上眼镜

## 6. 交给 systemd（常驻 + 开机自启）

`/etc/systemd/system/glasses.service`：

```ini
[Unit]
Description=亮亮眼镜同传服务
After=network-online.target

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/home/ubuntu/glasses
# 数据与模型
Environment=HF_HOME=/opt/leion/models
# 大脑要用的 DSH 检出（漏了这行 → systemd 里找不到工具运行时）
Environment=DSH_CHECKOUT=/home/ubuntu/deepseek-harness
Environment=DEEPSEEK_API_KEY=<你的 key>
# 识别进程靠 PATH 里的 python 起
Environment=PATH=/home/ubuntu/glasses/.venv/bin:/usr/local/bin:/usr/bin:/bin
# 编码（不设识别结果可能变乱码）
Environment=PYTHONUTF8=1
Environment=PYTHONIOENCODING=utf-8
# cu12 运行库 + PATH 一起由脚本生成，别手抄
EnvironmentFile=/etc/leion/asr.env
ExecStart=/usr/bin/node scripts/start-all.mjs --public --data-dir /var/lib/leion/live --port 8788 \
          --whisper-model large-v3 --compute int8_float32
Restart=always
RestartSec=3
StandardOutput=append:/var/log/glasses.log
StandardError=append:/var/log/glasses.log

[Install]
WantedBy=multi-user.target
```

```bash
sudo mkdir -p /etc/leion
sudo python3 scripts/make-env-file.py ~/glasses/.venv --hf-home /opt/leion/models --out /etc/leion/asr.env
sudo systemctl daemon-reload && sudo systemctl enable --now glasses
sudo systemctl status glasses
```

> **手动能跑、systemd 起不来**，99% 是少了上面某一个 `Environment=`：
> `PATH`（venv 的 python）、`LD_LIBRARY_PATH`（cu12）、`DSH_CHECKOUT`（大脑）、
> `HF_HOME`（模型）。这四样都是"环境没带进去"，不是代码问题。

## 7. 排障表（按症状查）

| 症状 | 先看这里 | 常见原因 |
|---|---|---|
| `SyntaxError: Unexpected token '?'` | `node -v` | Node 太旧（apt 的 12.22）→ NodeSource，见 §2.1 |
| 大脑退出：`无法加载真实的 @deepseek-ai/dsh-tools` | `preflight.cjs` ⑥ | 没有/没构建 DSH 检出，或 systemd 少了 `DSH_CHECKOUT`，见 §2.3 |
| 识别退出：`EACCES ... mkdir '/var/lib/leion'` | `preflight.cjs` ③ | 数据目录上级属于 root，见 §2.5 |
| 首次识别慢得像卡住 | `fetch-model.py --list` | 模型没下，正在下 2.9 GB，见 §2.4 |
| `libcublas.so.12: cannot open shared object file` | `check-asr-env.py` ② | 缺 cu12 运行库 / 没设 `LD_LIBRARY_PATH`，见 §2.2 |
| Pascal 卡上 `float16` 起不来 | `check-asr-env.py` ③ | 用 `int8_float32`，见 §1.1 |
| 手机"连不上服务器" | `check-relay.py --base http://<IP>:8788` | 一条命令分清：服务没起 / 只听 127.0.0.1 / 防火墙 / 密钥错 |
| 服务器能连、外面超时 | `ss -ltnp \| grep 8788` | 安全组没放行入站，见 §4.2 |
| `/hello` 的 features 里没有 `auth`/`org` | 重启服务 | 跑的是旧进程 |
| 说了话没字幕 | `var/logs/asr.log` | 麦克风太远/增益低；`--silence-skip-level` 调到 0.01 |
| 静音时冒出"谢谢大家" | 同上 | 应 > 0.02 才进解码；把那段电平记下来 |
| 字幕出来但术语不生效 | 日志 `热词表：N 条（user=meeting:…）` | 还没"开始同传"过（会议术语未发布）/ 手机没勾库 |
| 音频文件越来越大 | `du -h /var/lib/leion/live/audio-in.pcm` | 只追加不清空；重启会清，或加定时任务 |

更细的"为什么"见 [`20-部署踩坑记录.md`](20-部署踩坑记录.md)。

## 8. 迁移（换机器 / 本地 → 服务器）

只搬**数据目录**（`accounts.json`、`libraries/`、`meeting-terms/`、`meetings/`）。
scrypt 哈希与 sha256 token 都是可移植的，**换机器不用重设密码**。

```bash
# 旧机器
tar czf leion-data.tgz -C /var/lib/leion live
# 新机器
sudo mkdir -p /var/lib/leion && sudo chown "$USER": /var/lib/leion
tar xzf leion-data.tgz -C /var/lib/leion
```

模型缓存（`HF_HOME`）也可以整目录搬，省一次 2.9 GB 下载。

> 环境不是机器属性，而是"数据目录"属性：同一份代码指向哪个目录就读写哪套数据。
> `var/live` 与 `var/live-test` 只是目录名约定，不是行为开关。

## 9. 安全须知（别跳）

1. **公网必须 TLS**，否则密钥与会议音频是明文。
2. `--public` 的强密钥要留好，泄露等于谁都能推字幕、上传音频。
3. **共享密钥轮换**：删 `relay-secret.txt` 重启即重新生成，手机端要同步改。
4. **管理员初始密码**建完立刻改。
5. 音频落盘含真实会议内容：注意目录权限与定期清理。
6. 别把 `DEEPSEEK_API_KEY` 写进仓库；放 systemd 的 `Environment=` 或 `$DSH_HOME/.credentials.yaml`。

## 10. 已知未验证 / 缺口（诚实标注）

- systemd 常驻与开机自启**还没在真实机器上跑过**（手动启动已跑通）。
- TLS 尚未启用：当前公网走的是明文 http。
- GPU 并发未测：设计是"一场同传一路音频"，多人同时说话要靠后续的**房间/发言权**模块。

- 没有健康检查端点给负载均衡；监控只能看 `/status`。
- 管理控制台没有"停用账号/续期"按钮（后端 `setAccountStatus` 已有，界面待补）。
- P40 上的 RTF 是 3 秒合成音、单句测的；真实会议语音的延迟与质量待复测（方法见 `docs/04 §4.1`）。
