# 服务器部署指南（2026-10-24 版）

> 读者：要把这套同传系统放到一台**带 GPU 的 Linux 服务器**上、让手机通过公网连上来的人。
> 本文按"照着做就能起来"的顺序写，每一节末尾都有**怎么验证**。
>
> 与旧版的区别：账号改了（注册=邮箱+用户名+密码+验证码，登录=用户名+密码）、
> 术语改成"开会即发布"的会议术语、多了管理控制台 `/admin`、
> `--libraries`/`--meeting` 参数已删除。**旧文档里那些参数现在会报"未知选项"。**

---

## 0. 一页速览

```bash
# 服务器上（一次性）
git clone <仓库> /opt/glasses-harness && cd /opt/glasses-harness
python3 -m venv .venv && . .venv/bin/activate && pip install faster-whisper numpy
node --version            # 需要 ≥ 20

# 每次开机（或交给 systemd）
node scripts/start-all.mjs --public --data-dir /opt/glasses-data --port 8788
```

需要配的东西**只有四样**：`--data-dir`、`--port`、共享密钥（`--public` 会自动生成强密钥）、
`HF_HOME`（模型缓存，start-all 会自动指到 `var/cache/hf`）。

---

## 1. 服务器要什么

| 项 | 要求 | 为什么 |
|---|---|---|
| **GPU** | 强烈建议（N 卡 + ≥ 6 GB 显存） | large-v3 中文 3.9% 字错率；纯 CPU 只能退到 small（18.9%），且每句 1.9 秒 |
| CPU / 内存 | 4 核 / ≥ 8 GB | 模型常驻，另有 Node 三个进程 |
| 磁盘 | ≥ 40 GB | 模型缓存约 3 GB + 音频只追加不清空（16k 单声道 ≈ 115 MB/小时） |
| 系统 | Ubuntu 22.04 / Debian 12 | 脚本全是 Node，跨平台；但本文命令按 Debian 系写 |
| Node | **≥ 20** | 用到 `fetch`、`node:test` |
| Python | 3.10+ | faster-whisper |
| 出网 | 要能访问翻译 API（DeepSeek）与模型源 | 首次要下模型；翻译每句一次调用 |

**端口**：只开 `8788`（转发）。TLS 由反代在 443 收。GPU 不需要对外。

## 2. 一次性准备

### 2.1 拉代码 + Python 依赖

```bash
sudo mkdir -p /opt && cd /opt
git clone <你的仓库地址> glasses-harness
cd glasses-harness

python3 -m venv .venv
. .venv/bin/activate
pip install -U pip
pip install faster-whisper numpy        # 识别只用这两个
node --version                           # 必须 ≥ 20
```

> Node **没有任何运行时依赖**（`package.json` 的 dependencies 是空的），所以不用 `npm install`。
> 这条路是刻意的：服务器上少一个包源就少一类事故。

### 2.2 首次下模型（约 3 GB，只做一次）

```bash
export HF_HOME=/opt/glasses-harness/var/cache/hf
export HF_ENDPOINT=https://hf-mirror.com      # 服务器在墙内时用镜像；墙外可去掉
python - <<'PY'
from faster_whisper import WhisperModel
WhisperModel("large-v3", device="cuda", compute_type="float16")   # 触发下载
print("模型就绪")
PY
```

**验证**：`ls $HF_HOME/hub | grep large-v3` 能看到 `models--Systran--faster-whisper-large-v3`。

> ⚠️ `HF_HOME` 不设的话，`start-all` 会自动指到 `var/cache/hf`（仓库内）。
> 如果你把仓库放在只读目录或想共用缓存，就显式设成别处 —— **换机器时这一条最容易忘**。

### 2.3 建数据目录

```bash
sudo mkdir -p /opt/glasses-data && sudo chown $USER /opt/glasses-data
```

里面会长出这些（**这就是全部状态，迁移时整目录搬走即可**）：

```
glasses-data/
  accounts.json        账号（密码 scrypt 哈希、token sha256 —— 换机器不用重设密码）
  libraries/           术语库（管理员建的）
  meeting-terms/       当前这一场的会议术语（插件读的就是它）
  meetings/<会议id>/    历史归档（每场一份，含 meta.json）
  terms.json           旧模型的全局热词表（向后兼容，新部署可忽略）
  audio-in.pcm         录音（只追加；需要定期清理）
  relay-secret.txt     共享密钥（--public 模式自动生成强密钥）
  asr-inbox.jsonl      收件箱       subtitle-bus.json  字幕总线
```

## 3. 启动

### 3.1 先手动起一次（推荐，能立刻看到报错）

```bash
cd /opt/glasses-harness
. .venv/bin/activate
node scripts/start-all.mjs --public --data-dir /opt/glasses-data --port 8788
```

`--public` 做了三件事（**绑公网必须加**）：强密钥（至少 24 字符）+ 按 IP 限流 + 音频请求体上限，
并在启动横幅里把密钥打印出来 —— **把它抄下来，手机要用**。

启动横幅里要确认这几行：

```
识别模型    large-v3 / cuda / float16
数据目录    /opt/glasses-data
术语来源    旧的全局表：…（或"会议术语 N 条（会议 m-…）"）
共享密钥    <24 位以上>
```

### 3.2 交给 systemd（常驻 + 开机自启）

`/etc/systemd/system/glasses.service`：

```ini
[Unit]
Description=亮亮眼镜同传服务
After=network-online.target

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/opt/glasses-harness
Environment=HF_HOME=/opt/glasses-harness/var/cache/hf
Environment=PYTHONUTF8=1
Environment=PYTHONIOENCODING=utf-8
# 用 venv 里的 python，别依赖系统 python
Environment=PATH=/opt/glasses-harness/.venv/bin:/usr/local/bin:/usr/bin:/bin
ExecStart=/usr/bin/node scripts/start-all.mjs --public --data-dir /opt/glasses-data --port 8788
Restart=always
RestartSec=3
StandardOutput=append:/var/log/glasses.log
StandardError=append:/var/log/glasses.log

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now glasses
sudo systemctl status glasses          # active (running)
journalctl -u glasses -f               # 或 tail -f /var/log/glasses.log
```

> `PYTHONUTF8=1` 不能省：不设的话识别结果会在某些 locale 下变乱码。

## 4. TLS：**必须做**（推荐 Caddy）

转发进程**没有内置 TLS**，公网上明文传密钥和音频是不能接受的。

```bash
sudo apt install -y caddy
```

`/etc/caddy/Caddyfile`：

```
translate.example.com {
    reverse_proxy 127.0.0.1:8788
}
```

```bash
sudo systemctl reload caddy
```

然后把 `start-all` 的 `--port` 对应的监听收回本机（二选一）：

- 保持 `--host 0.0.0.0` 但用安全组只放行 443（Caddy）与 SSH；
- 或加 `--host 127.0.0.1`，只让 Caddy 访问（更干净）。

**验证**：`curl https://translate.example.com/status?secret=<密钥>` 应返回 JSON。

> 国内服务器要先备案；没有域名可以先用 IP + 自签证书（手机需要信任，麻烦），
> 更实际的是申请一个便宜域名。

## 5. 首次上线核对清单（照着打勾）

```bash
# ① 服务活着
curl -s "http://127.0.0.1:8788/hello?secret=<密钥>" | head -c 200
#   期望：{"ok":true,...,"features":["hello",...,"org"]}

# ② 管理页能开（先建一个管理员，见下）
curl -sI "http://127.0.0.1:8788/admin?secret=<密钥>" | head -1
#   期望：HTTP/1.1 200 OK
```

**建管理员**（账号模型：登录=用户名+密码）：

```bash
cd /opt/glasses-harness
node scripts/terms-admin.mjs admin    --env prod --root /opt/glasses-data --username boss --password '<换成强密码>' --email you@example.com
node scripts/terms-admin.mjs accounts --env prod --root /opt/glasses-data   # 确认 boss/admin/active
```

> `--env prod` 对应 `var/live`；服务器上数据目录是 `/opt/glasses-data`，
> 所以要么把 `--base` 指过去，要么直接在数据目录里跑（见 §7 的"数据目录与 CLI 的对应"）。

**然后在浏览器**打开 `https://translate.example.com/admin?secret=<密钥>`：

1. **全屏登录**：填密钥 + `boss` + 密码 → 进控制台
2. 「当前会议术语」应显示"还没有会议术语"（正常，还没开始过同传）
3. 「账号」→ 加一个 dev 测试账号（用户名+密码，默认 7 天过期）
4. 「批量导入」→ 建一两个库（或用「填入示例」）

**手机端**：

1. 设置里填地址 `https://translate.example.com`（或 `http://<服务器IP>:8788`）、密钥
2. 账户：用刚加的测试账号**登录**（用户名+密码）；或走「注册」（邮箱 → 取码 → 用户名密码）
3. 术语库页：勾选库 → 保存 → 顶部应显示"本场会议术语 N 条"
4. 点「开始同传」说一句 → 服务器日志应出现
   `[术语] 新一场与会：会议 m-…，N 条`，字幕应使用勾选库里的写法

## 6. 排障表（按症状查）

| 症状 | 先看这里 | 常见原因 |
|---|---|---|
| 手机上"注册失败/not-found" | `/hello` 的 `features` 里有没有 `auth`、`org` | 服务器上跑的是**旧进程**：重启 `systemctl restart glasses` |
| 管理页 401 `X-Leion-Secret` | URL 是否带 `?secret=`，或页面顶部那格 | 密钥填错/没填 |
| 管理页能开，但账号/库报 401 | 是否已登录 | 控制台需要先登录拿 token |
| 字幕出来了，但术语不生效 | 日志 `热词表：N 条（user=meeting:…）` | ① 还没"开始同传"过（会议术语未发布）；② 手机没勾库 |
| 说了话没字幕 | 日志里有没有"近乎静音…解码前丢弃" | 麦克风太远/增益太低；把 `--silence-skip-level` 调到 0.01 再试 |
| 静音时冒出"谢谢大家/中文字幕" | 同上 | 若仍出现，把那段电平记下来（应 > 0.02 才会进解码） |
| 首次识别慢得像卡住 | `HF_HOME` | 没设就会重下模型 |
| 端口被占 | `ss -lntp \| grep 8788` | 旧进程没停干净 |
| 音频文件越来越大 | `du -h /opt/glasses-data/audio-in.pcm` | 只追加不清空；重启会清，或加定时任务 |

## 7. 数据目录与 CLI 的对应（容易搞混的一条）

- `start-all --data-dir /opt/glasses-data` → 服务读写 `/opt/glasses-data`；
- `scripts/terms-admin.mjs --env prod`（不给别的）→ 读写 `<仓库>/var/live`，**不是**服务器目录。

两者对上用 **`--root`**（2026-10-24 新增，直接指定数据目录，不要求目录名叫 live/live-test）：

```bash
node scripts/terms-admin.mjs admin    --env prod --root /opt/glasses-data --username boss --password '...'
node scripts/terms-admin.mjs accounts --env prod --root /opt/glasses-data
```

> 日常管理尽量用**管理控制台**（`/admin`），它天然和 relay 用同一个数据目录；
> CLI 只在"还没有管理员、进不去控制台"时用一次。

## 7.5 本地 vs 服务器：谁算"生产"、谁算"测试"？

**结论：环境不是机器属性，而是"数据目录"属性。** 同一份代码，指向哪个目录就读写哪套数据。

| 位置 | 建议数据目录 | 说明 |
|---|---|---|
| 服务器 | `/opt/glasses-data` | 正式数据（管理端建库、手机会议术语都落这里） |
| 家里 / 开发机 | `var/live` | 本地默认；随便折腾不影响服务器 |
| 本地做实验 | `var/live-test` | 与上面那套物理隔离（CLI 的 `--env test` 就是它） |

三条容易踩的：

1. **CLI 的 `--env prod|test` 只是目录名约定**，不改变任何服务行为；服务器目录叫
   `glasses-data` 对不上这个约定，所以要用 `--root /opt/glasses-data`。
2. 启动横幅会打印 **「数据目录环境」**（生产 / 本地默认 / 测试 / 自定义）——
   它只是标签，但能立刻看出"我在改哪套数据"。
3. **两套数据不要互相指**：拿本地机器去读写服务器目录（网络盘 / 挂载），
   等于在家里直接改生产 —— 出问题时日志里看不出来。

## 7.6 显存只有 4 GB 的机器能当服务器吗？

**能，但要把模型或精度降一档。** 下面显存与耗时都是**估算**（本项目只在 8 GB 卡上实测过）：

| 模型 / 精度 | 显存占用（估） | 中文字错率 | 每段耗时（估） |
|---|---|---|---|
| large-v3 / float16（缺省） | ~5 GB | **3.9%**（实测） | 基准 1× |
| large-v3 / int8_float16 | ~3 GB | 约 4%（略降） | 1.3~1.8× |
| medium / float16 | ~2.5 GB | **7.4%**（实测） | 更快 |
| medium / int8_float16 | ~2 GB | 约 7~8% | 1.3~1.8× |
| small / CPU（int8） | 0（走内存） | 18.9%（实测） | 1.9 秒/句，接近不可用 |

```bash
# 4GB 卡稳妥档：medium + 量化
node scripts/start-all.mjs --public --data-dir /opt/glasses-data --whisper-model medium --compute int8_float16

# 想尽量保精度：large-v3 + 量化（显存紧、可能 OOM，先试）
node scripts/start-all.mjs --public --data-dir /opt/glasses-data --compute int8_float16
```

> ⚠️ **显存放不下时 ctranslate2 直接抛错，不会自动降级**。顺序是：先 `--compute int8_float16`
> 跑 large-v3 → 报 OOM 就换 `--whisper-model medium`。
> 判断标准不是"能不能起来"，而是**说一句要等多久**（看日志里的 `RTF` 与"识别"耗时）。

### 用家里电脑当服务器，还要解决三件事

1. **公网可达**：家庭宽带通常没有公网 IP。三条路 ——
   · 端口转发 + DDNS（要有公网 IP，IPv4 现在很少给）；
   · **Cloudflare Tunnel / Tailscale Funnel**（不需要公网 IP，建议先试）；
   · 一台便宜小 VPS 只做反代，家里电脑主动外连（与 §4 的 TLS 逻辑一致）。
2. **稳定性**：休眠、断电、驱动更新都会让服务消失 —— 至少关掉休眠、设开机自启。
3. **TLS**：无论哪条路，手机侧都要 https（否则密钥与音频明文）。

## 8. 迁移（换机器 / 本地 → 服务器）

1. 停旧服务：`systemctl stop glasses`
2. 只搬三样：`accounts.json`、`libraries/`、`meeting-terms/`（想留历史再加 `meetings/`）
3. 新机器上启动即可：**密码不用重设**（scrypt 哈希原样可用），token 也是 sha256（旧 token 继续有效，若想强制重登就删 `accounts.json` 里的 `tokens`）

```bash
rsync -av --progress old:/opt/glasses-data/accounts.json  new:/opt/glasses-data/
rsync -av --progress old:/opt/glasses-data/libraries/     new:/opt/glasses-data/
rsync -av --progress old:/opt/glasses-data/meeting-terms/ new:/opt/glasses-data/
```

## 9. 安全须知（别跳）

1. **`--public` 必须加**：否则密钥是 6 位、无限流；绑公网等于开门。
2. **必须走 TLS**：密钥与音频都在头/体里明文传。
3. **`/admin` 只在 TLS 后面暴露**；它没有独立鉴权（靠共享密钥 + 登录 token 两层）。
4. **共享密钥轮换**：删 `relay-secret.txt` 重启即可（会重新生成），手机端要同步改。
5. **管理员的初始密码**：建完立刻改（CLI 改密码命令尚未提供，可先删账号重建）。
6. **音频落盘含真实会议内容**：注意磁盘权限与定期清理。

## 10. 已知未验证 / 缺口（诚实标注）

- 本文的命令**没有在真实服务器上完整跑过一遍**（当前只在开发机验证了 start-all/relay/管理页的接口与流程）。
- systemd 单元与 Caddy 配置是按代码推导的，第一次部署请**逐条对日志**。
- 转发进程没有内置 TLS（靠反代）。
- 没有健康检查端点给负载均衡；监控只能看 `/status`。
- `audio-in.pcm` 只追加不清空，长期跑需要定时轮转（或每天重启）。
- GPU 上并发能力未测：目前设计是"一场同传一路音频"，多人同时说话要靠后续的房间/发言权模块。
- 管理控制台没有"停用账号/续期"按钮（后端 `setAccountStatus` 已有，界面待补）。
