# 服务器部署指南（2026-10-24 版）

> 读者：要把这套同传系统放到一台**带 GPU 的 Linux 服务器**上、让手机通过公网连上来的人。
> 本文按"照着做就能起来"的顺序写，每一节末尾都有**怎么验证**。
>
> 与旧版的区别：账号改了（注册=邮箱+用户名+密码+验证码，登录=用户名+密码）、
> 术语改成"开会即发布"的会议术语、多了管理控制台 `/admin`、
> `--libraries`/`--meeting` 参数已删除。**旧文档里那些参数现在会报"未知选项"。**

## 0. 一页速览

```bash
# 服务器上（一次性）
git clone <仓库> /opt/glasses-harness && cd /opt/glasses-harness
python3 -m venv .venv && . .venv/bin/activate && pip install faster-whisper numpy
pip install nvidia-cublas-cu12 "nvidia-cudnn-cu12==9.*"   # GPU 必需：cu12 运行库（见 §9.5 / §9.6）
node --version            # 需要 ≥ 20

# 交给 systemd 前，用它算出 PATH / LD_LIBRARY_PATH（别手抄）
python3 scripts/make-env-file.py .venv --hf-home var/cache/hf

# 每次开机（或交给 systemd）
node scripts/start-all.mjs --public --data-dir /opt/glasses-data --port 8788
```

需要配的东西**只有四样**：`--data-dir`、`--port`、共享密钥（`--public` 会自动生成强密钥）、
`HF_HOME`（模型缓存，start-all 会自动指到 `var/cache/hf`）。

GPU 库的两种装法：**conda** 看 §9.5，**裸机 venv（不用 conda）** 看 §9.6。

## 1. 服务器要什么

| 项 | 要求 | 为什么 |
|---|---|---|
| **GPU** | 强烈建议（N 卡 + ≥ 6 GB 显存） | large-v3 中文 3.9% 字错率；纯 CPU 只能退到 small（18.9%），且每句 1.9 秒。**Pascal 卡（Tesla P40 等）也能用，但精度要用 `int8_float32`，见 §9.7** |
| CPU / 内存 | 4 核 / ≥ 8 GB | 模型常驻，另有 Node 三个进程 |
| 磁盘 | ≥ 40 GB | 模型缓存约 3 GB + 音频只追加不清空（16k 单声道 ≈ 115 MB/小时） |
| 系统 | Ubuntu 22.04 / Debian 12 | 脚本全是 Node，跨平台；但本文命令按 Debian 系写 |
| Node | **≥ 20**（⚠️ `apt install nodejs` 装到的是 **12.22**（22.04）或 18.x（24.04），都得换 NodeSource，见 §9.6 步骤 6） | 用到 `fetch`、`node:test`、`??` |
| Python | 3.10+ | faster-whisper |
| 出网 | 要能访问翻译 API（DeepSeek）与模型源 | 首次要下模型；翻译每句一次调用 |
| **DSH 检出** | 一份已构建的 `deepseek-harness`（见 §2.0） | 大脑要跑在真实的 DSH 工具运行时上；缺了它 `start-all` 会在第三个进程退出 |
| 翻译凭据 | `DEEPSEEK_API_KEY` 或 `$DSH_HOME/.credentials.yaml` | 真实模型翻译；离线例句表不需要 |

**端口**：只开 `8788`（转发）。TLS 由反代在 443 收。GPU 不需要对外。

## 2. 一次性准备

### 2.0 前置：大脑需要一份 deepseek-harness 检出（最容易漏的一条）

`start-all` 会起三个进程：转发（relay）、识别（asr-bridge）、**大脑**（`harness-side.mjs`）。
大脑负责调大模型做翻译，它**必须跑在真实的 DSH 工具运行时上** —— 也就是这台机器上
要有一份 `deepseek-harness` 检出，而且**已经构建过**：

```
<检出>/packages/core/tools/lib/index.js     ← 有这个东西才算"可用"
```

> 为什么不能省：`lib/real-tools.mjs` 是**故意拒绝降级**的。仿一个校验器能跑起来，
> 但会给假的"契约没问题"的安全感（历史上就放过 `output.schema` 写成原始 JSON Schema 这种
> 真实环境必然失败的写法）。

```bash
# Node ≥ 20 + pnpm（见 §9.6 步骤 6；检出要 2~3 GB 磁盘）
corepack enable && corepack prepare pnpm@latest --activate

cd ~
git clone <deepseek-harness 仓库地址> deepseek-harness
cd deepseek-harness
pnpm install
pnpm build
ls packages/core/tools/lib/index.js      # 必须存在

# 指向它（临时；常驻要用 systemd 的 Environment=，见 §3.2）
export DSH_CHECKOUT="$HOME/deepseek-harness"
```

**翻译凭据**（大脑调真实模型时才需要；`--offline` 不需要）：

- `export DEEPSEEK_API_KEY=...`，或
- 放在 `$DSH_HOME/.credentials.yaml` 里（DSH 的凭据存储）

**只想先验证网络连通性？** 完全可以不启动大脑，只起转发进程：

```bash
node relay/lan-relay.mjs --data-dir /var/lib/leion/live --port 8788 --public
```

**检查这一步是否就绪**：`node scripts/preflight.cjs` 的第 ⑥ 项。

### 2.1 拉代码 + Python 依赖

```bash
sudo mkdir -p /opt && cd /opt
git clone <你的仓库地址> glasses-harness
cd glasses-harness

python3 -m venv .venv
. .venv/bin/activate
pip install -U pip
pip install faster-whisper numpy        # 识别只用这两个
node --version                           # 必须 ≥ 20
```

> **用 GPU 的话再加一步**（cu12 运行库，缺了会退回 CPU 或直接报错）：
>
> ```bash
> pip install nvidia-cublas-cu12 "nvidia-cudnn-cu12==9.*"
> python3 scripts/make-env-file.py .venv      # 看算出来的 LD_LIBRARY_PATH，并确认依赖齐
> ```
>
> 细节与踩坑：conda 环境见 §9.5，裸机（不用 conda）见 §9.6。

> Node **没有任何运行时依赖**（`package.json` 的 dependencies 是空的），所以不用 `npm install`。
> 这条路是刻意的：服务器上少一个包源就少一类事故。

### 2.2 首次下模型（2.9 GB，只做一次）

```bash
export HF_HOME=/opt/glasses-harness/var/cache/hf

# 推荐：用仓库里的脚本下（可续传、支持镜像、默认关掉 Xet）
python3 scripts/fetch-model.py large-v3 --mirror      # 墙外就去掉 --mirror

# 已经下了一半？重跑同一条命令即可（缓存按文件续传）
python3 scripts/fetch-model.py --list                 # 看缓存里都有什么、占多大
```

`large-v3` 实测占 **2.9 GB**（`--list` 会打印真实大小）。

**验证**：`python3 scripts/fetch-model.py --list` 里能看到
`Systran/faster-whisper-large-v3  2.9 GB`。

> ⚠️ **国内直连官方源基本下不动**，而且报错长这样（很容易被误判成"环境装坏了"）：
>
> ```
> '[SSL: UNEXPECTED_EOF_WHILE_READING] EOF occurred in violation of protocol'
> Retrying in 1s [Retry 1/5]. ...
> https://huggingface.co/api/models/.../xet-read-token/edac...
> ```
>
> 两个开关解决，缺一不可：
>
> ```bash
> export HF_ENDPOINT=https://hf-mirror.com    # ① 换镜像
> export HF_HUB_DISABLE_XET=1                 # ② 关掉 Xet 传输（镜像站不转 Xet 接口）
> ```
>
> 新版 `huggingface_hub` 默认用 Xet 传大文件，所以**只设镜像、不关 Xet 仍会报上面那个 SSL 错**。
> `scripts/fetch-model.py` 默认已经把 ② 打开，这就是推荐用它而不是手搓 `WhisperModel` 的原因。

> ⚠️ `HF_HOME` 不设的话，`start-all` 会自动指到 `var/cache/hf`（仓库内）。
> 如果你把仓库放在只读目录或想共用缓存，就显式设成别处 —— **换机器时这一条最容易忘**。

### 2.3 建数据目录

```bash
sudo mkdir -p /opt/glasses-data && sudo chown "$USER": /opt/glasses-data
```

> **如果你打算用 `/var/lib/leion/live` 这类路径，也要先建好并改属主** —— `/var/lib` 属于 root，
> 直接 `--data-dir /var/lib/leion/live` 会在识别进程启动时 `EACCES: permission denied, mkdir '/var/lib/leion'`：
>
> ```bash
> sudo mkdir -p /var/lib/leion && sudo chown "$USER": /var/lib/leion
> ```
>
> 现在 `start-all` 在起进程**之前**就会试写一次，并直接打印上面的修法；
> `node scripts/preflight.cjs` 的第 ③ 项也会提前报出来。

里面会长出这些（**这就是全部状态，迁移时整目录搬走即可**）：

```
glasses-data/
  accounts.json        账号（密码 scrypt 哈希、token sha256 —— 换机器不用重设密码）
  libraries/           术语库（管理员建的）
  meeting-terms/       当前这一场的会议术语（插件读的就是它）
  meetings/<会议id>/    历史归档（每场一份，含 meta.json）
  terms.json           旧模型的全局热词表（向后兼容，新部署可忽略）
  audio-in.pcm         录音（只追加；需要定期清理）
  relay-secret.txt     共享密钥（--public 模式自动生成强密钥）
  asr-inbox.jsonl      收件箱       subtitle-bus.json  字幕总线
```

## 3. 启动

### 3.1 先手动起一次（推荐，能立刻看到报错）

```bash
cd /opt/glasses-harness
. .venv/bin/activate
node scripts/start-all.mjs --public --data-dir /opt/glasses-data --port 8788
```

`--public` 做了三件事（**绑公网必须加**）：强密钥（至少 24 字符）+ 按 IP 限流 + 音频请求体上限，
并在启动横幅里把密钥打印出来 —— **把它抄下来，手机要用**。

启动横幅里要确认这几行：

```
识别模型    large-v3 / cuda / float16
数据目录    /opt/glasses-data
术语来源    旧的全局表：…（或"会议术语 N 条（会议 m-…）"）
共享密钥    <24 位以上>
```

### 3.2 交给 systemd（常驻 + 开机自启）

`/etc/systemd/system/glasses.service`：

```ini
[Unit]
Description=亮亮眼镜同传服务
After=network-online.target

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/opt/glasses-harness
Environment=HF_HOME=/opt/glasses-harness/var/cache/hf
Environment=PYTHONUTF8=1
Environment=PYTHONIOENCODING=utf-8
# 大脑要用的 DSH 检出（见 §2.0）；漏了这一行 systemd 里就找不到大脑的工具运行时
Environment=DSH_CHECKOUT=/home/ubuntu/deepseek-harness
# 真实模型翻译的凭据（也可以放在 $DSH_HOME/.credentials.yaml 里）
Environment=DEEPSEEK_API_KEY=<你的 key>
# 用 venv 里的 python，别依赖系统 python
Environment=PATH=/opt/glasses-harness/.venv/bin:/usr/local/bin:/usr/bin:/bin
ExecStart=/usr/bin/node scripts/start-all.mjs --public --data-dir /opt/glasses-data --port 8788
Restart=always
RestartSec=3
StandardOutput=append:/var/log/glasses.log
StandardError=append:/var/log/glasses.log

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now glasses
sudo systemctl status glasses          # active (running)
journalctl -u glasses -f               # 或 tail -f /var/log/glasses.log
```

> `PYTHONUTF8=1` 不能省：不设的话识别结果会在某些 locale 下变乱码。

## 4. TLS：**必须做**（推荐 Caddy）

转发进程**没有内置 TLS**，公网上明文传密钥和音频是不能接受的。

```bash
sudo apt install -y caddy
```

`/etc/caddy/Caddyfile`：

```
translate.example.com {
    reverse_proxy 127.0.0.1:8788
}
```

```bash
sudo systemctl reload caddy
```

然后把 `start-all` 的 `--port` 对应的监听收回本机（二选一）：

- 保持 `--host 0.0.0.0` 但用安全组只放行 443（Caddy）与 SSH；
- 或加 `--host 127.0.0.1`，只让 Caddy 访问（更干净）。

**验证**：`curl https://translate.example.com/status?secret=<密钥>` 应返回 JSON。

> 国内服务器要先备案；没有域名可以先用 IP + 自签证书（手机需要信任，麻烦），
> 更实际的是申请一个便宜域名。

### 4.1 "在服务器上能连上自己"≠"手机能连上"

一条容易误判的经验：在服务器上跑

```bash
python3 scripts/check-relay.py --base http://10.0.0.12:8788 --secret <密钥>
```

**通过了也不代表手机能连** —— 那个 `10.x` 是云主机的**内网地址**，同机/同 VPC 内当然通，
但手机不在这个 VPC 里就完全够不着（而且 `10.x` 本来就不可能被公网路由）。

判断方式：**换一台机器测**（你的笔记本，且不要挂在 VPN 上）：

```bash
python3 scripts/check-relay.py --base http://<你在服务器上看到的内网IP>:8788 --secret <密钥>
```

- **超时** → 手机也一定连不上，得先解决下面三件事之一；
- **连接被拒** → 地址通了但没人在听（服务停了 / 端口不对）。

三条路，按投入从小到大：

| 场景 | 做法 | 注意 |
| --- | --- | --- |
| **手机和服务器同一个局域网** | 手机直接填服务器局域网 IP | 这条路最干净，练手/demo 首选 |
| **服务器有公网 IP / EIP** | 安全组放行 8788（或只放 443）→ 手机填公网地址 | **公网必须配 §4 的 TLS**，明文等于裸奔 |
| **什么都没有（临时验证）** | SSH 隧道：把服务器端口映射到你笔记本，手机连笔记本 | 只用于验证，不要长期这么跑 |

SSH 隧道（临时验证手机能不能连）——在**笔记本**上执行：

```bash
ssh -L 0.0.0.0:8788:127.0.0.1:8788 ubuntu@<服务器公网IP>
# 即使服务器没有公网 IP，只要有跳板/端口映射也行；关键是本机能 SSH 进去
```

然后手机填 `http://<笔记本的局域网IP>:8788`（笔记本防火墙要放行 8788）。
先在本机确认隧道通了，再让手机连：

```bash
python3 scripts/check-relay.py --base http://127.0.0.1:8788 --secret <密钥>
```

> ⚠️ 隧道方案里流量是"手机 → 笔记本 → SSH → 服务器"，仍然有明文段，**只用于内部验证**。

## 5. 首次上线核对清单（照着打勾）

```bash
# ⓿ 环境体检（只检查不改动；Node 太旧这类问题在这里就说清楚了）
node scripts/preflight.cjs
#   期望：① Node ≥ 20 / ② python3 / ③ 数据目录可写 / ④ 端口空闲 / ⑤ 模型已在缓存，全绿

# ① 服务活着
curl -s "http://127.0.0.1:8788/hello?secret=<密钥>" | head -c 200
#   期望：{"ok":true,...,"features":["hello",...,"org"]}

# ② 管理页能开（先建一个管理员，见下）
curl -sI "http://127.0.0.1:8788/admin?secret=<密钥>" | head -1
#   期望：HTTP/1.1 200 OK

# ②' 模型真在本地（不在的话第一次识别会去下 2.9 GB，看起来像卡住）
python3 scripts/fetch-model.py --list
#   期望：Systran/faster-whisper-large-v3  2.9 GB

# ③ 一条命令把上面全测一遍（推荐；手机连之前先在这台机器/另一台电脑上跑）
python3 scripts/check-relay.py --data-dir /opt/glasses-data
#   期望：② TCP ✓ / ③ hello ✓ / ④ status ✓ / ⑤ admin ✓

# ④ 再测一次"大脑到底能不能翻译"（塞一句话进收件箱，等译文）
python3 scripts/check-relay.py --data-dir /opt/glasses-data --say "这是一条测试信息"
#   期望：⑦ 大脑链路 ✓ 译文到了：Esta é uma mensagem de teste
#   没等到就看它给出的四条排查（进程 / 大脑日志 / 翻译凭据 / 先用 --offline 排除大脑）
```

**从另一台电脑测局域网连通性**（这一步才真正验证防火墙与监听地址）：

```bash
python3 scripts/check-relay.py --base http://<服务器IP>:8788 --secret <密钥>
# 连不上就看它给出的三条提示：服务没起 / 只听 127.0.0.1（要 --public）/ 防火墙没放行
```

**建管理员**（账号模型：登录=用户名+密码）：

```bash
cd /opt/glasses-harness
node scripts/terms-admin.mjs admin    --env prod --root /opt/glasses-data --username boss --password '<换成强密码>' --email you@example.com
node scripts/terms-admin.mjs accounts --env prod --root /opt/glasses-data   # 确认 boss/admin/active
```

> `--env prod` 对应 `var/live`；服务器上数据目录是 `/opt/glasses-data`，
> 所以要么把 `--base` 指过去，要么直接在数据目录里跑（见 §7 的"数据目录与 CLI 的对应"）。

**然后在浏览器**打开 `https://translate.example.com/admin?secret=<密钥>`：

1. **全屏登录**：填密钥 + `boss` + 密码 → 进控制台
2. 「当前会议术语」应显示"还没有会议术语"（正常，还没开始过同传）
3. 「账号」→ 加一个 dev 测试账号（用户名+密码，默认 7 天过期）
4. 「批量导入」→ 建一两个库（或用「填入示例」）

**手机端**：

1. 设置里填地址 `https://translate.example.com`（或 `http://<服务器IP>:8788`）、密钥
2. 账户：用刚加的测试账号**登录**（用户名+密码）；或走「注册」（邮箱 → 取码 → 用户名密码）
3. 术语库页：勾选库 → 保存 → 顶部应显示"本场会议术语 N 条"
4. 点「开始同传」说一句 → 服务器日志应出现
   `[术语] 新一场与会：会议 m-…，N 条`，字幕应使用勾选库里的写法

## 6. 排障表（按症状查）

| 症状 | 先看这里 | 常见原因 |
|---|---|---|
| `SyntaxError: Unexpected token '?'`（一启动就崩） | `node -v` | **Node 太旧**（22.04 的 apt 自带 12.22）：`??` 要 Node 14+，本项目要 20+。用 NodeSource 重装，见 §9.6 步骤 6 |
| 识别进程退出：`EACCES: permission denied, mkdir '/var/lib/leion'` | `ls -ld /var/lib/leion` | 数据目录上级属于 root，没给当前用户写权限。`sudo mkdir -p /var/lib/leion && sudo chown "$USER": /var/lib/leion`（现在启动前就会提示，见 §2.3） |
| 大脑退出：`无法加载真实的 @deepseek-ai/dsh-tools 构建产物` | `node scripts/preflight.cjs` 第 ⑥ 项 | 这台机器上**没有** deepseek-harness 检出，或没构建（缺 `packages/core/tools/lib/index.js`）。见 §2.0；systemd 里还要 `Environment=DSH_CHECKOUT=...` |
| 大脑退出：`Invalid module ... must not include encoded "/" or "\" characters` | 同上 | 老版本把 Windows 路径写死了（已修）；看到这个说明代码是旧的，先 `git pull` |
| 手机"连不上服务器" | `python3 scripts/check-relay.py --base http://<IP>:8788 --secret <密钥>` | 一条命令分清"服务没起 / 只听 127.0.0.1 / 防火墙 / 密钥错"四种 —— 别再靠猜 |
| 手机上"注册失败/not-found" | `/hello` 的 `features` 里有没有 `auth`、`org` | 服务器上跑的是**旧进程**：重启 `systemctl restart glasses` |
| 管理页 401 `X-Leion-Secret` | URL 是否带 `?secret=`，或页面顶部那格 | 密钥填错/没填 |
| 管理页能开，但账号/库报 401 | 是否已登录 | 控制台需要先登录拿 token |
| 字幕出来了，但术语不生效 | 日志 `热词表：N 条（user=meeting:…）` | ① 还没"开始同传"过（会议术语未发布）；② 手机没勾库 |
| 说了话没字幕 | 日志里有没有"近乎静音…解码前丢弃" | 麦克风太远/增益太低；把 `--silence-skip-level` 调到 0.01 再试 |
| 静音时冒出"谢谢大家/中文字幕" | 同上 | 若仍出现，把那段电平记下来（应 > 0.02 才会进解码） |
| 首次识别慢得像卡住 | `HF_HOME` | 没设就会重下模型 |
| 端口被占 | `ss -lntp \| grep 8788` | 旧进程没停干净 |
| 音频文件越来越大 | `du -h /opt/glasses-data/audio-in.pcm` | 只追加不清空；重启会清，或加定时任务 |

## 7. 数据目录与 CLI 的对应（容易搞混的一条）

- `start-all --data-dir /opt/glasses-data` → 服务读写 `/opt/glasses-data`；
- `scripts/terms-admin.mjs --env prod`（不给别的）→ 读写 `<仓库>/var/live`，**不是**服务器目录。

两者对上用 **`--root`**（2026-10-24 新增，直接指定数据目录，不要求目录名叫 live/live-test）：

```bash
node scripts/terms-admin.mjs admin    --env prod --root /opt/glasses-data --username boss --password '...'
node scripts/terms-admin.mjs accounts --env prod --root /opt/glasses-data
```

> 日常管理尽量用**管理控制台**（`/admin`），它天然和 relay 用同一个数据目录；
> CLI 只在"还没有管理员、进不去控制台"时用一次。

## 7.5 本地 vs 服务器：谁算"生产"、谁算"测试"？

**结论：环境不是机器属性，而是"数据目录"属性。** 同一份代码，指向哪个目录就读写哪套数据。

| 位置 | 建议数据目录 | 说明 |
|---|---|---|
| 服务器 | `/opt/glasses-data` | 正式数据（管理端建库、手机会议术语都落这里） |
| 家里 / 开发机 | `var/live` | 本地默认；随便折腾不影响服务器 |
| 本地做实验 | `var/live-test` | 与上面那套物理隔离（CLI 的 `--env test` 就是它） |

三条容易踩的：

1. **CLI 的 `--env prod|test` 只是目录名约定**，不改变任何服务行为；服务器目录叫
   `glasses-data` 对不上这个约定，所以要用 `--root /opt/glasses-data`。
2. 启动横幅会打印 **「数据目录环境」**（生产 / 本地默认 / 测试 / 自定义）——
   它只是标签，但能立刻看出"我在改哪套数据"。
3. **两套数据不要互相指**：拿本地机器去读写服务器目录（网络盘 / 挂载），
   等于在家里直接改生产 —— 出问题时日志里看不出来。

## 7.6 显存只有 4 GB 的机器能当服务器吗？

**能，但要把模型或精度降一档。** 下面显存与耗时都是**估算**（本项目只在 8 GB 卡上实测过）：

| 模型 / 精度 | 显存占用（估） | 中文字错率 | 每段耗时（估） |
|---|---|---|---|
| large-v3 / float16（缺省） | ~5 GB | **3.9%**（实测） | 基准 1× |
| large-v3 / int8_float16 | ~3 GB | 约 4%（略降） | 1.3~1.8× |
| medium / float16 | ~2.5 GB | **7.4%**（实测） | 更快 |
| medium / int8_float16 | ~2 GB | 约 7~8% | 1.3~1.8× |
| small / CPU（int8） | 0（走内存） | 18.9%（实测） | 1.9 秒/句，接近不可用 |

```bash
# 4GB 卡稳妥档：medium + 量化
node scripts/start-all.mjs --public --data-dir /opt/glasses-data --whisper-model medium --compute int8_float16

# 想尽量保精度：large-v3 + 量化（显存紧、可能 OOM，先试）
node scripts/start-all.mjs --public --data-dir /opt/glasses-data --compute int8_float16
```

> ⚠️ **显存放不下时 ctranslate2 直接抛错，不会自动降级**。顺序是：先 `--compute int8_float16`
> 跑 large-v3 → 报 OOM 就换 `--whisper-model medium`。
> 判断标准不是"能不能起来"，而是**说一句要等多久**（看日志里的 `RTF` 与"识别"耗时）。

### 用家里电脑当服务器，还要解决三件事

1. **公网可达**：家庭宽带通常没有公网 IP。三条路 ——
   · 端口转发 + DDNS（要有公网 IP，IPv4 现在很少给）；
   · **Cloudflare Tunnel / Tailscale Funnel**（不需要公网 IP，建议先试）；
   · 一台便宜小 VPS 只做反代，家里电脑主动外连（与 §4 的 TLS 逻辑一致）。
2. **稳定性**：休眠、断电、驱动更新都会让服务消失 —— 至少关掉休眠、设开机自启。
3. **TLS**：无论哪条路，手机侧都要 https（否则密钥与音频明文）。

## 8. 迁移（换机器 / 本地 → 服务器）

1. 停旧服务：`systemctl stop glasses`
2. 只搬三样：`accounts.json`、`libraries/`、`meeting-terms/`（想留历史再加 `meetings/`）
3. 新机器上启动即可：**密码不用重设**（scrypt 哈希原样可用），token 也是 sha256（旧 token 继续有效，若想强制重登就删 `accounts.json` 里的 `tokens`）

```bash
rsync -av --progress old:/opt/glasses-data/accounts.json  new:/opt/glasses-data/
rsync -av --progress old:/opt/glasses-data/libraries/     new:/opt/glasses-data/
rsync -av --progress old:/opt/glasses-data/meeting-terms/ new:/opt/glasses-data/
```

## 9. 安全须知（别跳）

1. **`--public` 必须加**：否则密钥是 6 位、无限流；绑公网等于开门。
2. **必须走 TLS**：密钥与音频都在头/体里明文传。
3. **`/admin` 只在 TLS 后面暴露**；它没有独立鉴权（靠共享密钥 + 登录 token 两层）。
4. **共享密钥轮换**：删 `relay-secret.txt` 重启即可（会重新生成），手机端要同步改。
5. **管理员的初始密码**：建完立刻改（CLI 改密码命令尚未提供，可先删账号重建）。
6. **音频落盘含真实会议内容**：注意磁盘权限与定期清理。

## 9.5 附录：CUDA 13 + conda 的服务器（2026-10-24 遇到的真实环境）

很多 GPU 云机预装的是 **CUDA 13 + torch(cu132)**，而 `ctranslate2`（faster-whisper 的后端）
是按 **CUDA 12** 构建的，要 `libcublas.so.12` 与 `libcudnn*.so.9`。
只有 cu13 的库时典型报错：
`libcublas.so.12: cannot open shared object file` 或 `Could not locate cudnn_ops64_9`。
参考：[cublas64_12 not found](https://alaintural.com/writing/cublas64-12-dll-not-found-faster-whisper/)、
[cuDNN 9 报错排查](https://runaihome.com/blog/cudnn-ops64-9-dll-error-fix-2026/)。

**做法：给本项目单独建一个 conda 环境，装上 cu12 的运行库，别动机器上原有的 torch 环境。**

```bash
# 1) 独立环境（Python 3.12 已验证可用）
conda create -y -n leion python=3.12
conda activate leion

# 2) faster-whisper + **cu12 运行库**（这一条是关键，缺了就用不了 GPU）
pip install -U pip
pip install faster-whisper numpy
pip install nvidia-cublas-cu12 "nvidia-cudnn-cu12==9.*"

# 3) 把这几个 lib 目录加进 LD_LIBRARY_PATH（脚本会打印确切路径）
python - <<'PY'
import os, site, glob
paths = []
for root in site.getsitepackages():
    paths += glob.glob(os.path.join(root, 'nvidia', '*', 'lib'))
print(':'.join(paths))
PY
# 把上面输出的那一串写进环境（示例）：
export LD_LIBRARY_PATH="$(python -c "import os,site,glob;print(':'.join(sum([glob.glob(os.path.join(r,'nvidia','*','lib')) for r in site.getsitepackages()],[])))")${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"

# 4) 一锤定音：跑自检脚本（会告诉你该用哪个模型/精度、RTF 多少）
python scripts/check-asr-env.py            # 8GB 卡建议再跑一次 --models large-v3,medium
```

自检脚本会依次检查：Python 依赖 → **cu12 运行库在不在** → GPU 是否可见 →
同一段音频在 `float16` / `int8_float16` 下的加载耗时、解码耗时与 RTF。

**在 8 GB 卡上的选择建议**：`large-v3 / float16`（约 5 GB，能放下）；
如果还要同时跑别的占显存的东西，用 `--compute int8_float16`（约 3 GB，解码慢 1.3~1.8×）。

### systemd 单元里必须带上这两个环境变量

```ini
Environment=PATH=/opt/conda/envs/leion/bin:/usr/local/bin:/usr/bin:/bin
Environment=LD_LIBRARY_PATH=/opt/conda/envs/leion/lib/../site-packages/nvidia/cublas/lib:/opt/conda/envs/leion/lib/../site-packages/nvidia/cudnn/lib
```

> 懒得手抄就用本节脚本生成（conda 环境同样适用，写出来的就是这两行）：
>
> ```bash
> sudo python3 scripts/make-env-file.py /opt/conda/envs/leion --out /etc/leion/asr.env
> # 单元里改成：EnvironmentFile=/etc/leion/asr.env
> ```

> `asr-bridge` 起识别进程用的是 **PATH 里的 `python`**（`spawn('python …')`），
> 所以 systemd 的 PATH 必须指向 conda 环境，否则它会用系统 python → 报"没有 faster_whisper"。
> 用 `conda activate` 手动跑时不会有这个问题，改成 systemd 后最容易踩。

## 9.6 附录：裸机部署（不用 conda）

"裸机"在这份文档里指**不依赖任何预装环境**：一台干净的 Ubuntu（或你手里的物理机），
系统里只有 apt 装的软件，不用 conda、不用 Docker。**装法和 §9.5 只差三步**，
真正要小心的还是同一件事：cu12 运行库 + `PATH`/`LD_LIBRARY_PATH`。

### 先纠正一个常见误会：不需要装 CUDA Toolkit

本项目只用 GPU 跑 **faster-whisper**（后端是 `ctranslate2`）。它需要的是
**CUDA 运行库**（`libcublas.so.12`、`libcudnn*_9`），不是整套 CUDA Toolkit，
也不需要 torch。所以：

| 需要 | 不需要 |
| --- | --- |
| NVIDIA **驱动**（`nvidia-smi` 能跑） | CUDA Toolkit（`nvcc`） |
| `nvidia-cublas-cu12`、`nvidia-cudnn-cu12==9.*`（pip 装） | conda / Docker |
| Python 3.10+（3.12 已验证） | torch、torchvision |

> 驱动装哪个版本：能支持你机器上的卡就行（`nvidia-smi` 右上角显示的 `CUDA Version`
> 是"驱动最多支持到哪个 CUDA 版本"，只要 ≥ 12 就没问题。CUDA 13 的驱动**可以**跑 cu12 的库）。

### 步骤 1：系统依赖

```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip curl git ca-certificates

# 检查 Python 版本：24.04 自带 3.12（与我们验证过的一致）；22.04 是 3.10，也能用
python3 --version
```

**不用 `sudo pip`**：下面的依赖全装在项目自己的虚拟环境里，不污染系统 Python，
也就不会跟系统包打架（这是裸机最容易被搞坏的地方）。

### 步骤 2：建一个虚拟环境（替代 conda 环境）

```bash
sudo mkdir -p /opt/leion
sudo chown "$USER": /opt/leion          # 之后不用 sudo
python3 -m venv /opt/leion/venv
source /opt/leion/venv/bin/activate     # 之后每条命令都在激活状态里跑
python -V
```

### 步骤 3：装依赖 + cu12 运行库（关键的一条）

```bash
pip install -U pip wheel
pip install faster-whisper numpy
pip install nvidia-cublas-cu12 "nvidia-cudnn-cu12==9.*"   # ← 缺这条就只有 CPU
```

`nvidia-cublas-cu12` 是 NVIDIA 官方发的 **pip wheel**，它把 `.so` 文件直接装进
`site-packages/nvidia/*/lib`，跟系统里有没有 CUDA 无关。这就是"裸机不装 CUDA Toolkit 也能上 GPU"的原因。

### 步骤 4：生成 systemd 用的环境文件（别手抄路径）

```bash
# 先看一眼算出来的 PATH / LD_LIBRARY_PATH，以及依赖是否齐
python3 scripts/make-env-file.py /opt/leion/venv

# 确认没问题再落成文件（systemd 用）
sudo mkdir -p /etc/leion
sudo python3 scripts/make-env-file.py /opt/leion/venv --hf-home /opt/leion/models --out /etc/leion/asr.env
cat /etc/leion/asr.env
```

脚本会自己找出 `site-packages/nvidia/*/lib` 的真实路径，并检查
`ctranslate2` / `faster_whisper` 能不能 import；有问题时**退出码非 0 并说清缺什么**，
不会给你一份看着正常、实际跑不了的环境文件。

### 步骤 5：下模型 + 自检（这一步过了再往下走）

```bash
source /opt/leion/venv/bin/activate
export LD_LIBRARY_PATH="$(grep '^LD_LIBRARY_PATH=' /etc/leion/asr.env | cut -d= -f2-)"
export HF_HOME=/opt/leion/models

python3 scripts/fetch-model.py large-v3 --mirror     # 国内必须 --mirror，见 §2.2
python3 scripts/check-asr-env.py                     # 5 项：依赖 / cu12 库 / 卡支持哪些精度 / 实测 / 结论
python3 scripts/check-asr-env.py --models large-v3,medium
```

> 顺序很重要：**先下模型再自检**。反过来的话，自检的 ④ 会一边测速一边下载 2.9 GB，
> 失败时报的是 SSL/超时，看起来像"显卡环境坏了"。

第 2 项是"cu12 运行库在不在"，第 4 项会给出 `float16`、`int8_float16` 的加载/解码耗时与 RTF。
**8 GB 卡建议 `large-v3 / float16`**（约 5 GB）；还要腾显存就用 `--compute int8_float16`。

### 步骤 6：Node 20（转发进程要用）

```bash
# ⚠️ 不要用 apt install nodejs：22.04 上装到的是 12.22，一跑 .mjs 就报
#    SyntaxError: Unexpected token '?'（`??` 语法要 Node 14+，我们要求 20+）
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs
node -v     # 必须是 v20.x 或更高
```

> 如果 `node -v` 还是旧的：`sudo apt purge -y nodejs && sudo apt autoremove -y` 之后再装一遍
> （NodeSource 的包会顶掉发行版那个）。装完 `which node` 应是 `/usr/bin/node`。

装完先体检一次（**这是最快确认"环境对不对"的一步**，只检查不改动）：

```bash
node scripts/preflight.cjs
# 或 npm run doctor
```

它会依次查：Node 版本 → python3 → 数据目录可写 → 端口空闲 → 模型缓存里有没有 large-v3，
每项带 `[OK]` / `[WARN]` / `[FAIL]` 与修法。这个脚本**故意用老语法写**（CommonJS、不用 `??`），
所以哪怕 Node 太旧，它自己也能跑起来告诉你"Node 太旧"——而 `start-all.mjs` 在那种情况下只会给你一行
`SyntaxError`。

### 步骤 7：交给 systemd

单元文件与 §3.2 相同，只把 `PATH`/`LD_LIBRARY_PATH` 两行换成一句 `EnvironmentFile`：

```ini
[Service]
Type=simple
User=leion
WorkingDirectory=/opt/leion/app
# PATH 与 LD_LIBRARY_PATH 都在这里（由 scripts/make-env-file.py 生成）
EnvironmentFile=/etc/leion/asr.env
ExecStart=/usr/bin/node scripts/start-all.mjs --data-dir /var/lib/leion/live --port 8788
Restart=always
RestartSec=5
```

> 为什么非要这两行：`bridge/asr-bridge.mjs` 起识别进程用的是 **PATH 里的 `python`**
> （`spawn('python …')`），systemd 没有 shell、不认 `source` 也不认 `conda activate`。
> PATH 不指过去 → 报"没有 faster_whisper"；`LD_LIBRARY_PATH` 不给 → 报
> `libcublas.so.12: cannot open shared object file`。**这两个错是同一类：环境没带进去。**

TLS、开机自启、首次上线核对清单、排障表：全部回到 §3.2 / §4 / §5 / §6，与 conda 版完全一样。

### 与 conda 版（§9.5）的差异，一共就四行

| | conda（§9.5） | 裸机 venv（本节） |
| --- | --- | --- |
| 建环境 | `conda create -n leion python=3.12` | `python3 -m venv /opt/leion/venv` |
| 激活 | `conda activate leion` | `source /opt/leion/venv/bin/activate` |
| cu12 库 | 同样 pip 装 `nvidia-*-cu12` | 同样 pip 装 `nvidia-*-cu12` |
| 环境变量 | 手写进单元 | `scripts/make-env-file.py` 生成 |

> 反过来说：**裸机并不比 conda 更容易出问题**，隔离效果一样（都是独立的 Python 环境）。
> 真正的风险在别处：① 多个服务共用一个 venv；② 系统 Python 大版本升级后旧 venv 失效
> （重建 venv 即可，数据目录不受影响）；③ 有人 `sudo pip install` 到系统 Python。

### 如果"裸机"指的是物理机（自己插卡的机器）

上面全流程不变，另外多四件事：

1. **驱动要自己装**：`sudo ubuntu-drivers autoinstall`（或从 NVIDIA 官网装 .run）。
   装完 `nvidia-smi` 必须能跑；Secure Boot 开着时会拦第三方模块，按提示签名或关掉。
   **装驱动后要重启**。
2. **断电自启**：BIOS 里设 *Restore on AC Power Loss = Power On*，否则停电恢复后机器躺着不动。
3. **网络固定下来**：给服务器设静态 IP（或路由器 DHCP 绑定），否则手机端地址会变；
   公网访问还要在路由器上做端口转发，且**必须配 §4 的 TLS**。
4. **磁盘和环境**：模型约 3 GB + 音频落盘，`/var/lib` 不要放在小 U 盘上；定期清 `audio-in.pcm`。

### 裸机上最容易踩的四个坑

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| `libcublas.so.12: cannot open shared object file` | 只装了驱动 / 只装了 cu13 | `pip install nvidia-cublas-cu12 "nvidia-cudnn-cu12==9.*"`，并用 §步骤 4 生成 `LD_LIBRARY_PATH` |
| systemd 起来就报"没有 faster_whisper" | PATH 没指到 venv | 单元里用 `EnvironmentFile=/etc/leion/asr.env`（里面有 PATH） |
| 手动能跑、systemd 不能跑 | 手动时 `source` 过环境 | 同一份 `asr.env` 给两边用，别在两处各写一套 |
| `apt install nvidia-cuda-toolkit` 之后反而坏了 | Ubuntu 源的 toolkit 版本一般比驱动老，装上会被优先加载 | 不要装它；本项目不需要 Toolkit |

## 9.7 实机笔记：Tesla P40（Pascal）/ 驱动 550 / CUDA 12.4 / 系统 Python 3.10

一台具体机器（`nvidia-smi` 实测输出）：

```
Driver Version: 550.127.08    CUDA Version: 12.4
GPU: Tesla P40   23040 MiB   29C  P0  45W / 250W   无进程
系统 python3 = 3.10.12
```

**结论先说：这台机器可以直接用，24 GB 显存比开发机宽裕得多。**
只有一处必须改：识别精度不能用 `float16`，要用 `int8`（或 `int8_float32`）。
本机实测档位表与 RTF 见下面「实测结果」一节。

### 为什么必须改精度（本节唯一重要的事）

P40 是 **Pascal 架构（算力 6.1）**：有 FP16 **存储**，但没有 FP16 快速矩阵乘
（没有张量核）。`ctranslate2` 是按卡查表的，Pascal 上**根本不提供 `float16` / `int8_float16`**。
而本项目 GPU 缺省正好是 `float16` —— 在这台卡上"照着文档抄"会起不来，
报错是 ctranslate2 的一行英文，很难看出是"档位不对"而不是"环境装坏了"。

现在已经两头都兜住了：

| 位置 | 行为 |
| --- | --- |
| `bridge/whisper_stream.py` → `resolve_compute_type()` | 启动时查到这张卡不支持请求的精度，**自动换成能跑的**（优先 `int8_float32`）并打一行 ⚠️ 说明，不静默 |
| `scripts/check-asr-env.py` ③ | 直接打印"这张卡能跑哪些精度 + 推荐档位"，并按可用档位去实测 |
| `start-all.mjs --compute` | 白名单加了 `int8_float32` |

### 从零到跑（Python 3.10/3.12 都行 → 走裸机 venv 路线）

```bash
sudo apt update && sudo apt install -y python3-venv python3-pip curl git ca-certificates
sudo mkdir -p /opt/leion && sudo chown "$USER": /opt/leion
python3 -m venv /opt/leion/venv && source /opt/leion/venv/bin/activate

pip install -U pip wheel
pip install faster-whisper numpy
pip install nvidia-cublas-cu12 "nvidia-cudnn-cu12==9.*"     # cu12 运行库，见下

# 下模型（国内必须带 --mirror；脚本默认关掉 Xet，否则会 SSL 报错）
python3 scripts/fetch-model.py large-v3 --mirror

# 先自检：③ 打印这张卡支持的精度与推荐档位，④ 给真实 RTF
export LD_LIBRARY_PATH="$(python3 scripts/make-env-file.py /opt/leion/venv | grep '^LD_LIBRARY_PATH=' | cut -d= -f2-)"
export HF_HOME=/opt/leion/models
python3 scripts/check-asr-env.py --models large-v3

# 起链路（24 GB 显存可以用 large-v3，精度用 int8_float32）
# 数据目录要先建好并归你（/var/lib 属于 root，不建就会 EACCES）
sudo mkdir -p /var/lib/leion && sudo chown "$USER": /var/lib/leion
node scripts/start-all.mjs --public --data-dir /var/lib/leion/live --port 8788 \
     --whisper-model large-v3 --compute int8_float32
```

> `python3 -m venv` 用的是系统自带的 `python3`；这台机器上是 **3.10.12**，实测
> `faster-whisper 1.2.1 / ctranslate2 4.8.3 / numpy 2.2.6` 都能装上、cu12 库也能在
> venv 里找到（`.../site-packages/nvidia/cublas/lib/libcublas.so.12`）。
> **3.10 和 3.12 都能用**，不必为了版本去折腾 deadsnakes。

### 驱动 550 + CUDA 12.4 意味着什么

- **版本刚好对得上**：550 驱动最高支持到 CUDA 12.4 运行时，而 `ctranslate2` 要的正是 cu12 的库。
  所以这台机器**不需要** §9.5 那套"CUDA 13 上找 cu12"的折腾。
- 但"驱动支持 CUDA 12.4" **不等于** "系统里有 cu12 的库"。P40 机器一般没装 CUDA Toolkit，
  所以仍然要 `pip install nvidia-cublas-cu12 "nvidia-cudnn-cu12==9.*"`。
- 如果这台机器原本就装了系统级 cu12（`/usr/lib/x86_64-linux-gnu/libcublas.so.12`），
  `check-asr-env.py` 的 ② 会显示"找到"—— 两种来源都行，谁在 `LD_LIBRARY_PATH` 前面用谁。

### 24 GB 显存能做什么、不能做什么

- `large-v3` + `int8_float32`：int8 权重约 1.5 GB，激活 FP32 峰值几 GB，**余量很大**。
- 可以同时跑别的模型/服务（不像 8 GB 卡要算着用）。
- 但**不要**指望一张卡同时做多场同传：现在转发侧的设计是"一场一路音频"（`docs/19`）。
- 也不要因为显存大就上 `float32`：Pascal 上 `float32` 比 INT8 档慢得多，
  而 Whisper 上两者的准确率差异基本看不出来。**用实测 RTF 说话，别猜。**

### P40 是"被动散热"的（物理机部署要提前想）

P40 没有风扇，靠机箱风道。塞进普通台式机箱会过热降频甚至直接关机。

- 需要机箱风扇墙 / 服务器风道；
- 供电是 **CPU 8-pin**（不是 PCIe 8-pin），普通电源要转接线；
- 250 W 上限，`sudo nvidia-smi -pl 200` 可限功耗（更凉更省电，代价是慢一点）。

### 实测结果（2026-10-25，第一次在这台卡上跑通）

`check-asr-env.py` 的 ③ 在这台机器上给出的**真实列表**（不是推断）：

```
算力       6.1（Pascal）
支持的精度 float32, int8, int8_float32        ← 没有 float16 / int8_float16 / int16
推荐档位   int8_float32
显存 22.5 GB
```

④ 用 3 秒合成音频测的两档（`large-v3`，**每档先预热再计时**）：

| 档位 | 加载 | 解码 | RTF |
| --- | --- | --- | --- |
| `int8_float32` | 7.3 s | 668 ms | **0.22** |
| `int8` | 5.5 s | 680 ms | **0.23** |

**怎么读这两个数**：

- 两者 RTF 都 **≪ 1**（比实时快 4~5 倍），24 GB 的 P40 跑 large-v3 毫无压力。
- **两档实际上一样快**：668 ms vs 680 ms 差 1.8%，在噪声范围内。
- 第一次跑（没有逐档预热）时看到的是 0.28 / 0.22，看着像"int8 快 27%" ——
  那是**顺序造成的假象**：第一档要替后面所有档付 CUDA 上下文与 cuDNN 选算法的固定开销。
  脚本现在每档先预热再计时（与生产链路一致），复测后差值消失。**这正是当初必须复测的原因。**
- 所以**选哪个都行，按准确性倾向选**：`int8_float32`（激活 FP32，也是自动兜底选的那档）。
- 这是 **3 秒合成音**测出来的 RTF，**不能**和 `docs/04 §4` 那张表（33.5 秒真实语音、切成 20 句）
  直接并列 —— 短音频的 RTF 系统性偏乐观。

**目前的建议**：`--compute int8_float32`（与实测最快的档位等价，且精度更保险）。
