## 1. 与上一版的关键差异（我的假设错了，以原型为准）

| 项 | 我上一版（作废） | 原型（采用） |
|---|---|---|
| 发言权 | 申请 → 排队 FIFO → 主持人批准 → 30 秒超时释放 | **点击开麦即持麦**（无需长按），再点关闭；**后开麦者顶替先开麦者**（抢麦），被顶替者收到提示 |
| 防打断 | 无 | **锁定发言**：锁定期间他人开麦被拒，提示「XX 正在发言（发言已锁定）」；**仅管理者可解除他人锁定**；同一个按钮在"锁定/解锁"之间切换 |
| 并发裁决 | 队列 | **按服务端到达顺序**裁决，后到者收到「XX 正在发言」 |
| 入会 | 房间码 + 可选密码 | **6 位邀请码是入会唯一凭证**，无密码；校验通过后带出会议主题供确认 |
| 界面布局 | 底部大圆按钮 + 左抽屉 | **主区留给发言与译文字幕流**；右侧**竖向悬浮条**（当前发言人 + 投屏/扩声/收音状态）+ 右侧抽屉（人员与设备合并） |

## 2. 界面（5 个，③ 常驻）

```
启动 → ① 登录/注册（全屏）→ ② 首页（创建/加入）→ ③ 实时房间（核心）
                                                      ├→ ④ 右侧抽屉（发言人 + 设备）
                                                      └→ ⑤ 设置（服务器/语言/术语/隐私）
```

### ③ 实时房间（核心页）
- **主区 = 字幕流**（占绝大部分）：每句两条 —— 主行是**我的语言**的译文（大字 32~34sp），副行是原始发言（小字 16sp、低对比）。新句从下往上推。
- **底部单行控制**：`🎙 点击开麦`（开麦后变 `正在发言 00:12` 绿色呼吸）/ `锁定发言`（锁定后变 `解锁`）/ 原文-译文切换。**不用长按**。
- **右侧竖向悬浮条**（固定常驻、不轮播）：
  - 上格：**当前发言人**（头像 + 姓名；发言中绿环，空闲显示「麦克风空闲」）
  - 下格三项状态：**投屏 / 扩声 / 收音**（本项目手机-only：投屏=手机屏，扩声=耳机或关闭，收音=手机麦克风）
- **系统提示行**（插在字幕流里，灰色斜体）：
  - 会议开始：`— 会议开始 · 发言权互斥已启用：同一时刻仅一人开麦 —`
  - 抢麦成功：`你已接管麦克风 · 对方已被自动静音`
  - 被抢：`XX 接管了麦克风`
  - 被拒：`XX 正在发言（发言已锁定）`

### ④ 右侧抽屉
- 上半「发言人」：当前发言人 + 全员头像（**发言过即点亮**）+ 提示
- 下半「设备」：手机（收音/播报）能力开关；未连接设备置灰
- 管理者额外可见：解除他人锁定、移出成员

### ② 首页
`创建同传会议（生成邀请码）` / `加入同传会议（输入 6 位邀请码）` / `同传翻译官（单向收听）`，右上头像进 ⑤。

### ① 登录/注册
按原型：`用户名 + 邮箱 + 验证码`（新用户注册 / 老用户登录同一入口），底部勾选《用户协议》《录音与隐私政策》。

## 3. 服务端：发言权状态（`node:sqlite`）

```sql
CREATE TABLE floor_state (
  room_id TEXT PRIMARY KEY,        -- 单行主键 = 互斥锁本身
  holder  TEXT,                    -- 当前持麦者（NULL = 空闲）
  locked  INTEGER NOT NULL DEFAULT 0,  -- 是否锁定发言
  since   INTEGER NOT NULL
);
```

规则（实现即测试）：
1. **开麦请求**在一个事务里完成：查 `floor_state` → 空闲则直接置我；他人持有且**未锁定**则顶替（广播"被接管"）；他人持有且**已锁定**则拒绝（提示"XX 正在发言（发言已锁定）"）。
2. 同时到达按**到达顺序**处理（单写者 + 事务串行化即可，不做队列）。
3. **锁定**：持麦者可锁自己；**仅管理者**可解除他人锁定；锁定与解锁共用一个按钮。
4. 关麦即释放；断线超过 `N` 秒（建议 15 秒）视为释放，广播"XX 掉线，麦克风已释放"。
5. 客户端乐观 UI，最终以广播为准；冲突回滚并提示。

其他表：`rooms(id, name, code, host, langs, created_at)`、`room_members(room_id, user, joined_at)`、`utterances(room_id, user, src_lang, src_text, dst_text, start_at, is_final)`、`accounts`、`libraries`、`library_entries`、`requests`（原 JSON 内容迁入）。
`PRAGMA journal_mode=WAL; foreign_keys=ON; busy_timeout=3000`。

## 4. 存储与迁移

- **服务端**：`node:sqlite`（Node 22 内置，零依赖）。`scripts/migrate-sqlite.mjs` 一次性导入现有 `accounts.json`、`libraries/*.json`、`requests.jsonl`，之后只读写 SQLite，JSON 留档。
- **客户端**：原生 `SQLiteOpenHelper`（不加依赖）：`settings`、`rooms`（本地历史）、`utterances`（字幕回看，**7 天清理** `DELETE WHERE start_at < now-7d`）、`drafts`。
- **隐私**：7 天自动清理字幕与音频元数据；设置页提供「清空本房字幕」。

## 5. 已定（用户 2026-10-25 拍板）

1. **断线释放宽限 = 15 秒**：掉线超过 15 秒视为释放麦克风，广播「XX 掉线，麦克风已释放」。
2. **悬浮条保留「投屏 / 扩声」两格**，手机-only 阶段显示「—」占位；界面上不出现"眼镜"字样，后续接耳机播报时直接点亮。

## 6. 实施顺序（拆成小步，避免单次改动过大）

| 阶段 | 内容 | 交付物 |
|---|---|---|
| **P1** | SQLite 落地 + 迁移 | `lib/db.mjs`（`node:sqlite` 封装）、`scripts/migrate-sqlite.mjs`、迁移一致性测试（账号/库/申请条数逐项比对） |
| **P2a** | **建房 + 6 位邀请码加入 + 房间术语库** | 房间表与成员表、建房/加入/房间内术语库快照接口、对应测试；安卓：首页建房/加入 + 房间内术语库选择 |
| **P2b** | **发言权互斥（抢麦 / 锁定 / 到达顺序 / 断线释放）** | `floor_state` 事务实现 + 广播 + 接口测试；安卓：开麦按钮、系统提示、悬浮条发言人 |
| **P3** | 安卓整体重构收尾 | 5 屏全部按本文实现，右侧抽屉 + 设置页 |
| **P4** | 7 天清理 + 隐私页 | 定时清理任务、设置页「清空本房字幕」、隐私政策文案 |

每阶段完成即：跑全量测试 → 更新本文档对应章节 → 提交推送 → 告诉用户"可以构建/可以测"。

## 7. 验收

- 接口：并发开麦只有一个 holder；未锁定可被顶替并广播；已锁定时开麦被拒；管理者可解除他人锁定；断线 15 秒释放。
- 客户端：两部手机同房，A 开麦 B 显示「对方正在发言」；B 抢麦后 A 收到「XX 接管了麦克风」；A 锁麦后 B 被拒。
- 迁移：导入后账号/库/申请条数与 JSON 一致（逐项比对）。

## 8. 环境与数据目录（2026-10-25 定）

**本机只用于开发与跑自动化测试；所有应用侧测试都在服务器进行。**

| 环境 | 数据目录 | 谁用 | 说明 |
|---|---|---|---|
| 开发 | `<仓库>/var/live`、`var/live-test` | 本机（Windows） | 只跑 `node tests/run-all.mjs` 与离线脚本；不装 App、不联调 |
| 测试 | `/var/lib/leion/test` | 服务器 | 随便造数据、可整目录删 |
| 生产 | `/var/lib/leion/live` | 服务器 | 真实账号与会议；`leion.db` 就在这里 |

规则：
1. **一份代码 + 一个 `--data-dir` = 一套环境**，不靠机器身份判断；
2. CLI 的默认数据目录认 `LEION_DATA_DIR`（未设时回落到仓库内 `var/live`，**不会**默认写到 `/var/lib`）；
3. 服务器上每个环境一个独立 `leion.db`；删测试环境不影响生产；
4. 启动横幅与 `preflight.cjs` 都会打印实际数据目录，避免"以为在测试、其实写进了生产"。
## 9. 数据存储现状（2026-10-26 收尾）

| 数据 | 位置 | 备注 |
|---|---|---|
| 账号 / token / 验证码 | SQLite：`accounts / tokens / auth_codes` | 含 scrypt 参数（algo/N/r/p），否则密码校验不过 |
| 术语库 / 条目 / 分类 | SQLite：`libraries / library_entries / categories` | 字段与 `emptyLibrary()` 一一对齐（含 priority/visibility/users/updatedBy） |
| 用户申请 | SQLite：`requests`（事件式：create 行 + decision 更新） | 表里有 `payload` 保住原始事件字段 |
| 会议术语快照 | 文件：`<data-dir>/meeting-terms/{terms.json,meta.json}` | 插件每句都读它；**不迁库**（插件读的是文件，保持不变） |
| 字幕 | SQLite：`utterances`（7 天清理） | 待 P4 接入 |
| 房间 / 成员 / 发言权 | SQLite：`rooms / room_members / floor_state` | 待 P2a/P2b 接入 |

**备份只需两样**：`leion.db`（+ `-wal`/`-shm`）与 `meeting-terms/`。
旧 `accounts.json` / `libraries/*.json` / `requests.jsonl` 在迁移完成前仍会被读一次（库里为空时），迁移后可归档删除。

### 遗留（按优先级）

1. **音频与浏览器字幕联动**：房间页字幕依赖 `/frame` 长轮询，已在 `LanClient` 里跑；若发现"有译文但房间页不显示"，查这里。

3. **断线释放全靠轮询**：客户端 2 秒轮询 + 服务端 15 秒租约；没做 WebSocket。
4. **P4 未做**：字幕 7 天清理任务（`purgeOldUtterances` 已实现，未接入定时）、隐私政策页、设置页（服务器地址/密钥目前只在登录页填）。
5. **校对只看术语表、不看上下文历史**：跨句指代仍可能改错。
6. **管理员页没有房间级操作**（结束会议/踢人），只有列表。
