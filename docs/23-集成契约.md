# 集成契约：会议室 App ↔ 同传翻译官 App（2026-10-28）

> **读者**：做「同传翻译官」那一端的人（以及维护 relay 的人）。
> **本文只回答一件事**：两个 App 怎么共用同一台服务器而不互相踩。
> 数据通路的"为什么"在 [`05-数据通路.md`](05-数据通路.md)，房间与发言权的规则在
> [`21-房间与发言权-UI与存储设计.md`](21-房间与发言权-UI与存储设计.md)，部署在 [`10-服务器部署.md`](10-服务器部署.md)。

## 0. 一页速览

```
手机(录音) ──/audio──► relay ──asr-inbox.jsonl──► 识别进程 ──收件箱 json 行──► 大脑(DSH 插件)
                                                                                  │
                       手机(字幕) ◄──/frame 长轮询 或 /ws 推送 ◄── subtitle-bus.json ┘
```

- **两个 App 共用同一台 relay**：会议室 App 负责"开会的组织"（建房、抢麦、术语），
  翻译官 App 负责"听与看"（收音、字幕、投屏到眼镜）。
- **服务器是唯一的事实来源**：客户端不做语种判定、不做术语替换、不裁决发言权。
- **契约只做加法**：见 §8，改字段语义必须升 `features` 并用新名字。

## 1. 三条命令跑起"假服务器"（不需要 GPU / 模型 / 识别 / 凭据）

真链路要 4 样东西：GPU、faster-whisper 模型、DSH 检出、翻译凭据。联调字幕界面时**一样都不需要**，
因为 relay 的字幕来源只有一个文件（字幕总线）。开三个终端：

```bash
# ① 转发进程（假数据目录 + 固定密钥，纯本地）
node relay/lan-relay.mjs --data-dir var/dev --port 8799 --secret dev-secret

# ② 假字幕：每 2.5 秒往字幕总线写一帧（形状与真链路完全一致）
node scripts/fake-frames.mjs --bus var/dev/subtitle-bus.json

# ③ 验一下（另开终端）：应看到 changed:true 与 frame.text
curl -s "http://127.0.0.1:8799/frame?since=0" -H "X-Leion-Secret: dev-secret"
```

客户端里填：地址 `http://<这台电脑的局域网IP>:8799`、密钥 `dev-secret`。

`fake-frames` 的内置脚本覆盖三种最容易出问题的情形：
**中文→葡语 / 葡语→中文 / 超长句**（验折行与翻页）。`--partial` 会先发一帧"增量"再发定稿，
用来验客户端**原位更新**同一条字幕而不是新起一条。`--list` 看脚本，`--file` 用自己的：

```bash
node scripts/fake-frames.mjs --bus var/dev/subtitle-bus.json --file my.txt   # 每行：说话人|语种|原文|译文
```

> 真链路（要识别与翻译时）用 `node scripts/start-all.mjs …`，见 `docs/10` 与 `docs/21 §10 复现环境`。

## 2. 身份与鉴权

| 层 | 头 / 参数 | 说明 |
|---|---|---|
| 共享密钥 | `X-Leion-Secret: <密钥>` 或 `?secret=` | 每个请求都要；`--public` 模式会强制 ≥24 字符 |
| 账号 token | `X-Leion-Token: <token>` | 由 `/auth/login` 或 `/auth/register-email` 返回；**服务端只认 token 判"我是谁"** |
| 设备标识 | `/auth/login` 的 `label` 字段 | 建议填 `translator` / `room`（见下） |

**⚠️ 单会话的坑（现在就会遇到）**：同一账号后登录会**吊销前一个 token**。
你调翻译官、我调会议室，用同一个测试账号会**互相踢下线**。

- 现状：被踢方会在 10 秒内（或 `/ws?session=1` 的 `{type:'kicked'}` 一秒内）收到提示。
- 代码已经支持 `label`，**建议改成"同 label 顶掉旧的、不同 label 允许并存"**（待拍板，见 §9）。
  在那之前：**各自用各自的测试账号**（例如 `dev-translator` / `dev-room`）。

## 3. 能力协商（先问能力，再决定用哪条通道）

`GET /hello`（带密钥）返回：

```json
{ "ok": true, "device": "Leion Pro", "cols": 40, "lineBudget": 3, "seq": 12,
  "features": ["hello","say","audio","frame","status","diag","lint","terms","settings","auth","org",
               "floor-ws","frame-ws","room-closed-push","session-push"] }
```

| 字段 | 用途 |
|---|---|
| `cols` / `lineBudget` | **显示预算**：服务端按它把译文折成 `lines[]`。眼镜是 640×400，手机不一定是 |
| `features` | 能力表。**老服务端没有新能力**，客户端据此降级或直接提示"服务端版本较旧" |
| `seq` | 当前字幕序号，`/frame?since=` 的起点 |

已约定的能力标记：

| 标记 | 含义 | 缺了会怎样 |
|---|---|---|
| `floor-ws` | 发言权走 WS 推送 | 只能 2 秒轮询 |
| `frame-ws` | 字幕也走 WS 推送 | 只能长轮询 |
| `room-closed-push` | 发起者退出时主动推 `closed` | 需要靠轮询房间详情兜底（每 5 轮） |
| `session-push` | 被顶下线主动推 `kicked` | 只能 10 秒轮询 |

## 4. 端点清单

标记：**必须**=翻译官 App 必须实现；**可选**=按需；**会议室专用**=不要在翻译官里实现。

| 端点 | 标记 | 说明 |
|---|---|---|
| `GET /hello` | 必须 | 握手 + 显示预算 + 能力表 |
| `POST /audio?rate=&lang=&fresh=1` | 必须 | 裸 PCM S16LE 单声道分块上传。`rate` 只能是 16000/44100/48000；`lang` 是 `zh-CN`/`pt-BR`；**每次开始录音的第一块带 `fresh=1`** |
| `GET /frame?since=<seq>` | 必须（兜底） | 长轮询，最���挂 25 秒；返回 `{changed, reset, seq, frame}` |
| `WS /ws?room=<码或id>` | 可选（主通道） | 房间通道：`floor` / `frame` / `closed` 三类消息 |
| `WS /ws?session=1` | 可选（主通道） | 会话通道：`session` / `kicked` |
| `POST /say {text, from}` | 可选 | 手输一句话送进管道（排障神器：一秒区分"是语音坏了还是后面坏了"） |
| `GET /status` | 可选 | 诊断计数（帧数/收件箱行数/拒绝数/音频字节/WS 连接…） |
| `GET/PUT /settings` | 可选 | 目前只有 `proofread`（校对开关）。**以服务端为准**，别做本地自嗨 |
| `GET /terms`、`PUT /terms` | 会议室专用 | 术语表读写属会议室流程 |
| `/auth/*` | 必须 | 登录/注册/whoami/logout |
| `/org/*` | 会议室专用 | 库、房间、发言权——翻译官**只读**用（见 §5 房间内收听） |

## 5. 翻译官 App 的两种形态（都在原型里）

### 形态 A：纯单向收听（不建房）
只用 §4 里"必须 + 可选"：`/hello` → `/audio` 上传 → 收字幕 →（可选）投屏眼镜。
**不需要任何 `/org/*`。**

### 形态 B：房间内收听（凭码加入，只听不说）
原型首页有「同传翻译官（单向收听）」入口。如果要挂到某场会议里（共享术语、共享显示预算）：

1. `POST /org/rooms/join {code}` — 只需邀请码，不需要密码；
2. 之后**只读**：`GET /org/rooms/<id>/floor` 看谁在说话（自己不抢麦）；
3. `GET /org/rooms/<id>` 里 `room.closed === true` → 这场结束了，退出；
4. **不要**调 `/org/rooms/*/floor` 的 POST 动作（take/lock/force-release 是会议室的事）。

## 6. 数据形状（三个必须一致的地方）

### 6.1 收件箱行（识别 → 大脑）

纯文本一行 = 一��话；**推荐 JSON 行**（4.37 起产线默认）：

```json
{"text":"你好，会议改到三点","from":"zh-CN"}
```

逐句带语种的价值：手机切语种、双方交替发言时，**每句按自己的语种翻**，
不会出现"整路被定错语种、安静地输出另一种语言的译文"（实测词错率 100%）。
插件侧的解析在 `plugin/core.mjs` 的 `parseInboxLine`。

### 6.2 字幕帧（大脑 → 客户端）

```json
{ "speaker": "them", "lang": "pt-BR",
  "lines": ["早上好！我们现在可以开始会议了吗？"],
  "text": "早上好！我们现在可以开始会议了吗？",
  "source": "Bom dia! Podemos começar a reunião agora?",
  "sourceLang": "pt-BR", "termsMissing": [], "partial": false }
```

| 字段 | 客户端必须怎么用 |
|---|---|
| `text` / `lines` | `text` 是完整译文；`lines` 是**服务端按 `lineBudget` 折好的**。两者都要用：优先 `text`，放不下再用 `lines` |
| `source` | **原文**。原文与译文必须成对显示（这不是审美，是产品的核心承诺） |
| `partial` | `true` = 增量帧：界面要打「生成中」并**原位更新同一条片段**，不许新起一条 |
| `termsMissing` | 术语未按规范写法出现的中文名；只提示、不改字幕 |

### 6.3 WS 消息（三加一）

| 消息 | 触发 | 客户端动作 |
|---|---|---|
| `{type:'floor', holder, locked, leaseMs, released, releasedLocked, roomId}` | 发言权变化 | 整条替换本地的发言权状态；`released` 非空 = "XX 掉线，麦克风已释放" |
| `{type:'frame', seq, frame}` | 新字幕 | 与 `/frame` 的 `frame` **同一个结构**，复用同一个渲染入口 |
| `{type:'closed', roomId, reason}` | 会议结束（发起者退出） | 提示 + 退出房间；随后服务端会关闭连接 |
| `{type:'kicked', reason}` | 同账号在别处登录 | 提示"账号已在别处登录"+ 回登录页 |

## 7. 错误码语义（别只看 HTTP 200/500）

| 码 | 含义 | 客户端该做什么 |
|---|---|---|
| 401 | 会话失效（token 被吊销/过期） | 清本地 token、回登录页；**不要**重试 |
| 403 | 角色权限不足 | 提示权限问题，别重试 |
| 400 | 业务拒绝（参数/规则） | 显示 `hint`/`error` 文字 |
| 409 | 业务状态冲突（如"别人锁定中"） | 显示文字，**不是**网络错误 |
| 410 | 会议已结束（`closed:true`） | 退出房间 |
| 413 | 音频块过大（上限 1 MB/块） | 减小块大小 |
| 429 | 限流（每 IP 每分钟） | 退避重试 |
| 507 | 音频存储满 | 提示重启转发进程清理（见 `docs/10`） |

## 8. 版本演进规则（这条比什么都重要）

1. **只做加法**：加字段、加端点、加 `features` 标记都安全；改名、改语义、删字段**必须先升标记**。
2. 新能力一律先出现在 `features` 里；老客户端不认识就**忽略**，新客户端看不到标记就**降级**。
3. `features` 查一次就够（握手时），别每句都查。
4. 已经踩过的"语义变更"（对方如果照旧文档写会踩全套）：
   - **4.37**：收件箱从纯文本 → 带 `from` 的 JSON 行；`--from/--to` 已从入口删除；
   - **4.43**：字幕新增 WS 推送（`frame-ws`），长轮询保留；
   - **4.44 / 4.46**：会议结束 → `closed` 推送 + `/floor` 410 + 房间详情带 `closed`；
   - **4.45**：被顶下线 → `kicked` 推送（`session-push`）。

## 10. 联调检查清单（照着打勾）

- [ ] `/hello` 能拿到 `features` 与 `cols/lineBudget`
- [ ] 登录拿到 token；关掉 App 再开**不需要重新登录**
- [ ] `/audio` 上传后 `/status` 的 `audioBytes/audioChunks` 在涨，`audioRate/audioLang` 已写
- [ ] `/frame?since=` 能拿到帧；长轮询在没有新帧时是**挂住**（不是报错）
- [ ] 字幕**原文与译文成对**出现；增量帧是**原位更新**而不是新起一条
- [ ] 长句（`fake-frames` 最后一条）能正确折行/翻页
- [ ] 另一台设备同账号登录 → 这台一秒内提示"账号已在别处登录"（需 `session-push`）
- [ ] 发起者退出 → 这台提示"会议已结束"并退出（需 `room-closed-push`）
- [ ] 401 时界面给的是"登录已失效"而不是"网络错误"

## 11. 旧版 App 的地位（重要）

安卓侧原来的「同传 App」界面（`MainActivity` + 眼镜投屏那一套）**已冻结**：

- **它是翻译官 App 的参考实现**：收音、上传、长轮询、字幕成对显示、眼镜投屏与折行翻页都在里面，
  对照跑一遍比读文档快；
- 不再加新功能；会议室新界面（`HomeActivity` / `RoomsActivity` / `RoomActivity`）是另一条线；
- 新界面里的「旧版界面」入口**默认隐藏**（保留代码，一个属性就能放出来，见 `page_home.xml` 的 `homeLegacy`）。
