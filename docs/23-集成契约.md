# 集成契约：同传翻译官 ⇄ 会议室主 App（2026-10-29 重写）

> **读者**：做「同传翻译官」那一端的人，以及维护 relay 的人。
> **这一版和 2026-10-28 那版是两份不同的东西**：那一版假设翻译官 **复用我们的识别/翻译管线**
> （`/audio` → whisper → DSH 插件 → `/frame`）。现在翻译官**翻译走阿里云、独立数据通路**，
> 所以要接的不再是"字幕管道"，而是**我们的账号、术语库、历史记录**。
>
> 数据通路的"为什么"见 [`05-数据通路.md`](05-数据通路.md)；房间与发言权规则见
> [`21-房间与发言权-UI与存储设计.md`](21-房间与发言权-UI与存储设计.md)；协议演进的历史见本文 §9。

## 0. 一页速览：分工与不碰的地方

```
┌────────────── 会议室主 App（我们）──────────────┐
│ 账号 / 会话 · 房间与发言权 · 术语库 · 历史与转写  │
└───────▲──────────────────────────▲─────────────┘
        │ ①登录拿 token             │ ③写记录与转写
        │ ②读术语库                │ ④读自己的历史
┌───────┴──────────────────────────┴─────────────┐
│  同传翻译官（另一个团队）                        │
│  录音 → 阿里云（识别+翻译，独立通路）→ 本地展示    │
└────────────────────────────────────────────────┘
```

| 领域 | 归谁 | 说明 |
|---|---|---|
| 账号、登录、token、角色、有效期 | **我们** | 翻译官不自己做账号体系 |
| 术语库（读取、选库、条目内容） | **我们**（存储）+ 翻译官（消费） | 由我们审批，翻译官**只读** |
| 识别与翻译本身 | **翻译官**（阿里云） | 我们**不再**为它跑 whisper/DSH 插件 |
| 房间、成员、发言权（抢麦/锁定/移出） | **我们** | 翻译官**不碰** |
| 历史记录与转写全文 | **我们**（存储与展示） | 翻译官**写入**，会议室 App **展示** |
| 界面语言、记录类型标签 | **我们** | 两者共用同一套 token 与文案 |

**翻译官不要调用**：`POST /audio`、`GET /frame`、`/ws?room=`、`/org/rooms/*/floor`（含 take/lock/force-release）、
`/org/meeting/*/libraries`（那是"给这一场会议选库"的会议室动作）。理由：那些是**我们的字幕管道与会议流程**，
翻译官走自己的通路，接了会双跑同一段音频。

## 1. 身份与鉴权（复用，不要另做）

| 层 | 头 / 参数 | 说明 |
|---|---|---|
| 共享密钥 | `X-Leion-Secret: <密钥>` 或 `?secret=` | 每个请求都要 |
| 账号 token | `X-Leion-Token: <token>` | `/auth/login` 或 `/auth/register-email` 返回；**服务端只认 token 判"我是谁"** |

- 登录：`POST /auth/login {username, password, label}`，`label` 请填 `translator`（会议室 App 填 `room`）；
- 恢复会话：`GET /auth/whoami` → `{ok, user, role, status, expiresAt}`；
  `status==='disabled'` 或 `expiresAt` 已过 → 提示并回登录页；
- 注销：`POST /auth/logout`。

> ⚠️ **单会话的坑（现在就会遇到）**：同一账号后登录会**吊销前一个 token**。
> 你调翻译官、我调会议室，用同一个账号会**互相踢下线**。
> 在那之前：**各自用各自的测试账号**（例如 `dev-translator` / `dev-room`）。
> `label` 已经能上报，改成 per-label 并存是待拍板事项（§8）。

## 2. 术语库（读，不改）

```
GET /org/libraries           # 我可见的库
→ { ok, libraries:[{id, name, categoryId, categoryName, priority, visibility, entries, updatedAt}] }

GET /org/libraries/<id>      # 单库详情（含条目正文）
→ { ok, library:{ id, name, entries:[{zh, pt, ...}] } }
```

- 翻译官把 `entries` 里挑出来的条目**注入阿里云侧的 prompt**（术语优先、专名写法统一）；
- **审批流在我们这边**：用户改库只能提申请（`POST /org/requests`），管理员批了才落库；
  翻译官**不要**实现"改库"动作；
- 权限：`library.read` 对 admin/user/dev 都开放，所以任何能登录的账号都能读。

## 3. 历史记录：翻译官要写的两样东西

会议室 App 的「历史」页（`docs/21 §4.70`）里，**记录类型标签只有两种**：`同传会议` / `同传翻译官`。
翻译官写进来的记录必须是后者，且**必须能被我们的历史页直接显示**（名称/时间/时长/人数=仅自己/语言对/转写全文）。

### 3.1 现状 vs 需新增

| 能力 | 端点 | 状态 |
|---|---|---|
| 列我的历史（两 App 共用） | `GET /org/history?limit=50` | **已有** |
| 读某条记录的转写全文 | `GET /org/history/<id>/transcript` | **已有** |
| 按账号删记录 | `POST /org/history/<id>/delete` | **已有** |
| **创建一条"同传翻译官"记录** | `POST /org/history/interpreter` | **需新增** |
| **追加一条定稿转写** | `POST /org/history/<id>/utterance` | **需新增** |
| **结束记录（决定时长）** | `POST /org/history/<id>/close` | **需新增** |

> 三个"需新增"的端点我在写这份文档的同时给出了精确形状；relay 侧实现见 §3.4 的实现清单。
> 在它们上线前，翻译官可以先用 `GET /auth/whoami` + 本地存储做联调，但**不要**自己造一套历史存储 ——
> 那会让用户在两处看到不一致的记录。

### 3.2 创建（开始一场翻译官会话）

```http
POST /org/history/interpreter      X-Leion-Token: <token>
{ "name": "与圣保罗客户沟通",       // 可空；空则由服务端取默认名
  "langs": ["zh-CN", "pt-BR"] }    // 参与的语言对，去重后最多 2 个

200 { "ok": true, "id": "record-xxxx", "kind": "interpreter", "createdAt": "2026-10-29T09:10:00.000Z" }
```

- `kind` 固定 `interpreter`（历史页据此显示「同传翻译官」标签）；
- **人数**恒为 1（你自己），历史页会显示「仅自己」；
- 失败：`400`（`name` 过长 / `langs` 不是数组）、`401`（token 失效）、`403`（角色无 `meeting.configure`）。

### 3.3 追加转写 / 结束

```http
POST /org/history/<id>/utterance   X-Leion-Token: <token>
{ "srcText": "我们先确认一下交期",   // 原文（必填，非空）
  "dstText": "Vamos confirmar o prazo primeiro",  // 译文（必填，非空）
  "srcLang": "zh-CN",              // 可选
  "username": "张三",              // 可选：说话人显示名；空则用账号名
  "at": "2026-10-29T09:10:32.000Z" // 可选：这句的时刻；空则用服务端当前时间
}
200 { "ok": true, "id": 17 }
```

- **只写定稿**：增量/中间结果不要写。理由：转写全文是要给人读的，碎片会毁掉它；
- 幂等边界：同一个 `(id, at, srcText)` 重复提交会**重复插入**——翻译官自己保证"一句只写一次"；
- 失败：`400`（缺字段 / 空文本 / 非本记录成员）、`404`（没有这条记录）、`401`。

```http
POST /org/history/<id>/close       X-Leion-Token: <token>
200 { "ok": true, "id": "record-xxxx", "closedAt": "2026-10-29T09:42:10.000Z", "durationSeconds": 1930 }
```

- 结束之后**不再接受** `utterance`（返回 `409`），避免"结束了两边数据还在长"；
- 不结束时历史页会把这条显示为「进行中」，时长按当前时间算。

### 3.4 relay 侧实现清单（给维护 relay 的人）

1. `rooms` 表加列 `kind TEXT DEFAULT 'meeting'`（走 `COLUMN_PATCHES`，**每次 openDb 都要跑**，
   不能放进 `migrate()` 的版本门禁 —— 那是 `hidden_at` 踩过的坑）；
2. `createInterpreterRecord()`：插 `rooms`（`kind='interpreter'`、`host=我`、`closed_at=NULL`）
   + `room_members`（我，`joined_at=now`）；
3. `listHistory()` 把 `kind` 带出来（现在硬编码 `'meeting'`）；
4. `appendUtterance` 复用 `lib/db.mjs` 的现成函数（`utterances` 表）；
5. 三个路由放在 `/org/history/...` 下，权限沿用 `meeting.configure`（admin/user/dev 都有）。

## 4. 展示侧约定（翻译官在会议室 App 里怎么出现）

- 入口：主 App 首页第三张卡「同传翻译官」（现在标着「即将上线」、点了没反应）；
  接进来之后这张卡改为跳翻译官的界面，标签与历史页保持一致；
- 历史页卡片：类型标签「同传翻译官」、人数「仅自己」、语言对来自记录的 `langs`；
- 详情页：三列统计（时长/语种/人数）→ 转写全文（定稿框内滚动，卡片格式与会议字幕一致）→ 导出 Word；
  **没有** AI 摘要与行动项（会议纪要按老师建议砍掉，导出也不含）。

## 5. 数据形状（要在两端保持一致的三处）

### 5.1 转写行（翻译官 → 我们）

见 §3.3 的请求体。**原文与译文必须成对**——这是产品的核心承诺，不允许"只存译文"。

### 5.2 历史条目（我们 → 两端展示）

```json
{ "id": "record-xxxx", "name": "与圣保罗客户沟通", "kind": "interpreter",
  "createdAt": "2026-10-29T09:10:00.000Z", "closedAt": "2026-10-29T09:42:10.000Z",
  "durationSeconds": 1930, "active": false, "members": 1,
  "langs": ["pt-BR", "zh-CN"], "utterances": 128 }
```

### 5.3 错误文案

服务端返回的 `error` / `hint` 是**中文原话**，客户端要用本地映射翻成当前界面语言。
我们的做法在 Android 的 `ServerText`（三层查表 + 兜底"非中文界面不显示中文"），
建议翻译官也做同类映射；两边文案各自维护，不必一致。

## 6. 错误码语义（沿用）

| 码 | 含义 | 客户端该做什么 |
|---|---|---|
| 401 | 会话失效（token 被吊销/过期） | 清本地 token、回登录页；**不要**重试 |
| 403 | 角色权限不足 | 提示权限问题，别重试 |
| 400 | 业务拒绝（参数/规则） | 显示 `hint`/`error` 文字 |
| 404 | 记录不存在 / 不属于你 | 提示并回列表 |
| 409 | 状态冲突（记录已结束 / 别人锁定中） | 显示文字，**不是**网络错误 |
| 410 | 会议已结束 | 退出 |

## 7. 联调检查清单（照着打勾）

- [ ] 登录拿到 token；杀进程再开**不需要重新登录**；`whoami` 能返回 `role` 与 `expiresAt`
- [ ] `GET /org/libraries` 能读到库与条目数；`GET /org/libraries/<id>` 能读到 `entries`
- [ ] `POST /org/history/interpreter` 建出记录；**我们的历史页立刻能看到**，类型标签是「同传翻译官」
- [ ] 说两句 → 每条定稿写一次 `utterance`；我们的详情页转写区出现**两张字幕卡**（不是一整段文字）
- [ ] `close` 之后：历史页时长正确、状态不再是「进行中」；再写 `utterance` 返回 409
- [ ] 导出 Word 能打开，内容含概览 + 转写（不含摘要/行动项）
- [ ] 换个账号登录：看不到别人的记录；长按删除只影响自己
- [ ] 401 时界面给的是"登录已失效"，不是"网络错误"

## 9. 协议演进规则（这条比什么都重要）

1. **只做加法**：加字段、加端点、加 `features` 标记都安全；改名、改语义、删字段**必须先升标记**；
2. 新能力先出现在 `/hello` 的 `features` 里；老客户端不认识就**忽略**，新客户端看不到标记就**降级**；
3. `features` 握手时查一次就够，别每句都查；
4. 已经发生过的"语义变更"（照旧文档写会踩全套）：
   - **4.37**：收件箱从纯文本 → 带 `from` 的 JSON 行；
   - **4.43**：字幕新增 WS 推送（`frame-ws`），长轮询保留；
   - **4.44 / 4.46**：会议结束 → `closed` 推送 + `/floor` 410 + 房间详情带 `closed`；
   - **4.45**：被顶下线 → `kicked` 推送（`session-push`）；
   - **4.74**：帧带 `roomId`，`/frame?room=` 按房间取（多房间并发）；
   - **本版**：翻译官**不再复用** `/audio` 与 `/frame`；改为写历史记录与转写。

## 10. 假服务器（联调不需要 GPU / 模型 / 凭据）

```bash
# ① 转发进程（假数据目录 + 固定密钥，纯本地）
node relay/lan-relay.mjs --data-dir var/dev --port 8799 --secret dev-secret

# ② 冒烟：能力表
curl -s http://127.0.0.1:8799/hello -H "X-Leion-Secret: dev-secret"
```

翻译官要联调的是 `/auth/*`、`/org/libraries`、`/org/history*` —— **都不需要 GPU**。
（`scripts/fake-frames.mjs` 是给"我们的字幕管道"造帧的，翻译官走阿里云，用不上它。）
