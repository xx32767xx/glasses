## 0. 一页速览（把这张表打印出来照做）

| 阶段 | 做什么 | 判据（做完怎么算过） |
|---|---|---|
| **A. 老机器记账** | 记下版本/commit、`pip freeze`、P40 的 RTF 基线 | `git log -1`、`lib/app-version.generated.mjs`、`requirements.txt` 都有值 |
| **B. 系统 + 驱动** | Ubuntu 22.04 + **NVIDIA 550 系驱动**（Volta 能用；**别装 580+**） | `nvidia-smi` 列出 `V100S`，算力 7.0，32 GB |
| **C. 依赖从零装** | 系统包、Node 22.5+、venv（版本按老机器钉死）、DSH 检出 | `preflight.cjs` 六项全绿；`check-asr-env.py` ②③ 有数字 |
| **D. 模型** | rsync `/opt/leion/models`（省 2.9 GB 下载）或重下 | `HF_HOME/large-v3` 目录在 |
| **E. 空调试** | 空数据目录 + 测试口 8790 先跑通 | `GET /version` 200；`check-live-audio --self-test` 过 |
| **F. 精度定档** | 新卡用 **`float16`**（Volta 有张量核），别照抄老机器的 `int8_float32` | 日志 `识别模型 large-v3 / cuda / float16`；RTF 期望 0.08~0.10 |
| **G. 常驻** | systemd 单元 + `secrets.env` + `asr.env`（在新机器上重新生成） | `systemctl status leion` active；journal 无 `libcublas` / `node:sqlite` |
| **H. 验收** | 九步清单（§12） | 全过才搬数据 |
| **I. 数据迁移与切换** | 不在这篇里 → 按 [`31`](31-服务器迁移方案.md) §4/§8 做 | `doctor-db` 两库 `ok`；对账数字一致 |

> **一句话记住**：手动部署 = **把"镜像替你做的事"逐条自己列出来做一遍**。
> 镜像路线省掉的那半天，就是本文要花的那半天 —— 换来的是**新系统干净、驱动/精度档自己定**。

## 1. 为什么必须手动、代价是什么

镜像（系统盘快照）能省掉的事，手动时**一样都不能少，而且不知道少了什么**。表里的六样是"镜像会带、手动必须自己装"的：

| 镜像原来自动带过去的 | 手动部署时要自己做的 | 漏了的症状 |
|---|---|---|
| 操作系统 / 内核 / 账户 | 装 Ubuntu 22.04、建用户、配 SSH | ——（基础，不会漏） |
| **NVIDIA 驱动 / CUDA 运行库** | **给 V100S 装驱动（本文 §3，最容易装错）** | `nvidia-smi` 失败，或驱动太新把 Volta 甩了 |
| **Node 22.x** | NodeSource 22.x（≥ 22.5） | 服务 3 秒一重启（`node:sqlite` 不存在） |
| **`/opt/leion/venv`**（faster-whisper、cu12 库） | 重建 venv，**版本按老机器 `pip freeze` 钉死** | `libcublas.so.12 not found` / 精度档对不上 |
| **`~/deepseek-harness`**（已 build） | clone + `pnpm install && pnpm build` | 大脑退出：`无法加载真实的 @deepseek-ai/dsh-tools` |
| **`/etc/leion/*`**（`secrets.env`、`asr.env`） | 搬 `secrets.env`；`asr.env` **在新机器上重新生成** | 腾讯/DashScope 密钥缺失，或 `LD_LIBRARY_PATH` 错 |
| **`/etc/systemd/system/leion.service`** | 按 `docs/28` 重写一份，四处对齐新机器 | 手动能跑、systemd 起不来 |

**代价**：半天工期；**好处**：驱动/精度档/venv 都是"新卡专属"的，不会出现"镜像里的老驱动看起来在跑、其实指错精度"。

## 2. 开工前：在老机器上记下三样（5 分钟）

```bash
# ① 版本与 commit（新机器要 checkout 同一个）
cd ~/glasses && git log -1 --oneline
cat lib/app-version.generated.mjs | grep -E 'name|code'

# ② Python 版本清单（新机器按这个装，别装"最新的"）
source /opt/leion/venv/bin/activate && pip freeze > /var/tmp/leion-requirements.txt
scp /var/tmp/leion-requirements.txt newbox:/var/tmp/

# ③ P40 的基线数字（换卡后对比用；取最近一次实测，见 docs/26 §2.1）
#    large-v3 / int8_float32 / RTF 0.19~0.22 / 3 秒段 668 ms
```

## 3. 系统与驱动（V100S 专属，最容易翻车的一节）

### 3.1 驱动版本区间：**470 ~ 575 之间，绝不能是 580+**

| 事实 | 后果 |
|---|---|
| Volta（算力 7.0）从 CUDA 12.x 起**一直支持** | 470/535/550 都行 |
| **CUDA 13（驱动 580+）移除了 Volta** | 装 580+ 后 `nvidia-smi` 能列卡，但 `ctranslate2` 报 `unsupported device` / `no kernel image` |

```bash
# Ubuntu 22.04：装 550 系（推荐）。apt 源里没有就先加 PPA
sudo apt update && sudo apt install -y build-essential dkms
sudo add-apt-repository -y ppa:graphics-drivers/ppa
sudo apt install -y nvidia-driver-550       # 或 nvidia-driver-535

# 关掉 nouveau（apt 包一般会自己处理；核验一下）
lsmod | grep nouveau || echo 'nouveau 已禁用'
sudo reboot
```

### 3.2 重启后三处核验

```bash
nvidia-smi
#   期望：Name 含 V100S / 显存 32GiB / Driver Version 550.x
nvidia-smi --query-gpu=name,driver_version,memory.total,compute_cap --format=csv
#   期望：..., 7.0, 32 GiB
python3 -c "import ctypes; print('驱动能加载')"   # 不报 NVML 错即可
```

> 不需要装系统级 CUDA Toolkit（cuBLAS/cuDNN 由 §5 的 pip 包提供）。
> **V100S 是 PCIe 双槽 250W**，能直插现有 2U 机器，不换电源 —— 这也是选它的理由（见 §10）。

## 4. 系统依赖 + Node（≥ 22.5，不能少）

```bash
sudo apt update && sudo apt install -y python3-venv python3-pip curl git ca-certificates rsync sqlite3 ffmpeg
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash - && sudo apt install -y nodejs
node -v            # ≥ v22.5；apt 自带的一定不够
```

## 5. 代码 + Python 环境（版本按老机器钉死）

```bash
git clone <glasses 仓库> ~/glasses && cd ~/glasses
git checkout <§2 记下的 commit>

python3 -m venv .venv && . .venv/bin/activate
pip install -U pip wheel
pip install -r /var/tmp/leion-requirements.txt          # 照老机器，不装"最新"
# 若清单里没有 cu12 运行库（老机器是镜像自带的），补这两行：
pip install nvidia-cublas-cu12 "nvidia-cudnn-cu12==9.*"

python3 scripts/check-asr-env.py                        # ②③ 必须有数字
```

> ⚠️ **Volta 的版本坑**：新版 `torch≥2.5` 已不支持 Volta。主力链路（CTranslate2 跑 whisper）不受影响，
> 但以后想上 `en-parakeet-gpu`（NeMo 走 torch）必须把 torch 钉在 **2.4.x**（`docs/26` §2.4 有记）。
> `ctranslate2` 请用 cu12 wheel（4.x 都行，它认 CUDA 12 运行库，与驱动 550 配套）。

## 7. 模型（能从老机器搬就别重下）

```bash
# 情形一：从老机器搬（推荐，省 2.9 GB 下载）
sudo rsync -aHAX --numeric-ids ~/../opt/leion/models/ newbox:/opt/leion/models/   # 在老机器上执行
# 情形二：新机器自己下
export HF_HOME=/opt/leion/models
python3 scripts/fetch-model.py large-v3 --mirror      # 国内直连必失败，见 docs/10 §2.4
python3 scripts/fetch-model.py --list
```

`HF_HOME` 定好之后**别改**，之后所有命令都用它。

## 8. 数据目录：先空目录空调试

```bash
sudo mkdir -p /var/lib/leion && sudo chown "$USER": /var/lib/leion   # 否则 EACCES

node scripts/preflight.cjs                     # 六项全绿（① 必须 ≥ Node 22.5）
node scripts/start-multi.mjs --public --data-dir /var/lib/leion/new --port 8790 \
     --compute float16 --max-models 3 --idle-flush-ms 5000 --quiet-logs
curl -s http://127.0.0.1:8790/version          # 200 + appVersion
node scripts/check-live-audio.mjs --self-test
```

到这一步**新机器已经能翻译了**（空数据、无历史）。之后的眼镜验证、模型 A/B 都在这个状态做；
**正式数据一个字节都不要提前搬**（搬了就会有人边搬边写，见 `docs/31` §5）。

## 9. 精度定档：**`float16`**（V100S 是张量核卡）

```bash
python3 scripts/check-asr-env.py               # 它会打印"✓ 有张量核：float16 可用"，以及推荐档
```

| 档位 | 适用 | 期望 |
|---|---|---|
| **`float16`** | ✅ V100S 用这个 | 3 秒段约 0.25~0.35 s，RTF 期望 **0.08~0.10**（P40 的 2~2.5 倍） |
| `int8_float16` | 显存紧时的次选 | 略慢，显存更省 |
| `int8_float32` / `float32` | ❌ 别照抄老机器 | Pascal 时代的档，在 V100S 上白白慢一档 |

显存 32 GB：large-v3 `float16` 约 5 GB、`int8` 约 3 GB，`--max-models 3` 宽裕，压到 4 也行。
模型表里的 `compute_type` 若与启动参数冲突，**表优先** —— 先看：

```bash
node scripts/asr-model-switch.mjs --data-dir /var/lib/leion/new
```

## 10. 常驻（systemd）：四处对齐新机器

照 `docs/28` §2.1 抄单元，逐项改：

| 必须改 | 为什么 |
|---|---|
| `ExecStart` 的 node 绝对路径 | `which -a node` 确认是 ≥ 22.5 那个 |
| `--data-dir` / `--port` | 先用 `new` / 8790 测通，再改回 `live` / 8788 |
| `EnvironmentFile=/etc/leion/secrets.env` | 腾讯/DashScope/DeepSeek 密钥（**从老机器搬，权限 600**） |
| `EnvironmentFile=/etc/leion/asr.env` | cu12 的 `LD_LIBRARY_PATH`，**在新机器重新生成**，别手抄 |

```bash
sudo mkdir -p /etc/leion && sudo chmod 700 /etc/leion
sudo rsync -aHAX /etc/leion/secrets.env newbox:/etc/leion/        # 从老机器搬
sudo chmod 600 /etc/leion/secrets.env

sudo python3 scripts/make-env-file.py /opt/leion/venv \
     --hf-home /opt/leion/models --out /etc/leion/asr.env

sudo systemctl daemon-reload && sudo systemctl enable --now leion
sudo systemctl status leion --no-pager | head -8
sudo journalctl -u leion -n 40 --no-pager        # 无 ERR_UNKNOWN_BUILTIN_MODULE、无 libcublas
```

## 11. 验收清单（九步，全过才动数据）

```bash
# ① 环境六项
node scripts/preflight.cjs
# ② 识别环境两项（②③ 有数字）
python3 scripts/check-asr-env.py
# ③ 端口与进程
sudo ss -ltnp | grep 8790
# ④ 服务活着 + 密钥对
python3 scripts/check-relay.py --data-dir /var/lib/leion/new
# ⑤ 大脑能翻译
python3 scripts/check-relay.py --data-dir /var/lib/leion/new --say "这是一条测试信息"
# ⑥ 识别真出字（空目录也要能出）
node scripts/asr-try.mjs --data-dir /var/lib/leion/new --pcm var/tmp/sample.pcm --rate 16000 --seconds 8
# ⑦ 公网可达（安全组 + 防火墙）
python3 scripts/check-relay.py --base http://<新IP>:8790 --secret <密钥>
# ⑧ 眼镜链路（手机服务器地址指新机 → 我的 → 眼镜投屏 → 说话）
#    镜片出译文；会议页抽屉写「Rokid 眼镜投屏中」
# ⑨ 两步验收（若这台上要对外）：
curl -s http://127.0.0.1:8790/translate/info | head -c 200
```

眼镜验证的细节与"服务器不感知眼镜、只感知手机"这一点见 `docs/31` §6 与 `docs/09` §13.7。

## 12. 手动会漏的东西（对着这张表自查）

| # | 项 | 自查命令 | 漏了的表现 |
|---|---|---|---|
| 1 | Node ≥ 22.5 | `node -v` | `ERR_UNKNOWN_BUILTIN_MODULE: node:sqlite` |
| 2 | cu12 运行库 | `python3 scripts/check-asr-env.py` ② | 每段 `libcublas.so.12 not found` |
| 3 | `LD_LIBRARY_PATH`（`asr.env`） | 单元里有 `EnvironmentFile=…/asr.env` | 手动跑通、systemd 起不来 |
| 4 | `PYTHONUTF8=1` | 单元里有 | 中文识别结果变乱码 |
| 5 | DSH 检出已 build | `preflight.cjs` ⑥ | 大脑退出 |
| 6 | `HF_HOME` 一致 | 单元里有 `Environment=hf_home` | 首段识别卡 2.9 GB 下载 |
| 7 | 数据目录属主 | `preflight.cjs` ③ | `EACCES ... mkdir '/var/lib/leion'` |
| 8 | 密钥文件权限 | `ls -l /etc/leion` | 服务用户读不到腾讯密钥 |
| 9 | 安全组放行 | `check-relay.py --base http://<IP>:8788` | 手机超时、服务器日志却正常 |
| 10 | 时间/时区 | `date` | 日志时间线对不上，排障时误导 |

## 13. 排障表（V100S 特有，按症状查）

| 症状 | 先看这里 | 常见原因 |
|---|---|---|
| `nvidia-smi` 能列卡，但识别报 `unsupported device` / `no kernel image` | `nvidia-smi --query-gpu=driver_version` | **驱动 580+（CUDA 13 已移除 Volta）**，降到 550/535 |
| `float16` 起不来，`check-asr-env.py` ③ 说不可用 | 驱动版本 + cuDNN 版本 | cuDNN 9 对 Volta 个别组合失败 → 回退 `nvidia-cudnn-cu12==8.9.*` 或 `int8_float16` |
| 每段都 `libcublas.so.12: cannot open` | `check-asr-env.py` ② | 缺 cu12 pip 包 / 单元少 `asr.env` |
| 服务 3 秒一重启 | `which -a node; node -v` | 单元里的 node < 22.5（见 `docs/28` §2.4） |
| 中文结果乱码 | 单元 `Environment=PYTHONUTF8=1` | 缺编码变量 |
| `EACCES ... mkdir '/var/lib/leion'` | `preflight.cjs` ③ | 上级目录属主 root |
| 手机连不上新机 | `ss -ltnp \| grep 8790` / 安全组 | 只听 127.0.0.1 / 入站没放行 / 密钥错 |
| 眼镜"没连上" | 手机侧 | 与服务器无关：Rokid AI App 蓝牙 + `BLUETOOTH_CONNECT` 权限（`docs/09` §13.6b） |
| 首段识别像卡住 | `fetch-model.py --list` | 模型没搬也没下，正在下 2.9 GB |

## 14. 换卡之后、迁移之前（与 `docs/31` 的衔接）

- **A→E 阶段**（本文 §2~§9）全部在**空数据目录**上做，老机器 `117.50.180.93` 不碰、不停、不改；
- **F 阶段**（数据迁移）严格按 `docs/31` §4：停服 → checkpoint/`VACUUM INTO` → rsync → `doctor-db` 对账；
- **G/H**（切换与 7 天回滚）按 `docs/31` §8；老机器在 7 天内**不准删数据、不准卸单元**；
- **模型升级测试**（turbo、parakeet-gpu/NeMo、腾讯云）按 `docs/31` §7 —— 现在这台卡有张量核，`float16` 基线先立起来。

> 换卡期间唯一要改的"业务参数"就是**精度档**（§9）。其余行为（切句、术语、翻译、字幕）与卡无关，
> 老机器能用的参数原样带过去即可。
